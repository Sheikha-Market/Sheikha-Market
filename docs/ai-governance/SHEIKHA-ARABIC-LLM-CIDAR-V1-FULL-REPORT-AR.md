## 1. الحكم التنفيذي

لم تصل المنظومة إلى نموذج لغوي ضخم جديد مدرب من الصفر. الذي تحقق فعليًا هو
تدريب محول عربي تخصصي بطريقة QLoRA فوق نموذج Qwen2.5-0.5B-Instruct القائم.
النموذج الأساسي يقارب نصف مليار معلمة؛ لذلك لا يوصف هذا الناتج بأنه نموذج ضخم
مملوك بالكامل أو LLM جديد من الصفر.

اكتمل التدريب تقنيًا، ونجح الاستدلال العربي، لكن المرشح لم يجتز بوابة الجودة:

- النموذج الأساسي: حالتان ناجحتان من 6، بنسبة 33.33%.
- المحول العربي: حالة ناجحة واحدة من 6، بنسبة 16.67%.
- فرق الجودة: سالب 16.67 نقطة مئوية.
- قرار الترقية: `PROMOTION_REJECTED`.
- الاعتماد الإنتاجي والتجاري: غير ممنوح.

يظل الناتج أصلًا تجريبيًا صالحًا للبحث والتحسين، ولا يجوز تقديمه للعملاء على
أنه نموذج شيخة ضخم أو نموذج تجاري معتمد.

## 7. الإمكانات المثبتة

1. تشغيل استدلال عربي محلي على GPU.
2. تحميل محول صغير فوق نموذج أساس واحد دون نسخ أوزان كاملة لكل تخصص.
3. تدريب محلي قابل لإعادة التنفيذ مع بذرة وضبط وبصمات.
4. تتبع dataset والمخرجات بتجزئة SHA-256.
5. مقارنة المرشح بالأساس ومنع الترقية عند التراجع.
6. استخدام النموذج داخل مسار RAG أو موجه أدوات، بشرط بقاء التحقق الخارجي.

## 9. قوانين الحوكمة والاستخدام

### 9.1 قوانين القبول

1. لا يترقى مرشح لا يتفوق على baseline في مجموعة اختبار مستقلة.
2. لا يعتمد تجاريًا قبل مراجعة الترخيص والخصوصية والأمن والجودة.
3. لا يُدعى التدريب من الصفر إذا استُخدم نموذج أساس أو محول أو تقطير.
4. لا يُدعى امتلاك نموذج طرف ثالث؛ تُحفظ نسبته وشروط ترخيصه.
5. يجب تثبيت الإصدار والبصمة وdataset والضبط ونتيجة التقييم لكل إصدار.
6. أي تغيير في الأوزان أو البيانات أو tokenizer ينشئ إصدارًا وتقييمًا جديدين.
7. القرارات عالية الأثر تتطلب مراجعة بشرية مؤهلة وسجل قرار.

### 9.2 الاستخدامات المسموحة حاليًا

- البحث والتطوير المحلي.
- الاختبارات غير الإنتاجية والمقارنة والتحليل.
- بناء المناهج وتجارب الضبط داخل بيئة معزولة.
- استخدام مقيد خلف مراجع أو RAG مع وسم واضح بأنه تجريبي.

### 9.3 الاستخدامات المحظورة حاليًا

- تقديمه كخدمة تجارية معتمدة أو LLM ضخم مملوك.
- اتخاذ قرار طبي أو قانوني أو مالي أو أمني أو وظيفي مستقل.
- توليد فتوى أو حكم شرعي نهائي دون عالم أو جهة شرعية مؤهلة.
- إدخال أسرار أو بيانات شخصية غير مصرح بها.
- التدريب التلقائي من محادثات العملاء دون موافقة وغرض ومدة احتفاظ معلنة.
- إعادة نشر أوزان أو بيانات خارج شروط تراخيصها.

## 10. التراخيص والملكية

- النموذج الأساسي: Apache-2.0 بحسب ملف الترخيص المحفوظ مع المصدر.
- CIDAR: Apache-2.0 بحسب بطاقة dataset، مع بقاء مراجعة provenance واجبة.
- كود شيخة والمحولات: يخضعان لترخيص المشروع وحقوق المساهمين، ولا يلغيان حقوق
  النموذج الأساسي أو البيانات.
- رقم داخلي أو سجل حوكمة لا يساوي ترخيصًا حكوميًا أو موافقة تنظيمية.
- الاستخدام التجاري الممكن بموجب ترخيص مفتوح لا يعني تلقائيًا سلامة كل سجل أو
  إعفاء المستخدم من قوانين الخصوصية والمستهلك والملكية الفكرية.

هذا القسم توثيق هندسي وليس رأيًا قانونيًا؛ الاعتماد النهائي من مسؤول قانوني.

## 12. متطلبات الإنتاج

لا يصبح المرشح إنتاجيًا إلا بعد تحقق جميع الآتي:

1. منهج عربي مملوك أو موثق الحقوق، متوازن ومراجع.
2. مجموعة اختبار محجوزة لا تدخل التدريب.
3. تفوق إحصائي متكرر على baseline في الجودة والدقة والزمن والسلامة.
4. اختبارات هلوسة وتحريض وخصوصية وتسريب بيانات وPrompt Injection.
5. اختبارات تحميل وSoak وتعافٍ وقياس GPU والذاكرة والتكلفة.
6. مراقبة زمنية، حدود استخدام، Rate Limit، سجل تدقيق وخطة تراجع.
7. نشر Canary محدود، ثم توسيع تدريجي بناءً على مؤشرات فعلية.
8. توقيع مسؤول النموذج والأمن والقانوني ومالك المنتج.

## 13. حالة شات شيخة

فشل Enterprise Inspector الظاهر في الشات لا يثبت فشل النموذج المدرّب. الدليل
المعروض هو انتهاء مهلة أول Token بعد 8,000 ms في مسار إضافة VS Code. هذا خلل
نقل/مهلة أو اتصال بالخادم المحلي، بينما تقييم المحول نفذ محليًا عبر GPU.

حالة الشات الحالية وفق النص المقدم:

- الإضافة متصلة شكليًا وتعرض 39/39 أداة.
- طلب Inspector لا يحصل على أول Token خلال المهلة.
- الرد الاحتياطي صحيح من جهة عدم اختلاق حالة، لكنه لا يقدم التشخيص المطلوب.
- يلزم فحص صحة الخادم ومسار SSE ومدة أول Token وقراءة Inspector مستقلًا.

لا يعتمد الشات إنتاجيًا قبل نجاح طلب Inspector المتكرر وقياس P50/P95/P99
وتوثيق سبب كل fallback.
