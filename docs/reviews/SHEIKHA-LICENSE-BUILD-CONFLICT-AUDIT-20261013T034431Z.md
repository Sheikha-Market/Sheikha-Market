# مراجعة تراخيص شيخة والبناء السابق

وجدت رخصة تشغيل داخلية سابقة ACTIVE تمنح الاستخدام والتشغيل والاختبار والتكامل داخل بيئات شيخة. طابقت بصمة محتوى سجلها؛ هذا لا يثبت اعتمادًا حكوميًا أو ترخيصًا من مورد خارجي. سجل الترخيص السابق يعلن صفر شهادات خارجية صادرة.

## المقارنة
- نصوص LICENSE-SHEIKHA.md وLICENSE-PROPRIETARY.md متطابقة في النسخ القريبة التي قورنت. هذه مقارنة ملفات محددة وليست مراجعة قانونية شاملة لجميع النسخ والمكونات.
- منصة SHEIKHA_DEVELOPER_PLATFORM_V1 ومرجع system-builder-platform موجودان سابقًا. فحص اتساق عقد الترخيص والهيكل السابق نجح، وهو فحص محتوى لا تشغيل لكل القدرات.
- أدوات SDP الجديدة تستخدم المترجم الموجود، لكنها غير مربوطة بعد بسجل المنصة السابقة. التوصية إدراجها كمحول تطوير محلي تحت المنصة السابقة والحفاظ على مرجع البناء الأصلي.

## التعارضات والفجوات
1. حزمتا DEB بنفس الاسم والإصدار والمعمارية، وبصمتين مختلفتين. لا تختار بينهما بالاسم وحده؛ يلزم مصدر بناء وبصمة مرجعية وإصدار تمييزي قبل توزيع بديل. اختلاف البصمة لا يثبت فسادًا بذاته.
2. RPM سابق موجود وبصمته تطابق المصفوفة. التقرير المشار إليه في مساره الحالي مفقود، والسجل نفسه يذكر نقص إعلان التبعيات وعدم إثبات التثبيت الأصلي. لم يُعد البناء أو التثبيت.
3. التراخيص الداخلية السابقة لا تتعارض مفهوميًا مع طلب تقييم مورد خارجي، لكنها لا تغني عنه. لم يُعثر على دليل رخصة مورد خارجي سارية في السجلات المفحوصة؛ فحص حسابات الموردين لم يُجر.
4. قبل توزيع حزم SDP، ينبغي ربطها بإشعارات الرخصة القائمة وحقوق الأطراف الثالثة. لم تُصدر رخصة جديدة أو تُلغَ القديمة.

## قرار الاستكمال المقترح
الاحتفاظ بمنصة التطوير والبناء السابقين كمراجع، واعتبار SDP إضافة أدوات محلية محدودة. تعليق تثبيت الحزم الملتبسة أو توسيع صلاحيات ملفات البناء المخططة حتى اكتمال الأدلة. لا تغيير تلقائي لحالات ACTIVE أو لمنح التراخيص بناءً على نجاح الاختبارات.

المراجعة قراءة فقط للملفات التشغيلية: لا حذف أو تنظيف Git أو دمج أو إعادة بناء أو تثبيت أو مراسلات خارجية. التقرير JSON المرافق يتضمن مسارات الأدلة والبصمات دون بيانات مالك أو أسرار.
