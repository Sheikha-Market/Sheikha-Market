# هدف SDP الأصلي التجريبي على Linux

`node tools/environment/sheikha-sdp-v1.cjs native-linux hello-sheikha-v1`

يقرأ المشروع المحلي ويطبق فحص المترجم والربط الداخلي، ثم يولد C من تعليمات العرض والرفض والشروط ذات القيم المنطقية الحرفية، ويبنيه بGCC إلى ELF x86_64 ويشغله محليًا ويقارن المخرجات بتنفيذ VM. يدعم true وfalse وصحيح وخطأ، بما فيها الشروط المتداخلة حتى عمق 16 مع حد 4096 تعليمة؛ الشروط الأخرى والبنى غير المدعومة تُرفض؛ لا تحويل صامت إلى مخرجات مسبقة لبنى غير مدعومة.

تُشفّر بايتات النصوص في C باستخدام octal escapes لمنع إدخال شفرة من النص المعروض. خيارات GCC ثابتة، والمسار محصور في مشروع محلي. التنفيذ له مهلة ومخرجات محدودة.

يحفظ المصدر وC وELF وسياق الترخيص والتقرير والبصمات، ولا يغير الحزم السابقة. الأثر يعتمد على Linux وlibc المضيف؛ ليس Bare-Metal أو صورة OS أو مترجمًا أصليًا لكل لغة شيخة. نجاح المطابقة لهذا الجزء الصغير لا يثبت سلامة عامة للمترجم أو أهلية التوزيع والإنتاج أو تطابقًا ثنائيًا قابلاً لإعادة البناء. يلزم مراجعة تراخيص سلسلة الأدوات والمكتبات عند التوزيع.

أضيف تفسير القيم المنطقية الحرفية في VM أيضًا، مع إبقاء السلوك التاريخي للشروط النصية الأخرى لأجل التوافق؛ ذلك السلوك النصي ليس لغة تعبيرات منطقية مكتملة. لا ينقل إلى هدف C الأصلي. يراجع المولد كلا الفرعين، ولو لم يُنفذ أحدهما، لمنع إخفاء أوامر غير مسموحة داخله.

المقارنات العددية الثابتة مدعومة للأعداد الصحيحة العشرية بين -1000000 و1000000: == و!= و< و> و<= و>=. لا eval أو إدخال نص الشرط إلى C مباشرة؛ تُحلل المعاملات ثم تطبع أعدادًا ومعاملًا من قائمة محددة. الكسور والقيم الخارجة عن الحدود والصياغات العددية غير الصالحة تمنع توليد bytecode. تستمر الشروط النصية القديمة خارج هذا الهدف لأجل التوافق.

الحساب الصحيح الثابت داخل طرفي المقارنة يدعم + و- و* والأقواس والإشارة الأحادية. أولوية الضرب أعلى من الجمع والطرح. تُرفض أي قيمة وسيطة خارج ±1000000 حتى إن عاد الناتج النهائي إلى النطاق؛ لا قسمة أو كسور أو متغيرات. طول الشرط 128 حرفًا، وحد التعبير 64 رمزًا/عقدة وعمق 16. يعاد بناء C من شجرة حسابية محددة؛ لا eval.
