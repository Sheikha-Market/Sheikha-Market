# معالجة البيانات الطبيعية محلياً في شيخة

تاريخ التحقق: 18 أكتوبر 2026، بتوقيت الرياض.
النطاق: `LOCAL_IMPORT_PROCESSING_ONLY`، معالجة بيانات يقدّمها المستدعي في الذاكرة، دون اتصالات أو تخزين دائم.

## التنفيذ

أضيف [معالج مشترك](../../core/natural-data/sheikha-natural-data-v1.cjs) إلى [JavaScript SDK](../../sdk/sheikha-js/index.js) وإلى [خادم MCP للقراءة فقط](../../mcp-servers/sheikha-mcp-readonly-federation.cjs). يجمع دفعة من مصادر متعددة مع إبقاء هوية وسياق كل مصدر منفصلين، ويوحّد الوحدات ويحسب ملخصات القراءات. هذه فدرلة محلية للمدخلات، وليست شبكة مستشعرات متصلة.

لا يُشغّل محرك V37.1 الوارد في المحادثة المرفقة، ولا يكتب إلى قاعدة البيانات القديمة أو يعيد ختم أدلتها. تسجيل وصف مصدر أو حساب بصمة لا يثبت تشغيل مستشعر، أو دقة قياس، أو الاعتماد الشامل. معايير القبول هنا بنيوية وتقنية؛ لا تستخدم ديانة الأشخاص في قبول البيانات أو رفضها.

## صيغة الإدخال

الحقول العليا الأربعة مطلوبة: `schemaVersion=1` و`asOf` و`sources` و`observations`. الحد الأقصى 16 مصدراً و256 قراءة في الاستدعاء، والدفعات الفارغة مرفوضة.

لكل مصدر خمسة حقول مطلوبة:

| الحقل | المعنى |
| --- | --- |
| `id` | معرف فريد داخل الدفعة، وليس شهادة هوية |
| `domain` | `solar` أو `lunar` أو `planetary` أو `earth` أو `atmosphere` |
| `kind` | `synthetic` أو `model_output` أو `observation_import`، بحسب تصريح المستدعي |
| `referenceId` | معرف مرجع محلي، وليس عنواناً يُفتح أو ملفاً يُقرأ |
| `contextId` | معرف سياق ثابت للموقع أو الجهاز أو الإطار المرجعي |

المعرفات 1 إلى 64 محرف ASCII، تبدأ بحرف أو رقم وتسمح بعدها بالحروف والأرقام و`_ . : -`. لا تُرسل مفاتيح أو كلمات مرور أو معلومات شخصية. لا يُتحقق خارجياً من صحة المعرفات أو ملكية مصادرها. تسميات `observation_import` و`model_output` لا تثبت وجود قياس أو نموذج موثوق.

يجب أن يشير `contextId` لدى الجهة المستوردة إلى وصف مضبوط: موضع ومستوى القياس الشمسي، الجسم ومركز الرصد للمسافة الكوكبية، المرجع الرأسي للارتفاع، أو ارتفاع ومحطة القياس الجوي. غيّر معرف المصدر عند تغير سياق السلسلة. لا يفسّر المعالج هذه الأوصاف ولا يتحقق من صحتها، ولا يخلط إحصاءات مصدرين مختلفين.

لكل قراءة: `sourceId` و`metric` و`observedAt` و`value` و`unit`. الأوقات بصيغة UTC الدقيقة `YYYY-MM-DDTHH:mm:ss.sssZ`، مع تحقق التاريخ الفعلي ورفض قراءة بعد `asOf`. الوقت المرجعي مقدّم من المستدعي وليس ساعة موثوقة؛ `ageSeconds` عمر محسوب بالنسبة إليه، وليس ضمان حداثة البيانات.

## المقاييس والوحدات

| `metric` | وحدات الإدخال | وحدة الإخراج | الحدود بعد التحويل |
| --- | --- | --- | --- |
| `solar_irradiance` | `W/m2`, `kW/m2` | `W/m2` | 0 إلى 1e9 |
| `lunar_illuminated_fraction` | `fraction`, `%` | `fraction` | 0 إلى 1 |
| `planetary_distance` | `m`, `km` | `m` | 0 إلى 1e18 |
| `earth_elevation` | `m`, `km` | `m` | -1e6 إلى 1e6 |
| `air_temperature` | `K`, `degC` | `K` | 0 إلى 1e6 |
| `air_pressure` | `Pa`, `hPa` | `Pa` | 0 إلى 1e9 |

هذه حدود قبول برمجية عامة، وليست نطاقات معايرة أو شهادة معقولية علمية لجهاز بعينه. تُرفض القيم غير المحدودة والنصوص الرقمية والوحدات غير المطابقة، ولا يُفسّر `kWh/m2` على أنه إشعاع لحظي. تحويل `degC` إلى `K` يضيف 273.15، وفق [مرجع الوحدات لدى NIST](https://physics.nist.gov/cuu/Units/register2.html).

لا تُحسب المدارات أو منازل القمر في هذا المسار. الربط الفلكي اللاحق يحتاج خدمة أو مكتبة موثوقة وإعداد الجسم والإطار المرجعي ومقياس الزمن، كما تبيّن [وثائق JPL Horizons](https://ssd-api.jpl.nasa.gov/doc/horizons.html). لم يُفعّل اتصال بهذه الخدمة.

## القيمة المضافة والحدود

- تجميع القراءات حسب المصدر والمقياس فقط، مع الحد الأدنى والأقصى والمتوسط الحسابي للعينات وبداية ونهاية الفترة. المتوسط ليس متوسطاً زمنياً موزوناً أو تكاملاً للطاقة.
- دمج التكرارات ذات المصدر والمقياس والوقت والقيمة الموحدة المتطابقة، مع حفظ `inputIndexes` الصفرية. اختلاف القيمة في المفتاح نفسه يرفض الدفعة كاملة، دون اختيار قيمة تعسفياً. المقارنة عددية تامة، دون سماحية تقريب خفية.
- بصمتا SHA-256 للمحتوى المتحقق منه وللمخرجات الموحدة. البصمة الأولى لتسلسل JSON أعاد المعالج بناءه بترتيب حقول ثابت مع إبقاء ترتيب المصفوفات، وليست بصمة الملف الأصلي. البصمات لا توقّع المصدر ولا تصادق عليه.
- المصدر غير المستخدم يبقى `hasReadings=false`. جميع المصادر تبقى `authenticity=UNVERIFIED` و`calibration=NOT_VERIFIED` و`connection=NOT_CONFIGURED` حتى لو ادّعى المستدعي أنها قراءات ميدانية.
- لا شبكة أو ملفات أو قاعدة بيانات أو استدلال نموذج أو أوامر مادية في المعالج. تبقى `productionReady=false` و`liveSensorVerified=false` و`allSourcesConnected=false`.
- الحقول الإضافية وطلبات العناوين أو الملفات أو الصلاحيات مرفوضة. رفض MCP لا يعيد المدخلات إلى رسالة الخطأ. الاختبارات لا تدّعي تدقيق بقية وظائف الخادم أو كامل المشروع.

## الاستخدام

يتضمن [المثال الاصطناعي](../examples/sheikha-natural-data.synthetic.json) خمسة مصادر وسبع قراءات وستة مقاييس. القيم مختارة للاختبار وليست مشاهدات طبيعية بتاريخ المثال.

من جذر المستودع:

```javascript
const { createSheikhaClient } = require('./sdk/sheikha-js');
const batch = require('./docs/examples/sheikha-natural-data.synthetic.json');
const result = createSheikhaClient().processNaturalData(batch);
console.log(result.counts);
console.log(result.summaries);
console.log(result.boundaries);
```

عبر MCP اسم الأداة `sheikha_natural_data_process`، ومعاملاتها كائن الدفعة نفسه. يعلن `tools/list` المخطط البنيوي، ويطبق المعالج أيضاً تحقق التاريخ وربط المصدر بالمقياس والوحدة والتعارضات. لا يتيح المخطط إنشاء اتصال أو منح تفويض.

الخادم المعدّل يعرض ست أدوات، مع الحفاظ على الموارد الأربعة السابقة. لم تتغير ملفات إعداد MCP. الجلسة التي بدأت قبل التعديل تحتاج إعادة تشغيل الخادم من المضيف لاكتشاف الأداة؛ لم تُعد تشغيل جلسات المستخدم. أُغلقت عمليتا اختبار stdio بعد الاختبار.

## التحقق

نجحت **42 حالة اختبار**: 16 للمعالج الجديد، وحالة MCP فعلية جديدة، و7 للتكامل المحلي السابق، و18 للمحاكاة والموصلات وحوكمة SDK/MCP القائمة.

```bash
node --test --test-isolation=none --test-reporter=tap tests/sheikha-natural-data-v1.test.cjs tests/sheikha-industrial-network-v1.test.cjs tests/sheikha-robotic-connectors-v1.test.cjs tests/sheikha-sdk-mcp-governance.test.cjs
node --test --test-isolation=none --test-reporter=tap tests/sheikha-natural-data-mcp.test.cjs tests/sheikha-foundry-telecom-local-integration.test.cjs
```

احتاجت المجموعة الثانية السماح بإنشاء عملية Node فرعية محلية عبر stdio في بيئة الاختبار. شمل الاختبار اكتشاف المخطط والاستدعاء الفعلي ومطابقة SDK ورفض توسعة النطاق، ولم تُستدعَ أدوات قراءة الأدلة القديمة أو أداة HTTP المحلية.

للانتقال إلى مصدر حي يلزم تحديد المصدر أو الجهاز وعنوانه وبروتوكوله ومرجعه ووحداته، ثم محول قراءة محدود والتحقق من الهوية والصلاحيات والمعايرة عند الحاجة. اسم «Sheikha» وحده لا يحدد هذه المعلومات؛ لا وصول إلى جميع المصادر بمجرد إضافتها إلى كتالوج.
