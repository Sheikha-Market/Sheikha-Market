# ربط فوندري شيخة والاتصالات محلياً

تاريخ التحقق: 18 أكتوبر 2026، بتوقيت الرياض.
النطاق: `SIMULATION_ONLY`، لا تشغيل مصانع أو أجهزة أو شبكات فعلية.

## ما نُفّذ

رُبطت محاكاة الإنتاج القائمة ومحاكاة موصلات الاتصالات بدالة مشتركة في [JavaScript SDK](../../sdk/sheikha-js/foundry-telecom.cjs)، وأتيحت عبر [خادم MCP للقراءة فقط](../../mcp-servers/sheikha-mcp-readonly-federation.cjs). لا يوجد محرك إنتاج بديل أو قاعدة بيانات جديدة.

- سبع خلايا مترابطة: الفوندري، المزرعة الصناعية، المصنع البرمجي، التصنيع، التجميع، الجودة، والتوزيع.
- خمسة ملفات محاكاة للاتصال: سلكي، لاسلكي، إنترنت الأشياء، فضائي، وهجين.
- المحاكاة تعمل في الذاكرة؛ لا قراءة أجهزة أو اتصال شبكة أو استدلال نموذج أو تعديل ملفات عند استدعاء الدالة.
- النتيجة تميّز اكتمال المحاكاة عن الاتصال الحقيقي، وتبقي `productionReady=false`.

## الاستدعاء

من جذر المستودع:

```javascript
const { createSheikhaClient } = require('./sdk/sheikha-js');
const result = createSheikhaClient().simulateFoundryTelecom();
console.log(result.status); // LOCAL_SIMULATION_COMPLETED
console.log(result.boundaries);
```

الأداة عبر MCP:

```json
{
  "name": "sheikha_foundry_telecom_simulation",
  "arguments": {}
}
```

الإعدادان الحاليان `.mcp.json` و`.vscode/mcp.json` يشيران إلى الخادم نفسه؛ لم يُعدّلا في هذه الجولة. رفعت إضافة محاكاة الفوندري عدد الأدوات من أربع إلى خمس؛ ثم أضاف [تكامل البيانات الطبيعية المحلي](SHEIKHA-NATURAL-DATA-LOCAL-INTEGRATION.md) أداة سادسة. تبقى الموارد الأربعة القائمة دون تغيير. الخادم الموجود في جلسة بدأت قبل التعديل يحتاج إعادة تشغيل من المضيف؛ لم تُعد تشغيل جلسات المستخدم قسراً.

## الحوكمة

الدالة تقبل معاملات فارغة فقط. ترفض عناوين الشبكة ومعرّفات الأجهزة والمفاتيح وطلبات التشغيل المباشر حتى مع `humanApproved=true`. فشل أداة MCP يرجع رسالة عامة دون إعادة المعاملات السرية. نسخ النتيجة منفصل عن كتالوج المحاكاة المشترك، فلا يغيّره تعديل المستدعي لنتيجة سابقة.

وسوم الأداة تصف طبيعتها للعميل، لكنها ليست آلية تفويض؛ المنع هنا ناتج عن التحقق عند الاستدعاء وغياب النقل المادي والشبكي في المسار الجديد. [مرجع أدوات MCP](https://modelcontextprotocol.io/specification/2026-07-28/server/tools).

هذا الوصف يخص الأداة الجديدة، ولا يدّعي تدقيق جميع وظائف خادم القراءة القديم. لم تُستدعَ أدواته التي تقرأ سجلات خاصة أو تتصل بخدمة HTTP المحلية أثناء اختبار التكامل الجديد.

## التحقق

نجحت 25 حالة اختبار في مجموعتين منفصلتين: 7 للتكامل الجديد و18 للمحاكاة والموصلات وحوكمة SDK/MCP القائمة.

```bash
node --test --test-isolation=none --test-reporter=tap tests/sheikha-foundry-telecom-local-integration.test.cjs
node --test --test-isolation=none --test-reporter=tap tests/sheikha-industrial-network-v1.test.cjs tests/sheikha-robotic-connectors-v1.test.cjs tests/sheikha-sdk-mcp-governance.test.cjs
```

شمل الاختبار الجديد اتصال stdio حقيقياً بالخادم، واكتشاف الأداة، واستدعاءها، ومطابقة نتيجتها بنتيجة SDK، ورفض المعاملات غير المسموحة. أُغلقت عملية الاختبار عند انتهائه. فشل الاتصال أولاً بسبب منع إنشاء العمليات الفرعية (`EPERM`) داخل بيئة العزل، ثم نجح بعد السماح بتشغيل الاختبار المحلي خارج هذا القيد. لا يعني ذلك اختبار الإنترنت أو أي معدات.

تغطي الاختبارات القائمة ترتيب تبعيات الخلايا، والإيقاف الافتراضي، ومنع التعافي دون مراجعة، ورفض حزم المحاكاة المعادة أو المنتهية، وعدم قبول التفويض المزوّر. هذه اختبارات برمجية وليست اعتماد سلامة صناعية.
