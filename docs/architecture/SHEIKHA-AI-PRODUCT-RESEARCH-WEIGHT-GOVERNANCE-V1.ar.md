## 4. المنتج الأول: مساعد عربي يراجع قبل أن يحفظ

**النطاق:** طلب عرض سعر نصي واحد ببند واحد، وبيانات اصطناعية في مختبر معزول. لا فواتير أو التزامات أسعار أو حجز مخزون أو دفع أو عقود أو صوت أو مرفقات في هذه المرحلة.

المسار المقترح:

```text
إدخال العميل -> مسودة حقول وأسئلة -> مراجعة العميل
-> تحقق برمجي وصلاحية -> حفظ RFQ وفرصة CRM -> رقم ثابت وحالة قابلة للاسترجاع
```

النموذج يقترح مسودة فقط، ولا يحمل اعتماد قاعدة البيانات أو صلاحية إنشاء التزام. النص «أحتاج 20 طن حديد في الخبر» لا يكفي لاستنتاج نوع الطن أو درجة الحديد أو المقاس. تحفظ الكمية والوحدة كما وردتا، ويطلب توضيح ما ينقص. الحساب والتحويل بين الوحدات يتمان بوظائف حتمية بعد تأكيد الوحدة.

العقد الأدنى للمسودة: المادة، الكمية، الوحدة، المواصفة، المقاس عند اللزوم، موقع التسليم، مصدر كل حقل، والأسئلة المفتوحة. الحقل غير المذكور يبقى فارغًا؛ لا تُملأ قيمته من احتمال لغوي. تكون الواجهة عربية وإنجليزية بمكونات ثابتة ومدققة، لا شيفرة يولدها النموذج ثم ينفذها المتصفح.

تربط خدمة الأعمال التأكيد بهوية الفاعل والمؤسسة وبصمة المسودة وإصدارها. تعديل المسودة بعد التأكيد يبطل التأكيد القديم. يعاد التحقق من الصلاحية على الخادم عند الفعل، ولا يؤخذ نطاق المؤسسة من كلام النموذج.

منع التكرار يكون على مستوى الخدمة والتخزين: مفتاح idempotency ضمن المؤسسة والفاعل والعملية، مع بصمة للحمولة. تكرار المفتاح والحمولة يعيد المرجع نفسه؛ اختلاف الحمولة يرفض التعارض. يحفظ الطلب وفرصة المتابعة ذريًا حيث تسمح البنية، أو عبر outbox ومعالجة تكرار محكومة إذا انفصل التخزين. لا نعِد بتنفيذ شبكي «مرة واحدة تمامًا».

عند انقطاع الرد بعد الإرسال: «تعذر تأكيد النتيجة»، ثم استعلام بالمفتاح السابق. لا إنشاء تلقائي بمفتاح جديد. يبقى النموذج التقليدي متاحًا إذا تعطل المساعد، من دون إرسال بيانات تلقائيًا إلى مزود بديل.

| checkpoint تدريب | الأوزان وحالة optimizer وscheduler وRNG وخطوة التدريب والبيئة | حفظ معزول؛ لا فك تسلسل ملفات غير موثوقة؛ استئناف تجريبي منفصل |
| أوزان التوجيه والترتيب | معاملات التوجيه والعتبات وميزات الترتيب وإصدار المخطط | تغييرات محدودة ومراجعة، لا تعديل ذاتي لبوابات النجاح |

سجل الإصدار المقترح يحتوي: `artifactId`، المالك والنطاق، النوع، بصمة كل ملف، مراجعة الأساس والترميز، مرجع بيانات التدريب وحقوقها، وصفة التدريب والبيئة، مجموعة التقييم وبصمتها، الحالة وسببها، المراجع، إصدار الرجوع، ودليل استعادة مستقل. القيم المجهولة تسجل `UNKNOWN` أو `null`، ولا يعوض عنها باسم إصدار افتراضي أو بصمة مختلقة.

فهرس أداة الحفظ الحالية يسجل نسبًا معلنًا قيد التحقق، لا نسبًا مصدقًا. `recipeSha256` في حزم هذه المراجعة يخص وصف الحفظ والملاحظات على وصفة التدريب المرصودة الآن؛ ليس إثباتًا أن تلك الوصفة نفسها استُخدمت تاريخيًا.

دورة الحالة المقترحة: `DISCOVERED -> HASH_VERIFIED -> QUARANTINED أو EVALUATION_PENDING -> REVIEWED -> CANARY_APPROVED -> PRODUCTION_APPROVED`. لا انتقال تلقائي من «محفوظ» إلى «مجاز». يحتفظ بالإصدارات السابقة وفق سياسة احتفاظ معتمدة، مع تحقق من حقوق الحذف قبل أي إزالة.

قبل الترقية يلزم: إثبات الحقوق، تحقق نسب الأساس والبيانات، تقييم مستقل قابل للإعادة، اختبار التكامل والعزل، خطة رجوع مختبرة، واعتماد مسؤول الأعمال والبيانات والتشغيل. يستطيع شخص واحد حمل أكثر من دور في البداية، لكن يسجل سبب كل قرار وهويته؛ ولا يعتمد النموذج نفسه.

- تعرض OpenAI المعرف `gpt-6.1-sol`، وتوثق استدعاء الأدوات عبر Responses API. مرشح لتجربة فهم نصي إذا اعتمد الوصول والميزانية. [توثيق OpenAI](https://developers.openai.com/api/docs/models/gpt-6.1-sol).
- توثق Google `gemini-4-argon` بمدخلات متعددة الوسائط ومخرجات نصية؛ وتبين عدم دعم توليد المرئيات أو Live API فيه. مرشح تحليل لاحق، لا أساس تلقائي لخط إنتاج المرئيات أو الصوت الحي. [توثيق Google](https://ai.google.dev/gemini-api/docs/models/gemini-4-argon).
- توجد بطاقة Qwen3.8-27B الرسمية مع إعلان ترخيص Apache-2.0. وجود الأوزان لا يثبت ملاءمتها للعتاد أو إجازة جميع بيانات التطبيق. لم يُنزّل أو يُشغّل هنا. [بطاقة Qwen](https://huggingface.co/Qwen/Qwen3.8-27B).

لا يدخل إصدار صوتي بعينه أو منتج بحث خوارزمي في قرار التنفيذ الحالي دون تحقق منفصل من واجهته وحقوقه وتكلفته. البديل العملي الآن هو النموذج التقليدي للمهمة، ثم تأهيل مرشح واحد مقابل خط أساس؛ لا ترقية المحولات المحلية الفاشلة لأنها متاحة.

## 9. خطة التنفيذ والوقف

| المرحلة | المخرج | شرط الانتقال |
| --- | --- | --- |
| 0. حفظ الأدلة | الحزم المحلية والإيصالات والبصمات | أنجزت لهذا النطاق؛ النسخة المستقلة وخطة استعادة المفتاح ما زالتا مطلوبتين |
| 1. تدقيق R7 | مراجعة العقود ومعايير المتصفح والعزل والاستعادة | قبول المختبر الموثق، دون نقل حالة R6 التاريخية إليه |
| 2. مسودة RFQ ذكية | مخطط ثابت ومساعد اختياري دون صلاحية كتابة | نجاح الحقول الحرجة والامتناع الصحيح وعدم تراجع المنفعة |
| 3. تأهيل إصدار | مقارنة مرشح واحد، حقوق وتكلفة وخطة رجوع | موافقة صريحة قبل استخدام بيانات حقيقية أو مزود مدفوع |
| 4. تجربة محدودة | مجموعة مأذونة ومراقبة وخيار إيقاف | نتائج مستقلة ومراجعة قبل توسيع الاستخدام أو النشر |

كل مرحلة تنتج تقريرًا: ما تغير، ما اختُبر، ما فشل، أثره على المستخدم، وما ينتظر موافقة. لا موعد إطلاق إنتاجي مضمون قبل تأهيل الاعتمادات والموارد.

**واتش المقترح:** يرصد تغير البيانات والمراجع والإصدارات، وانحراف الجودة والزمن والتكلفة، وتغير بصمات الأصول. يصدر تنبيهًا أو طلب تحسين بمراجع، ولا يعدل الأوزان أو معايير القبول.

**الحارس المقترح:** يمنع الترقية دون أدلة، ويتحقق من نطاق المؤسسة والإصدار والبصمة والميزانية قبل الاستدعاء أو الفعل. يوقف المسار المتأثر ويعيده إلى النموذج التقليدي عند إخفاق شرط السلامة. التنبيه ليس إثبات تنفيذ إيقاف حتى يختبر الربط الفعلي.

**المتابعة اليومية المقترحة:** فحص الفهرس والبيانات الوصفية، بصمات الملفات المتغيرة، وملخص نتائج وآثار؛ فحص كامل دوري وإجراء استعادة بعد تغيير أداة الحفظ أو التخزين. لا نسخ متكرر لكل الأوزان كل دقيقة. الاقتراحات تمر بطلب تغيير واختبارات ومراجعة قبل الدمج.

لم تُنشأ مهمة مجدولة جديدة للأوزان أو يُفعّل ربط لحظي لواتش والحارس بهذا العمل. أدوات المرئيات السابقة تبقى مسارًا منفصلًا؛ لا يدل تشغيلها على تشغيل مساعد RFQ أو مراقبة أوزانه. لا نشر تلقائي للمرئيات أو الفيديوهات، ولا توليد خارجي متكرر دون مزود وميزانية معتمدين.

## 10. تشغيل أدوات التحقق

فحص قراءة فقط، بلا تدريب أو شبكة:

```bash
node tools/training/preserve-sheikha-qwen-adapters-v1.cjs audit
```

إنشاء جولة حفظ جديدة، وليس أمرًا مطلوبًا لإكمال الجولة المنجزة؛ يستهلك نحو 3GB إضافية للحزم مع مساحة مؤقتة أثناء الاستعادة:

```bash
node tools/training/preserve-sheikha-qwen-adapters-v1.cjs preserve
```

التحقق من حزمة قائمة: تستخرج مسارات الحزمة والمفتاح من إيصالها المحلي، دون عرض محتوى المفتاح. أداة الحفظ لا تسمح باستعادة فوق وجهة موجودة:

```bash
node tools/training/sheikha-artifact-custody-v1.js verify --bundle PRIVATE_BUNDLE --key PRIVATE_KEY
node tools/training/sheikha-artifact-custody-v1.js restore --bundle PRIVATE_BUNDLE --key PRIVATE_KEY --to NEW_PRIVATE_DIRECTORY
```

اختبارات الأدوات: 11 اختبارًا لجرد المصادر والحجر والنسخ، و52 اختبارًا لأداة الحفظ وخطة العهدة، نجحت في هذه المراجعة. تشمل العبث بالبصمات والروابط والهروب من النطاق وعدم الكتابة فوق الملفات، واستعادة ملفات الترميز والقالب كنص خامل. هذه ليست اختبارات جودة استدلال أو شهادة أمن شاملة.

**الخلاصة:** نحتفظ بما بُني وبأدلته، ونمنع الخلط بين الحفظ والجودة والترقية. نقدم للعميل مسارًا مفهومًا ومفيدًا، ونقبل التحسين عندما يثبت أثره ويمكن التراجع عنه، لا عندما يحمل اسم نموذج أحدث.
