# Sheikha Software Development Platform — SDP V1

منصة محلية لتطوير لغة شيخة وفحصها وإنتاج حزم bytecode تجريبية. اسم المنتج لا يعني اعتمادًا من QNX أو غيرها.

## الأدوات
- الحالة: `node tools/environment/sheikha-sdp-v1.cjs status`
- الاختبار: `node tools/environment/sheikha-sdp-v1.cjs check`
- البناء: `node tools/environment/sheikha-sdp-v1.cjs build`

خط البناء: مصدر شيخة → lexer → AST → فحص أنواع → IR → bytecode → تنفيذ محكوم محلي → تقرير وبصمات.

يبني الإصدار الحالي برنامج تأسيس OS وبرنامج طبقات المنظومة من مصدرين ثابتين؛ لا يقبل أسماء ملفات أو أوامر تشغيل اعتباطية. ينتج IR وbytecode وتقرير تنفيذ وSHA256SUMS في مجلد بناء جديد، ولا يغير تقارير البناء السابقة.

النموذج الأصلي Bare-Metal مسار مستقل له دليل إقلاع سابق؛ البناء هنا لا ينشئ ELF أو صورة OS جديدة ولا يثبت نقل البرامج إلى النواة. لا نشر إنتاجي أو اتصال أجهزة أو منح شهادات.

البيئة الحالية مستضافة على Linux/Node.js. دعم Windows أو QNX أو VxWorks أو INTEGRITY لم يُنفذ أو يُختبر لهذا الإصدار. لوحة التطوير المحلية منفصلة ومؤقتة وتحتاج فحص توفرها عند الاستخدام.

## الواجهة الموحدة

الأداة نفسها تدعم project-init PROJECT_ID وproject-build PROJECT_ID وproject-verify PROJECT_ID BUILD_ID وinventory. أمر check يشغّل 112 اختبارًا تغطي المترجم والربط والفاحص والمشاريع والجرد وقيود الواجهة. أوامر المشاريع الجديدة تستخدم الملفات والسجلات القائمة، ولا تنشئ أساسًا أو ترخيصًا بديلًا.

أمر project-verify للقراءة؛ حفظ مراجعة منفصلة متاح في أداة sheikha-sdp-project-verify-v1.cjs بالخيار --write. جرد المكونات محدود باستيرادات CommonJS الحرفية؛ لا يدعي تغطية كل تبعيات المنتج.

هدف native-linux تجريبي للعرض والرفض والشروط المنطقية الحرفية، وينتج ELF مضيفًا يعتمد على libc؛ ليس نواة شيخة المستقلة.

## سلسلة الأدوات المثبتة

الحالة: `node tools/environment/sheikha-sdp-v1.cjs toolchain-status`

البناء والفحص: `node tools/environment/sheikha-sdp-v1.cjs toolchain-verify hello-sheikha-v1`

يتحقق الفحص من GCC وClang وCMake وNinja، ويترجم الجزء المدعوم للعرض والرفض والشروط المنطقية الحرفية من لغة شيخة عبر CMake وNinja وClang إلى ELF على Linux x64. يقارن الناتج بتنفيذ VM ويحفظ بصمات المصدر والأثر والتقرير في مجلد جديد. يعتمد على أدوات المضيف وlibc؛ لا يشغّل مراحل إقلاع Bare-Metal ولا يثبت اكتمال المترجم. الجرد يشمل الآن واجهة SDP وأداة سلسلة البناء والهدف الأصلي ضمن حدود استيرادات CommonJS الحرفية.

مراجعة أثر محفوظ دون تشغيل ملفه التنفيذي: `node tools/environment/sheikha-sdp-v1.cjs toolchain-review hello-sheikha-v1 toolchain-YBIoJQ`

يفحص المراجع البصمات الأربع ولقطة مصدر المشروع وربط الترخيص الحالي، ويقارن C المولد وإعداد CMake والناتج المسجل بتنفيذ VM الحالي. لا يعيد تجميع الأثر أو تشغيله؛ تطابق البصمة الذاتية ورأس ELF لا يثبتان دلالة الملف التنفيذي أو توقيعًا موثوقًا. النسخ المحفوظة من إصدارات المترجمات تظل ادعاءات تقرير البناء، وليست شهادات مستقلة.

فحص تكرار البناء: `node tools/environment/sheikha-sdp-v1.cjs toolchain-repeatability hello-sheikha-v1`

ينشئ بناءين جديدين ويراجع أدلة كل منهما، ثم يقارن المصدر والخرج وبصمة ELF. النتيجة ملاحظة لبناءين على المضيف الحالي، وليست ضمان تكرار البناء على بيئات أخرى أو شهادة سلامة. تحفظ النتيجة في runtime/sheikha-sdp/v1/repeatability دون تغيير البنى السابقة.

## نطاق التطوير ومنع التجاوز

مرجعية العمل بالكتاب والسنة وقاعدة لا ضرر ولا ضرار توجيه أخلاقي حاكم، وليست شهادة امتثال تصدرها البرمجيات. بوابة SDP الجديدة تفحص اسم الأمر وعدد المعطيات ومعرّفات المشاريع والبناء قبل أي تنفيذ. البناء والاختبار والمراجعة تتطلب تطابق نطاق الترخيص الداخلي السابق، بينما تظل قراءة الحالة والجرد ممكنة لتشخيص اختلال النطاق. لا أوامر نشر أو دفع أو تغيير أسرار أو DNS أو تحريك أجهزة ضمن الواجهة. لا تنفذ البوابة عزلًا على مستوى نظام التشغيل ولا تضمن غياب كل ضرر؛ المسائل الشرعية والتأهيل الميداني تحتاج مراجعة بشرية مختصة وأدلة مستقلة.

## فحص المراقبة عند الطلب

`node tools/environment/sheikha-sdp-v1.cjs watch-check hello-sheikha-v1 toolchain-YBIoJQ`

يفحص تطابق نطاق السجل الداخلي وبصمات آثار Bare-Metal التاريخية واتساق أدلة بناء المشروع، ويسجل PASS أو FAIL أو UNKNOWN لكل فحص. التقرير الجديد خاص بهذه اللحظة وهذه المصادر فقط، ويُحفظ مع بصمته في runtime/sheikha-sdp/v1/watch. لا يعيد إقلاع النواة ولا يفحص صحة الخدمات الحية ولا يقرأ مستشعرات مادية أو يوقف الخدمات. ليس مراقبة مستمرة أو حارس سلامة ماديًا. يبقى التشخيص متاحًا إذا تعطل نطاق الترخيص؛ لا يمنح ذلك صلاحية بناء أو تشغيل جديدة.

جلسة مراقبة محدودة: `node tools/environment/sheikha-sdp-v1.cjs watch-session hello-sheikha-v1 toolchain-YBIoJQ`

تجري ثلاث جولات بفاصل خمس ثوانٍ بعد انتهاء الجولة السابقة، وتحفظ كل جولة ببصمة وربط ببصمة سابقتها وتقرير ملخص. يبقى الفشل العابر مسجلًا ولو تعافى الفحص الأخير؛ فجوة أخذ عينات فوق 15 ثانية تمنع وصف الجلسة بأنها ناجحة بالكامل. تراقب الأدلة المحلية فقط، وتتوقف بعد الجولة الثالثة؛ لا تُثبت خدمة دائمة أو تعمل على مدار الساعة، ولا تتدخل في الخدمات. سلسلة البصمات غير موقعة وليست مانعة للعبث ممن يملك تعديل جميع الملفات.

مراجعة سجل مراقبة محفوظ: `node tools/environment/sheikha-sdp-v1.cjs watch-session-review session-4HhuKN`

يفحص المراجع بصمات الملفات الأربعة، وتسلسل الجولات وربط كل جولة بسابقتها، ويعيد حساب النتائج والملخص من الملاحظات المحفوظة. لا يعيد جمع الملاحظات ولا يثبت صحتها المستقلة أو حالة النظام الآن. لا تعتبر السلسلة غير الموقعة إثباتًا لعدم قدرة مالك الملفات على تعديل السجل وإعادة بصمته بالكامل.

لوحة التطوير المحلية متاحة أثناء تشغيل tools/environment/sheikha-linux-development-runtime-v1.cjs عند /sdp-dashboard، وبياناتها عند /sdp. تعرض نطاق SDP واتساق بناء toolchain-YBIoJQ وسجل session-4HhuKN كأمثلة أدلة محددة، مع الفصل عن صحة الخدمات الآن. تتجدد القراءة عند الطلب بكاش خمس ثوان؛ ليست جلسة مراقبة دورية.

تعرض اللوحة قياسًا حيًا محددًا لـ GET http://127.0.0.1:8080/health: الوقت وكود HTTP وزمن الاستجابة، مع مهلة إجمالية ثانيتين ودون حفظ جسم الاستجابة أو متابعة التحويلات. لا يثبت HTTP 200 جاهزية جميع وظائف الخدمة. نسخة معاينة محلية مستقلة متاحة بتشغيل أداة لوحة Linux مع --preview على المنفذ 39732 دون إيقاف النسخة السابقة.

جلسات watch-session الجديدة تحفظ قراءة GET للخدمة المحلية 8080/health في كل جولة، بما فيها الوقت وزمن الاستجابة وكود HTTP أو حالة التعذر/المهلة. أي فشل عابر يبقى ظاهرًا في الملخص حتى بعد التعافي. المراجع يقبل الجلسات التاريخية الخالية من هذا القياس بوصفها أدلة محلية فقط، ولا يحوّلها إلى قياس حي. لا يثبت نجاح الجولات جاهزية الخدمة الكاملة.

لوحة المراقبة تختار أحدث مجلد جلسة حسب mtime المحلي، ضمن حد 128 جلسة. تراجع تلك الجلسة وحدها؛ إذا كان آخر سجل ناقصًا أو تالفًا تعرض UNKNOWN بدل الرجوع الصامت إلى نجاح قديم. تعرض وقت آخر جولة وعمرها، وتصف ما فوق 60 ثانية بأنه تاريخي أقدم من دقيقة. الاختيار حسب بيانات نظام الملفات غير الموقعة، وليس ترتيبًا معتمدًا خارجيًا.

سجل استجابات الخدمة في /service-history، وتعرض اللوحة آخر 20 قياسًا. تشترك نقاط قياس الخدمة في كاش خمس ثوان لتقليل الطلبات. تُحفظ حتى 720 مشاهدة لكل جلسة في ملفات جديدة داخل runtime/sheikha-linux-development/v1/service-observations، دون جسم الاستجابة. حالة فشل الحفظ ظاهرة وتوقف محاولات الكتابة لتجنب إظهار سلسلة محفوظة كاملة بعد فجوة. سجل البصمات غير موقع، ولا يستبدل الرصد المستقل.

مراجعة سجل خدمة محفوظ: `node tools/environment/sheikha-sdp-v1.cjs service-history-review journal-dI1YEY`

يفحص ترتيب الملفات وتسلسل القياسات وربط البصمات وصحة حقول القياس وحدود الحجم. يحتفظ بعدد حالات التعذر والمهلة والردود غير 200 حتى لو كان آخر رد ناجحًا. لا يجمع قياسًا جديدًا. سجل غير موقع لا يثبت اكتمال التاريخ أو استقلال صحته؛ حذف آخر السجل أو إعادة كتابة جميع سجلاته لا يمكن إثباته بهذا الفاحص وحده.

الأرشيف المحلي في /service-archive يعرض مراجعة أحدث مجلد سجل قياسات حسب mtime المحلي، بحد 128 مجلدًا، دون قياس جديد. اللوحة تعرض عدد القياسات المحفوظة وعدد حالات التعذر والمهلة والردود غير 200 ووقت آخر قياس وعمره. تلف أحدث سجل يظهر UNKNOWN ولا يعوض بنجاح قديم.

توسعة الشروط الحرفية: true/false وصحيح/خطأ مدعومة في VM وهدف C، مع فحص الفرعين وحدود العمق والحجم. التعابير العامة والمتغيرات خارج نطاق هذا الهدف؛ المقارنات العددية الثابتة توسعت لاحقًا ضمن الحدود أدناه. مثال تجريبي جديد في المشروع literal-branches-v1 لا يغير hello-sheikha-v1.

تصحيح IR: يحفظ الآن الشروط داخل الفروع بدل إسقاطها، ويُختبر الخرج المتوقع للمصدر المتداخل صراحة. أي حزمة تاريخية احتوت شرطًا متداخلًا مسقطًا قد تفشل المقارنة بالمترجم الحالي؛ تحفظ كما هي ويُنشأ بناء جديد، دون وصفها بأنها مكافئة للنتيجة المصححة.

يدعم VM والبناء الأصلي ست مقارنات بين أعداد صحيحة ثابتة ضمن ±1000000. يفحص مدقق الأنواع المقارنات داخل الفروع المتداخلة أيضًا، بما فيها غير المنفذة. المصدر التجريبي integer-comparisons-v1 يختبر المقارنات السالبة والحدود والتداخل. لا حساب عشري مالي أو متغيرات؛ توسع الحساب الصحيح الثابت لاحقًا ضمن الحدود أدناه.

يدعم الحساب الصحيح الثابت في الشروط الجمع والطرح والضرب والأقواس مع أولوية العمليات، ورفض تجاوز النطاق في أي خطوة وسيطة. مثال integer-arithmetic-v1 يثبت الخرج المتوقع في VM وGCC وClang. لا يدعي محرك حساب مالي أو لغة تعبيرات عامة.

مرجع هوية لغة شيخة وأركانها وحدودها: sheikha-language/docs/unified-language-spec.md، مسجل في المرجع الجذري الحالي. مثال القيم والمنهج العربي language-charter-v1.shk يمر بالمترجم ومدقق العقد وVM؛ النجاح تحقق برمجي محدود لا شهادة شرعية أو تأهيل لكل العلوم.

حالة اللغة والمرجعية والقدرات: `node tools/environment/sheikha-sdp-v1.cjs language-status`. يقرأ مثال الميثاق ويمرره بالمترجم وVM، ويعرض بصمات المثال والمواصفة والنحو وفهرس المنهجيات، ويطابق فهرس المناهج المسجل مع محرك البحث الحالي، ويراجع دليل الجزء الأصلي المحدود. لا ينشئ دراسة علمية أو يصدر فتوى أو يشغل ELF أثناء الاستعلام.

دراسة وصفية لسجل خدمة محفوظ: `node tools/environment/sheikha-sdp-v1.cjs study-service journal-dI1YEY`. تراجع نفس بايتات السجل أولًا، ثم تحسب عدد المشاهدات ومتوسط/أدنى/أعلى زمن الانتظار، وتفصل زمن ردود 200 عن المهلة والتعذر والردود الأخرى. تعرض نافذة الرصد وانحياز العينة عند الطلب. نسبة نجاح العينة لا تُسمى تقدير توافر عام أو SLA، ولا استنتاج سببية.

مقارنة وصفية بين سجلين: `node tools/environment/sheikha-sdp-v1.cjs compare-service journal-dI1YEY journal-K4eEpu`. تراجع السجلين أولًا، وترفض استخدام السجل نفسه أو مشاهدات متطابقة بينهما. تعرض أحجام العينات والفروق باتجاه العينة الثانية ناقص الأولى، مع فصل زمن ردود 200 عن زمن انتظار جميع المحاولات. لا تجربة مضبوطة أو استنتاج سببي أو دلالة إحصائية أو استقلال عينات مثبتًا. تفعيل المنهج المقارن هنا محدود بسجلات نقطة محلية واحدة.

تعرض لوحة /sdp-dashboard قدرات اللغة عبر فحص المرجع والمترجم المحلي، وتحليلًا وصفيًا لأحدث سجل خدمة متحقق منه. التحليل يعرض حجم العينة ومتوسط الانتظار ومتوسط ردود 200 منفصلين، ولا يجري قياسًا جديدًا أو يقرر السببية أو مستوى الخدمة. تعذر أي فحص يظهر UNKNOWN دون حجب بقية الأدلة؛ لا اعتماد شرعي آلي ولا ادعاء اكتمال جميع العلوم.

تعرض اللوحة مقارنة وصفية لأحدث سجلين بحسب وقت تعديل المجلد، بعد تحقق محتوياتهما ورفض تكرار الملاحظات بينهما. ترتب العينة الأقدم في الاختيار أولًا وتعرض الفرق الثانية ناقص الأولى. هذا الترتيب ليس تجربة زمنية مضبوطة؛ لا دلالة إحصائية أو سببية. تعذر أحدث زوج يظهر UNKNOWN ولا يُبحث عن زوج أقدم ناجح.

تقوية الاعتمادية: تعذر إعداد الأدلة أو توليد HTML يعيد HTTP 503 وحالة UNKNOWN دون تفاصيل خاصة، ويزيل النتيجة المؤقتة المتعذرة للسماح بمحاولة جديدة فور الطلب التالي. اختبارات حقن الفشل تتحقق من استمرار مسارات القراءة والتعافي دون إعادة تشغيل الخدمة. النطاق المحلي الحالي لا يثبت جاهزية إنتاجية أو امتلاك جميع التقنيات. أولويات التوسع: جودة المترجم، سلامة الأدلة، أدوات البناء، قياسات مؤهلة، ومحاكاة صناعية؛ لكل توسع تنفيذ واختبار مستقل.

الاتصالات المحكومة: connection-status يعرض علاقة الخدمة المحلية وهدف استجابتها؛ connection-check ينفذ GET ثابتًا على 127.0.0.1:8080/health عبر IntegrationGateway وIntegrationRegistry القائمين. الهدف HTTP 200 خلال 1000 ms هدف تطويري وليس SLA. تسجل التغذية الراجعة في الذاكرة ضمن جلسة محدودة بمئة طلب، وتحفظ عدد إخفاقات الهدف بعد التعافي؛ لا مراقبة مستمرة أو اتصال خارجي أو معالجة ذاتية. صلاحيات الموصل المحلي لا تنتقل إلى بقية البوابة أو الأنظمة. تأهيل الأنظمة الخارجية والهوية والتشفير والعقود والتراخيص يبقى خاصًا بكل تكامل.

الموصلات وأشباه الموصلات: electronics-status يعرض معمارية حوكمة تربط موصلات البرمجيات المقيدة بمسار منفصل لمواصفات الموصلات الكهربائية وأشباه الموصلات والمستشعرات والمعالجات. فاحص المواصفات يرفض الحقول الزائدة والحدود غير الرقمية أو غير الصالحة ومراجع البصمات غير الصحيحة شكليًا. قبول المواصفة لا يثبت أصالة ورقة البيانات أو وجود قطعة أو توافقها أو سلامتها؛ تبقى نتائج القياس والمعايرة والتأهيل المستقل معلقة، دون تشغيل عتاد أو تصنيع أو شراء. حدود المنتج النهائية تستلزم مرجعًا مصنعياً قابلًا للتحقق وتأهيل حالة الاستخدام.

ترميز المكونات والإرسال والاستقبال: component-protocol-demo يجرب رسالة حرارة اصطناعية في الذاكرة مع رقم تسلسل ومدة صلاحية وإقرار مرتبط ببصمة بايتات الرسالة. رمز SHK-COMP-V1 هو بصمة مواصفات معلنة وفق ترتيب الحقول الحالي، وليس هوية قطعة فعلية أو توقيعًا أو مصادقة؛ البصمة غير سرية. الرسائل محدودة 4096 بايت، طلب معلق واحد ومئة رسالة للجلسة؛ يرفض التكرار والتغيير والانتهاء. لا UART/I2C/SPI/CAN/GPIO حقيقي أو قياس حراري أو اتصال بجميع الشرائح. يحتاج كل عتاد ورقة بيانات موثقة ومشغلًا وصلاحيات وتأهيلًا مستقلًا.

التكامل مع أنظمة التشغيل: os-integration-status ينفذ اختبار VM محليًا ويجرد أصول المصادر وبصماتها مع مرجع التراخيص الداخلي. يسجل موارد المضيف كما يعلنها نظام التشغيل دون إثبات مادي مستقل. Linux وWindows وmacOS ملفات استهداف عبر Node.js، ويؤهل اختبار الدخان للمضيف الحالي فقط؛ الأنظمة الأخرى PROPOSED_NOT_TESTED_ON_TARGET. لا استبدال نواة أو تنصيب مشغلات أو شراء عتاد أو اتصال بحسابات Microsoft وApple. هذا مسار للتكامل البرمجي المحدود؛ لا توافق شامل أو تأهيل صناعي.
