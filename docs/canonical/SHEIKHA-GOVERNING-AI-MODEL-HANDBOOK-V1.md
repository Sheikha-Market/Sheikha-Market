# كتاب نموذج شيخة الحاكم ومحرك اتحاد النماذج V1

## بطاقة المنتج

- الاسم: نموذج شيخة الحاكم ومحرك اتحاد النماذج
- الاسم التقني: `SHEIKHA_GOVERNING_MODEL_ORCHESTRATOR_V1`
- رقم الترخيص الداخلي: `SHEIKHA-AI-GOV-ORCH-2026-0001`
- طبيعة الرقم: ترخيص منتج داخلي قابل للتتبع، وليس اعتمادًا حكوميًا أو دوليًا
- المالك للبرمجيات الأصلية: مشروع شيخة، مع بقاء حقوق كل نموذج ومورد لصاحبها
- الحالة: `ACTIVE_GOVERNED_NOT_COMMERCIALLY_PROMOTED`
- اللغات: العربية أولًا، مع دعم التوجيه متعدد اللغات بحسب النموذج

## الملخص التنفيذي

نموذج شيخة الحاكم ليس ادعاءً بامتلاك أوزان كل نماذج العالم، ولا نموذجًا واحدًا نُسخت داخله
آلاف النماذج. هو طبقة حوكمة وتوجيه تجمع بيانات القدرات والحقوق والقياسات، ثم تختار أداة أو
نموذجًا مصرحًا به لكل مهمة. عند غياب مرشح مستوفٍ للشروط تستخدم المنظومة مسارًا عربيًا حتميًا
محدودًا أو تمنع التنفيذ مع بيان السبب.

السجل المثبت حاليًا يحتوي 540 سجل نموذج اتحادي، لا 3500. وجود سجل لا يعني أن النموذج مثبت أو
مجاني أو قابلًا للاستدعاء أو مرخصًا تجاريًا. توجد سبعة نماذج محلية في Ollama وقت التحقق.

## المشكلة التي يحلها

تختلف النماذج في اللغة، والبرمجة، والاستدلال، والتكلفة، والخصوصية، والترخيص، وزمن الاستجابة.
استخدام نموذج واحد لكل شيء يرفع المخاطر والتكلفة. المحرك يحول هذا الاختلاف إلى محفظة قدرات
محكومة، دون جمع أوزان متعارضة أو إزالة قيود الترخيص.

## الميزة التنافسية

1. العربية أولًا: إجابات تشغيلية حتمية للمهام الحساسة للزمن، ثم نموذج توليدي عند الحاجة.
2. الأدلة قبل الادعاء: التسجيل والفهرسة والاختبار والترخيص حالات منفصلة.
3. اختيار متعدد الأبعاد: القدرة، والترخيص، والجودة، والزمن، والتكلفة، والخصوصية، والموثوقية.
4. استقلال واجهة المنتج: يمكن تبديل المورد دون تغيير عقد المستخدم أو مسار الحوكمة.
5. خفض التكلفة: الاسترجاع والحساب والأدوات تسبق استدعاء النموذج الكبير.
6. احتواء الفشل: النموذج المتراجع يُعزل تلقائيًا ولا يُرقّى إلى المستخدمين.
7. قابلية التدقيق: لكل قرار مسار وبصمة ومصدر ودليل وحدود.

القيمة التجارية ليست في كثرة أسماء النماذج، بل في خفض زمن القرار والتكلفة والمخاطر مع الحفاظ
على قابلية التراجع والتفسير. هذه القيمة تحتاج قياسات ميدانية قبل تحويلها إلى أرقام تسويقية.

## المعمارية

```text
طلب المستخدم
  -> تصنيف النية والأثر
  -> تحقق المخطط والصلاحية
  -> بوابة الحقوق والترخيص
  -> استرجاع دليل أو أداة حساب عند الحاجة
  -> اختيار نموذج مستوفٍ للجودة والزمن
  -> توليد أو مسار عربي حتمي
  -> فحص الاتساق والسلامة
  -> سجل تدقيق
  -> مراجعة بشرية للأثر المرتفع
```

## طرق التكامل المسموحة

- توجيه الطلب إلى نموذج واحد وفق القدرة.
- Ensemble مع حفظ أثر كل مساهمة.
- RAG بمصادر مرخصة واستشهادات قابلة للتتبع.
- استدعاء أدوات حساب وتحليل حتمية.
- Fine-tuning أو distillation عند وجود حق مكتوب لكل مدخل ومخرج.
- Canary ومقارنة A/B بعد موافقة تشغيلية.

لا يسمح افتراضيًا بدمج أوزان مجهولة الترخيص، أو نقل مخرجات نموذج لتدريب منافس خلافًا للرخصة،
أو إعادة بيع وزن لا يوجد تفويض صريح بإعادة توزيعه.

## نموذج البيانات

يسجل كل نموذج بالحد الأدنى: هوية المورد، الإصدار، البصمة، المدخلات والمخرجات، القدرات، نافذة
السياق، طريقة الاستدعاء، الترخيص، قيود الاستخدام، جودة الاختبار، زمن P50/P95، التكلفة، موقع
البيانات، تاريخ القياس، وحالة دورة الحياة.

## التدريب والتحسين

دورة التدريب: بيانات مرخصة -> provenance -> فحص PII والأسرار -> تقسيم train/validation/test ->
موافقة بشرية -> تدريب معزول -> بصمات checkpoints -> تقييم مستقل -> Canary -> ترقية أو عزل.

لا يعمل التدريب بلا توقف. المجدول يفحص باستمرار، لكنه يدرب فقط عند وجود إصدار بيانات جديد،
موارد مناسبة، انتهاء فترة التهدئة، وترخيص وموافقة مطابقين للبصمة. لا تتم الترقية التجارية آليًا.

### تدريب النماذج المتخصصة تحت الحاكم

يعامل الحاكم كل نموذج جديد بوصفه Student محدود المجال، وليس نسخة تدعي معرفة كل شيء. يحدد
المجال ومعيار النجاح، ويتحقق من ترخيص النموذج والبيانات، ثم يبني curriculum واختبارًا مستقلًا
وخطة تراجع. مخرجات Teacher لا تصبح بيانات صحيحة تلقائيًا؛ تُعامل كمادة اصطناعية غير موثوقة حتى
تُراجع وتُقارن بمصادر مستقلة.

عند استخدام مرجعية الكتاب والسنة يلزم corpus موثق ببصمة، وسياسة لصحة المصدر والإسناد، وفصل
النص المنقول عن الشرح والاستنباط، ومراجعة بشرية من متخصصين مؤهلين. البرنامج لا يصدر فتوى، ولا
يدعي سلطة شرعية، ولا يجعل كل مسألة تقنية حكمًا دينيًا. القيم الحاكمة هي الصدق والعدل والأمانة
والوفاء بالعقود والتثبت ومنع الضرر، مع الالتزام بالقوانين والحقوق الصحيحة.

## الحالة المحلية المثبتة

- Qwen2.5-0.5B LoRA V2: معزول بعد نتيجة 0/6.
- Sheikha-Core المبني على Llama 3.1 8B: نتيجة 1/6 وزمن متوسط مرتفع؛ غير مرقى.
- Qwen3-4B: مثبت وترخيصه Apache-2.0، لكن Ollama شغله على CPU وانتهت الحالات عند 30 ثانية؛
  يلزم إصلاح GPU ثم إعادة التقييم.
- المسار العربي الحتمي: يعمل في SSE للحوكمة والحساب والهندسة وإصلاح البرمجيات والجاهزية.

## المواصفات التشغيلية المستهدفة

- أول Token للمسار الحتمي: أقل من ثانية محليًا.
- P95 للنموذج التوليدي: يحدد بعد اختبار GPU ولا يُفترض مسبقًا.
- التوافر التجاري: لا يُعلن قبل اختبار حمل متعدد المراحل ومراقبة فعلية.
- التوسع: Stateless gateway، صفوف محكومة، workers، rate limits، circuit breakers، cache،
  مناطق متعددة، ونسخ احتياطي واختبار استعادة.

جهاز RTX 4060 مناسب للتطوير والتقييم وCanary محدود، وليس وحده بنية لخدمة ملايين المستخدمين.
التوسع لذلك يحتاج عقد موارد إقليمية، ميزانية، مراقبة، واختبارات سعة.

## الأمن والخصوصية

- المنع الافتراضي للشبكة والملفات والعمليات غير المصرح بها.
- خزنة أسرار بدل تضمين المفاتيح.
- تقليل البيانات وتحديد مدة الاحتفاظ وحق الحذف.
- فصل بيانات العملاء وعدم التدريب عليها دون موافقة وحق صريح.
- سجل تدقيق غير قابل للتعديل الصامت.
- مراجعة بشرية للطب والصحة والمال والقانون والأثر المرتفع.

## الصلاحيات

المسموح: قراءة الحالة المحكومة، واستدعاء API معتمد، واسترجاع مصدر مصرح، وتشغيل أداة حساب،
وإنشاء مسودة، وطلب موافقة. المحظور افتراضيًا: shell عام، وملفات عامة، وتثبيت البرامج، وتغيير
النظام، والوصول للنواة أو firmware، والنشر الخارجي، والتوقيع، وإصدار فتوى أو حكم شرعي آلي.

## الترخيص

يغطي الرقم الداخلي كود المحرك والوثيقة التي أنشأها المشروع فقط. لا يعيد ترخيص Qwen أو Llama
أو أي نموذج طرف ثالث. Qwen3-4B مسجل تحت Apache-2.0، وSheikha-Core الحالي يتضمن Llama 3.1
وتسري عليه رخصة مجتمع Llama ومتطلبات الإسناد والاستخدام. يجب توزيع Notices المطلوبة مع المنتج.

لا يستطيع البرنامج إصدار تراخيص حكومية أو شهادات اعتماد دولية ذاتيًا. يستطيع توليد مسودة،
وفهرسة الأدلة، ومتابعة انتهاء الصلاحية، لكن الإصدار القانوني يبقى للجهة المخولة.

## حدود الاستخدام

لا ادعاء بالوعي أو العلم المطلق أو التفوق على جميع النماذج. لا استخدام غير قانوني أو ضار، ولا
قرارات عالية الأثر بلا إنسان مؤهل. لا ضمان للدقة دون تحقق مستقل، ولا وصف «جاهز للإنتاج» قبل
اجتياز الجودة والأمن والحمل والتعافي والترخيص.

## خارطة الإغلاق التجاري

1. إصلاح Ollama GPU وإثبات `PROCESSOR=100% GPU`.
2. إعادة Qwen3-4B على بوابة عربية موسعة وقياس P50/P95.
3. اختبار السلامة والهلوسة والخصوصية وحقن الأوامر.
4. اختبار حمل وrate limits وqueue وcircuit breaker والتعافي.
5. إعداد NOTICE وSBOM وprovenance وعقد مستوى الخدمة.
6. مراجعة قانونية بشرية للرخص والخصوصية وشروط البيع.
7. Canary محدود، ثم قرار ترقية موقع بالبصمة وقابل للتراجع.

## سياسة الادعاء

الحالة التجارية النهائية تبقى `false` حتى تنجح جميع البوابات. تشغيل مسار محدود بنجاح لا يثبت
جاهزية عالمية، وفهرسة نموذج لا تمنح حق استخدامه، وكثرة النماذج لا تعني جودة أعلى تلقائيًا.
