## التنفيذ المضاف

المدخل: `tools/verification/sheikha-raha-engine-v1.py`. يستخدم Python ومكتباته القياسية، ويعيد استخدام قارئ الملفات الآمن الموجود في `tools/verification/sheikha-v35-evidence-audit-v1.py` دون تعديل ذلك القارئ.

```text
Legacy engine / manifest / Evidence V2 / master bytes
    -> bounded read + SHA-256 + static AST parsing
    -> historical binding observations (no engine import or execution)

Local JSON batch
    -> schema + decimal + unit validation
    -> duplicate detection / conflict quarantine
    -> separate totals by kind, unit and source class

Review result + fixed production hold
    -> stdout summary, or explicit new private bundle
    -> observations.json + review.sqlite3 + SHA256SUMS + COMPLETE.json
```

هذه أداة مراجعة محلية تعمل داخل نظام التشغيل، وليست نواة نظام أو محرك حوسبة ثقيلة مقاس الأداء. لا API جديدًا، ولا مؤقتًا، ولا مراقبًا مستمرًا، ولا اتصالًا بمزود. لا تُحمّل أوزانًا ولا تُدرّب نموذجًا، ولا تحرك أجهزة، ولا تنشر أو تدفع. حدود `PRODUCTION_HOLD` تخص مخرجات هذه الأداة وغياب مسارات التنفيذ فيها؛ لا تثبت فرض عزل على بقية عمليات الجهاز. التحقق من المدخلات ليس sandbox مستقلًا لنظام التشغيل.

## عقد الدفعة

مثال قابل للتشغيل: `examples/raha/synthetic-batch-v1.json`. جميع سجلاته `SYNTHETIC` وبصمات المصدر فيه قيم اختبار، وليست مراجع لمستندات مالية أو مستشعرات حقيقية.

- غلاف JSON يضم `schemaVersion: 1` و`records` فقط. الحد 1 MiB للدفعة و1000 سجل، وبحد أدنى سجل واحد. تُرفض المفاتيح المكررة والقيم غير المنتهية.
- حقول السجل المحددة: `id`, `kind`, `value`, `unit`, `sourceSha256`, `sourceClass`. لا يقبل السجل حقول اعتماد أو تشغيل إضافية.
- `value` نص عشري، حتى 12 رقمًا قبل العلامة وستة بعدها؛ لا float أو صيغة أسية. الحساب باستخدام `Decimal`، دون تحويل وحدات أو أسعار عملات.
- `measurement` يدعم `kg`, `m`, `l`, `kWh`, `count`. وحدة `count` تتطلب عددًا صحيحًا. الإشارة السالبة مسموحة في القياسات وفق هذا العقد التقني فقط.
- `transaction` يدعم `SAR`, `USD`, `EUR` لأغراض تجميع أرقام المراجعة فقط. القيم السالبة تعزل لأنها غير مدعومة في هذا النموذج، وليس ذلك حكمًا على صلاحية معاملات الرد أو التسوية.
- `sourceClass` إما `SYNTHETIC` أو `USER_DECLARED`. وجود `sourceSha256` صحيح الشكل لا يصادق على المصدر ولا يفتح ملفات يشير إليها المستدعي.
- نفس المعرف والمحتوى المتطابق يُحتسب مرة واحدة. اختلاف المحتوى تحت نفس المعرف يعزل جميع نسخه، حتى إن كانت إحدى النسخ غير صالحة. اختلاف التنسيق مثل `1.0` و`1` يظل تعارض محتوى، ولا يُحسم تخمينًا.
- لا تخلط المجاميع بين الأنواع أو الوحدات أو البيانات الاصطناعية والمصرح بها. السجل المقبول شكليًا حالته `VALIDATED_FOR_REVIEW`، وليس موافقة مالية أو شرعية.

يتضمن التقرير مواقع السجلات وبصماتها وأسباب العزل والمجاميع، ولا ينسخ السجلات الخام أو معرفاتها. حجب السجلات لا يجعل البصمات أو المجاميع عامة أو مجهولة الهوية؛ تبقى الحزمة خاصة. stdout يعرض الحالة والأعداد فقط.

## الأدلة والتخزين

فحص V43.75 يقارن مانيفست الإصدار بسجله، وبصمة قاعدة البيانات التاريخية بالمرجع التاريخي نفسه. يعرض مقارنة القاعدة الحالية بالماضية للمعلومية فقط؛ اختلافها لا يثبت التلف أو يبرر إعادة ختم التاريخ. سلامة بنية SQLite الرئيسية لم تُفحص، ولم تُفتح القاعدة الحية عبر SQLite. تُقرأ بايتاتها فقط لحساب البصمة.

القارئ يرفض الروابط الرمزية والملفات الخاصة، ويحد الملف إلى 64 MiB، ويتحقق من استقرار الملف أثناء القراءة. تتم قراءة المصادر ثانيةً بعد التدقيق، وتُرفض ملفات SQLite الجانبية `-wal/-shm/-journal`. هذه إجراءات كشف تغير وليست لقطة معاملية أو ضمانًا لغياب كاتب متزامن؛ النتيجة وصف لوقت الفحص فقط.

الحفظ اختياري، في دليل جديد مباشر داخل `reports/private` ذي صلاحية `0700`. لا استبدال لدليل سابق؛ ملفات الحزمة `0600`. قاعدة `review.sqlite3` جديدة تمامًا، تضم metadata وبصمات قرارات مراجعة السجلات، وليست نسخة أو ترقية للقاعدة الرئيسية. يستخدم الإدخال معاملات SQL معلّمة، وتُفحص سلامة قاعدة المراجعة وتطابق الصفوف قبل اكتمال الحفظ.

يُكتب `COMPLETE.json` أخيرًا، ويحتوي بصمتي التقرير وقاعدة المراجعة. غيابه يعني حزمة غير مكتملة، ولا يُحذف الدليل الجزئي تلقائيًا. وجوده يعني اكتمال كتابة الحزمة فقط، حتى لو كان محتوى التقرير `BLOCKED`. البصمات ليست توقيعًا أو إثبات هوية أو سجلًا غير قابل للتعديل؛ من يستطيع تغيير الملفات قد يعيد حسابها. لا يُعاد تثبيت بصمات Evidence V2 ولا تُمحى ملاحظات سابقة.

## التشغيل

مراجعة دون حفظ أو تعديل للمصادر:

```bash
python3 -I -B tools/verification/sheikha-raha-engine-v1.py --batch examples/raha/synthetic-batch-v1.json
```

حفظ صريح في دليل جديد؛ يجب ألا يكون الاسم مستخدمًا:

```bash
python3 -I -B tools/verification/sheikha-raha-engine-v1.py --batch examples/raha/synthetic-batch-v1.json --output-dir reports/private/sheikha-raha-review-new
```

حذف `--batch` يجري تدقيق الأدلة فقط. `--ecosystem` يحدد جذر الملفات القديمة المقروءة ولا يسمح بتشغيلها. رمز الخروج `0` يعني اكتمال المراجعة المحددة بلا عزل أو خطأ أدلة؛ `2` يعني خطأ أو سجلًا معزولًا أو تدقيقًا محجوبًا. في الحالتين يبقى الإنتاج معلقًا، ولا يوجد خيار لفك الحظر أو لإصدار اعتماد شرعي.
