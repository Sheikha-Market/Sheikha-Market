# رقمنة الأصول ومعمارية القدرات

## النطاق والنتيجة

استجابة لتصريح المالك بشراء الأصول، أضيف سجل توثيقي محلي للأصول الستة المذكورة في المرفقين. هذا ليس جردًا لجميع المشتريات، ولا إثباتًا بأن كل ملف برمجي مذكور أصل مشترى. تخصيص تصريح الشراء لكل أصل ما زال غير مؤكد.

في متابعة 2026-10-22، وبناءً على الرد «الافضل الكل»، توسع **نطاق الجرد والتوثيق المطلوب** ليشمل النطاقات والاستضافة والخدمات السحابية والبرمجيات وحزم التصميم والتراخيص والاشتراكات والمعدات والروبوتات وخطوط الإنتاج والبصريات والفيديو. الرد اختيار لشمول المراجعة، وليس قائمة مشتريات مفصلة أو دليلًا على شراء كل فئة.

التنفيذ المحلي المتاح: قراءة البطاقات، فحص ملفات محددة وبصماتها، فحص اتساق حزمة الموردين، تصفية الأصول، عرض المعمارية المقترحة وبوابات الجاهزية، وتنزيل ملف الرقمنة أو بطاقة أصل. يمكن حفظ لقطة خاصة صراحة من أداة الطرفية.
أضيفت خطة متطلبات مرتبطة بالأصول والقدرات والبوابات، مع التصفية وتتبع المتطلبات السابقة وتنزيل الخطة وتحديد الخطوة التالية لكل أصل.
أضيف لاحقًا [مختبر الموردين المحلي](SHEIKHA-SUPPLIER-LAB.md) من بطاقة حزمة الموردين: تنفيذ مستقل للقراءة ببيانات اصطناعية للعقود الثلاثة، لا تعديل للحزمة الأصلية ولا اعتماد تلقائي للأصول أو المتطلبات. حالات الحزمة الواردة أدناه تخص الملفات الأصلية المحفوظة، وليست إنكارًا لوجود نموذج المختبر المنفصل.
لا تشغيل للمصادر المرفقة، ولا فتح لقاعدة SQLite، ولا قراءة أسرار، ولا تعديل استضافة أو نطاقات أو DNS أو TLS أو خدمات نظام التشغيل. لم تُشغّل معدات أو تُنشر خدمة أو تُدفع رسوم.

مرجعية الكتاب والسنة والقيم الإسلامية مثبتة كمرجعية للمشروع، مع الصدق والأمانة والعدل وحفظ الحقوق وعدم الضرر. ليست نتيجة الفحص شهادة شرعية أو اعتمادًا هندسيًا أو قانونيًا؛ المسائل التطبيقية تُحال إلى مراجعة مؤهلة قبل تنفيذها.

## نطاق الجرد الشامل

الحقل الإضافي `inventoryScope` يسجل مصدر اختيار المستخدم ونصه وتاريخ استلامه `2026-10-22` بتوقيت `Asia/Riyadh`، والغرض `INVENTORY_AND_EVIDENCE_REVIEW`. حالته `FULL_SCOPE_REQUESTED_NOT_ITEMIZED`. تظل `inventoryComplete`, `itemizedPurchaseListProvided`, `purchaseEvidenceProvided`, `executionAuthorized` غير مفعلة.

| --- | --- | --- |
| النطاقات | `domain-core`, `domain-market` | التسجيل والحساب المسؤول والتجديد ودليل السيطرة |
| الاستضافة والخدمات السحابية | `hosting-service` | الخطة والموارد والمدة والتكلفة ومستند الاستحقاق |

| التراخيص والاشتراكات | لا قائمة تفصيلية في هذا السجل | المنتجات والمقاعد والمدة وحدود الحقوق ومستنداتها |
| المعدات والروبوتات وخطوط الإنتاج | لا قائمة تفصيلية في هذا السجل | الطرازات والكميات والموقع والمسؤول والاستلام والفحص والسلامة |
| البصريات والفيديو والتصاميم | لا بطاقات مشتريات مفصلة في هذا السجل | الأعمال والإصدارات والمنشئ وحدود الاستخدام والنشر |

غياب قائمة في فئة لا يعني عدم وجود أصول فيها، ولا ينفي البصريات المرفقة سابقًا. لم تُفهرس مكتبة البصريات أو تُفحص معدات في هذه المتابعة. السجلات الستة القائمة موزعة مرة واحدة على الفئات الثلاث الأولى، ولا تُنشأ بطاقة مشترى أو كمية أو رقم تسلسلي أو ترخيص من مجرد اختيار «الكل». تبقى كل فئة `purchaseVerified = false` و`productionEnabled = false`، ويبقى تخصيص تصريح الشراء لكل أصل غير مؤكد.

لكل فئة قائمتا بيانات جرد وأدلة مراجعة مطلوبة، دون بيانات دخول أو مفاتيح تفعيل أو محتوى مستندات خاصة. القسم «نطاق الجرد الشامل» داخل تبويب السجل يعرضها، ويُضمَّن النطاق في تنزيل ملف الرقمنة الكامل. بطاقة الأصل وخطة متطلباته لا تتغيران؛ عدد الأصول 6، والمصادر 11، والمتطلبات 66. التقارير القديمة دون الحقل الجديد تخفي القسم بدل اختلاق نطاق تاريخي، وفشل القراءة يمسح بياناته المعروضة.

## بطاقات الأصول

| المعرف | الأصل | دوره المقترح | الدليل الناقص الأهم |

| `domain-governance-source` | مصدر توثيق V42.8 | تعريف علاقات النطاقات | عقد تكامل محدد واختبار توجيه مستقل |

البطاقة تحتوي معرفًا ثابتًا ونوعًا ودورًا ومراجع أدلة واعتماديات وقدرات مقترحة واحتياجات مراجعة. جميعها `DIGITIZED_DRAFT`، وقدراتها `PROPOSED_NOT_ACTIVATED` وجاهزيتها `HOLD`.
لا تُسجل هذه البطاقات كأصول `OWNED` أو `ACTIVE` في سجل الملكية القائم. يُعاد استخدام دالة البصمة من `core/ownership/sheikha-owned-asset-registry.cjs` دون تغيير عقد ذلك السجل أو نقل ملكية برمجيات طرف ثالث.
الاسم البديل `www` ليس أصلًا مشتَرى إضافيًا في العد. أسماء الخدمة والمصادر البرمجية مأخوذة من سياق المرفق، ولا تحدد خطة شراء أو عدد خوادم أو عدد تراخيص.

فدرلة توثيقية مقترحة: بطاقات مستقلة وهوية موحدة وروابط اعتماد محددة؛ ليست اتحاد خدمات منشورًا أو نقلًا للصلاحيات بين البيئات.

```text

                                |
سجل الأصول والأدلة -> المتطلبات -> التصميم -> الاختبارات -> قرار تنفيذ مستقل

البوابات:             sheikha.top              sheikha.shop
                          |                       |
التطبيقات:                |                حزمة بوابة الموردين
                          |                       |
الاستضافة المقترحة:        +----- خدمة محددة ومراجعة -----+

V42.7 / V42.8: مصادر وصف تاريخية تحتاج مراجعة، لا طبقة تحكم مفعلة
```

الواجهة تعرض خمس طبقات: الحوكمة، البوابات، التطبيقات والعقود، التكامل المقترح، والاستضافة والبيانات. روابط `PLANNED_DEPENDENCY` تحمل `deployed = false` دائمًا.
لا عنوان مورد يختاره العميل، ولا تمرير أوامر طرفية أو SQL أو استيراد مصادر من هذا المخطط. لا تغيير في قائمة سماح MCP أو صلاحيات GPT/Codex، ولا انتقال موافقات بينهما.

## الإدارة والمنهجية

بوابات المراجعة الثماني موثقة داخل الملف والواجهة: الحصر، الحقوق، الهندسة، الأمن، التشغيل، الميزانية، القيم والأثر، والتفويض. لكل بوابة دور مسؤول ودليل مطلوب، لكن `assignedPerson = null`؛ لم يُعيّن أشخاص أو تُسجل موافقات نيابة عن المالك.

تسلسل العمل المقترح:
1. استكمال قائمة الأصول وأدلة الشراء المنقحة، وتعيين مسؤول لكل أصل.
2. ربط المتطلبات بالقدرات وبالأدلة والفجوات؛ لا تحويل تصريح إلى إثبات.
3. وضع فرضية اختبار وخط أساس ومتغيرات ومعيار قبول قبل تنفيذ الاختبار.
4. تنفيذ اختبارات محددة في بيئة منفصلة وحفظ الإصدار والنتيجة والأثر.
5. مراجعة المخاطر والحقوق والميزانية والقيم والتراجع ثم إصدار قرار منفصل.
6. مراقبة القياسات بعد تشغيل مأذون به، وتسجيل التحسينات كمقترحات واختبارات جديدة.

لا اختبار آلي يمنح فتوى أو يعلن استيعاب جميع العلوم أو الجاهزية الكاملة. إثبات حق استخدام أصل لا يعني أن كل قدرة متاحة تقنيًا أو مأذون باستخدامها.

## خطة المتطلبات والقبول

يبني `core/ownership/sheikha-asset-execution-plan-v1.cjs` خطة محلية من الحقول المنتقاة في تقرير الرقمنة، دون قراءة إضافية أو كتابة أو تنفيذ مصادر. يُضاف `executionPlan` إلى التقرير قبل حساب بصمته. تبقى النسخ التاريخية كما هي؛ الإضافة لا تعيد كتابة لقطة سابقة ولا تحولها إلى نسخة حديثة.

الخطة الحالية تغطي 6 أصول و11 قدرة و66 متطلبًا:

| الفئة | العدد | ما يتم تقييمه |
| --- | --- | --- |
| فحوص محلية | 7 | قراءة مصادر كل بطاقة ومقارنة البصمات المرجعية المتاحة، واتساق ملفات حزمة الموردين وأعلام توقفها |
| قبول القدرات | 11 | معايير تنفيذ واختبار محددة لكل قدرة، دون تشغيل تلك الاختبارات |
| مراجعات الحوكمة | 48 | ثماني بوابات لكل أصل، دون تعيين أشخاص أو تسجيل موافقات |

كل متطلب يحمل معرفًا ثابتًا، ومعرف الأصل والبوابة والقدرات، ومعايير قبول، وأدلة مطلوبة، ومراجع المصادر المرصودة وبصماتها، ودور المسؤول، ومتطلبات سابقة مقترحة، وخطوة تالية. لا تنسخ الخطة محتوى الأدلة أو الأسرار؛ وجود مرجع ملف لا يجعله دليل قبول موضوعيًا.

الحالات محددة ولا تحتوي حالة اعتماد إنتاج:

- `LOCAL_PASS`: نجاح فحص الملف المحلي المحدد فقط. غياب بصمة مرجعية لمصدر مقروء لا يصبح مقارنة ناجحة بمرجع مستقل؛ تبقى المقارنة غير متاحة في سجل المصادر.
- `LOCAL_FAIL`: نقص أو رفض قراءة أو اختلاف مرجعي أو عدم استيفاء اتساق الحزمة. تظهر مراجعة هذا الفحص أولًا في الخطوة التالية للأصل.
- `NOT_TESTED`: معيار قبول قدرة مقترح؛ لم يُنفذ اختبار قبولها هنا.
- `REVIEW_REQUIRED`: الدليل والقرار والمسؤول المسمى لم يُستكملوا، حتى عند نجاح جميع الفحوص المحلية.

عند استيفاء الفحوص المحلية تكون الخطوة التالية حصر نطاق الأصل وتسمية مسؤوله. متطلبات الهندسة مرتبطة بمتطلبات القدرات، والتفويض مرتبط ببوابات المراجعة السبع الأخرى. الرسم خالٍ من الدوران في الاختبارات، لكنه ترتيب مقترح وليس آلة تشغيل أو منح صلاحيات. اعتماديات الأصول المعمارية تبقى `PLANNED_DEPENDENCY` مستقلة عن ترتيب متطلبات المراجعة؛ لا يُدّعى استيفاؤها أو تنفيذها.
