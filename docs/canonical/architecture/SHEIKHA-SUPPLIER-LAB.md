# مختبر الموردين المحلي

## النطاق

نموذج برمجي محلي للقراءة فقط، ينفذ عقود القوائم الثلاثة الواردة في تصميم بوابة الموردين: الموردون والمواد والوثائق. ليس تفعيلًا لموردين حقيقيين أو استضافة أو صلاحيات شراء، وليس تنفيذًا كاملًا لحزمة إدارة الموردين. لا كتابة أو رفع مستندات أو إرسال طلبات أو توقيع عقود أو دفع أو تحكم بالأجهزة.

مصدر البيانات ثابت داخل `core/ownership/sheikha-supplier-lab-v1.cjs`: 6 موردين و9 مواد و8 سجلات وثائق اصطناعية، موسومة على مستوى الاستجابة والسجل والواجهة. المعرفات `SUP-SYN-*`, `MAT-SYN-*`, `DOC-SYN-*` ليست معرفات أصول حقيقية. لا أسماء أشخاص أو بيانات اتصال أو أرقام تراخيص أو فواتير أو أسعار أو مخزون تجاري. الوثائق بيانات وصفية بلا محتوى أو رابط تحميل أو مسار ملف.

التنفيذ داخل الذاكرة دون فتح قاعدة بيانات. ملف المعمارية الأصلي يقترح `sqlite_lab_only`؛ لم يُنفذ تخزين SQLite أو ترحيل بياناته هنا. بقيت الحزمة الأصلية تحت `/home/sheikha/sheikha-v43-1-lean-lab/supplier-portal-mvp/` وبياناتها المعلنة `NOT_IMPLEMENTED` منفصلة وغير معدلة. نجاح هذا النموذج لا يعيد كتابة أدلتها أو يمنحها قبولًا إنتاجيًا.

## العقود والحدود

تُركب المسارات في خادم المعاينة المحلي فقط، لا في `server.js` ولا SDK ولا MCP:

| المسار | العملية | مرجع المتطلب |
| --- | --- | --- |
| `GET /api/suppliers` | قائمة الموردين التجريبيين | `supplier-package--acceptance-1` |
| `GET /api/materials` | قائمة المواد التجريبية | `supplier-package--acceptance-2` |
| `GET /api/documents` | بيانات الوثائق التجريبية | `supplier-package--acceptance-3` |

المعاينة تستمع إلى loopback. الحواجز القائمة تتحقق من `Host` الدقيق والأصل و`Sec-Fetch-Site`، وتطلب المسارات الثلاثة رمز `X-Sheikha-Session` الصادر عن جلسة المعاينة. هذه حماية معاينة محلية، وليست هوية مستخدمين أو عزل مؤسسات أو صلاحيات إنتاج. يستطيع مستخدم محلي الوصول إلى جلسة المعاينة؛ لا يجوز وضع بيانات موردين حقيقية فيها قبل بناء المصادقة والتفويض المناسبين.

`HEAD` يتبع حماية `GET` ولا يعيد جسمًا. لا مسارات POST لهذه القوائم. تعديل وحذف السجلات غير متاحين. مسارات محتوى الوثائق والتنزيل والتفاصيل غير موجودة؛ تعرض الواجهة تفاصيل السجل الذي عاد من القائمة فقط.

المعاملات المقبولة:

| المعامل | القيد |
| --- | --- |
| `q` | حتى 80 وحدة UTF-16؛ بحث حرفي بعد تشذيب الأطراف وتوحيد NFC في الاسم والمعرفات، مع رفض محارف التحكم وتوجيه النص |
| `limit` | عدد صحيح عشري 1 إلى 25، الافتراضي 5 |
| `offset` | عدد صحيح عشري 0 إلى 1000، الافتراضي 0 |
| `category` | للموردين والمواد: `METALS`, `ENERGY`, `AUTOMATION`, `RECYCLING` |
| `kind` | للوثائق فقط: `SPECIFICATION`, `TEST_RECORD`, `LICENSE_SAMPLE` |
| `supplierId` | للمواد والوثائق فقط، بالشكل `SUP-SYN-000` بثلاث خانات عشرية |

لا حقول إضافية أو مكررة أو قيم متداخلة أو مصفوفات. يُحلل نص الاستعلام الخام باستخدام `URLSearchParams` كي لا يخفي محلل Express حقولًا مرفوضة مثل `__proto__`. حد الاستعلام 1024 بايت في النص الخام وبعد إعادة ترميزه. القيم الكسرية والسالبة والصيغ العلمية والأصفار البادئة مرفوضة. معرف مورد صحيح الشكل وغير موجود يعطي قائمة خالية، لا وصولًا إلى مصدر بيانات آخر. `path`, `url`, `source`, وأعلام الموافقة مرفوضة؛ البحث عن نص يشبه مسارًا لا يقرأ الملف.

الاستجابة `SUPPLIER_LAB_PAGE` بإصدار 1 تتضمن العقد ومرجع متطلبه، ومعرف مجموعة البيانات `SHEIKHA_SUPPLIER_SYNTHETIC_V1`، والمرشحات المطبقة، والسجلات وبيانات الصفحات والسياسة وبصمة JSON معيارية. الترتيب ثابت حسب المعرف. الاستجابات كائنات مستقلة؛ تعديلها في المستهلك لا يغيّر البيانات الأصلية. الوحدات `kg`, `piece`, `m` صريحة، والعلاقات بين المورد والمادة والوثيقة متسقة في الاختبارات.

`syntheticData = true`، وتبقى `realSupplierData`, `productionEnabled`, `mutationEnabled`, `externalCallsMade`, `purchaseVerified`, `databaseOpened`, `documentContentExposed`, `sourcePackageModified` على `false`. هذه حدود النموذج وليست نتائج فحص خارجي. البصمة تكشف اختلاف المحتوى ولا تمثل توقيعًا أو إثبات ملكية أو اعتمادًا. الواجهة لا تتحقق تشفيريًا من البصمة؛ الاختبارات تتحقق من تركيب الاستجابة والبصمة.

## الواجهة

`/workspace/supplier-lab.html`، مرتبطة من بطاقة حزمة الموردين داخل سجل الأصول. ثلاثة تبويبات، وبحث ومرشحات وعداد صفحات وتنقل سابق وتالٍ. تعرض تفاصيل السجل القطاع والوحدة والعلاقات وحدود الوثيقة، مع انتقال من المورد إلى مواده ووثائقه والعودة إلى سجله.

التنزيل يقتصر على JSON **للصفحة الحالية** بمرشحاتها وسياسة البيانات الاصطناعية؛ ليس تصديرًا لجميع النتائج ولا تنزيل محتوى الوثائق. تغيير التبويب أو المرشح يعيد التصفح إلى البداية. أثناء القراءة تُمنع الطلبات المتداخلة والتنزيل. عند الفشل تمسح السجلات والتفاصيل القابلة للتنزيل، وتبقى إعادة المحاولة متاحة. تُعاد جلسة المعاينة مرة واحدة عند رفض رمزها لتسمح بالتعافي من إعادة تشغيل الخادم.

لا رفع أو اتصال بجهة خارجية ولا تخزين خلفي أو جدولة. حواجز الطلبات وأدوات المعاينة الأخرى لم تُوسع. إتاحة الصفحة من خادم قديم دون تركيب المسارات تظهر فشل القراءة ولا بيانات نجاح بديلة.

هذه أدلة اختبار نموذج اصطناعي محدد، لا إغلاق آلي لمتطلبات الأصول الـ66 ولا إعلان نجاح كل اختبارات المشروع. لا تزال مراجعة الحقوق والأمن متعدد المستخدمين والتخزين والاسترجاع والمراقبة والتفويض خارج نطاق هذا النموذج. قيم الكتاب والسنة مرجعية المشروع، وليست شهادة امتثال شرعي آلية.
