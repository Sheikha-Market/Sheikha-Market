SHEIKHA Global Runtime Platform · SHEIKHA UGIT-RP · 17 أكتوبر 2026

الحالة: `READ_ONLY_VERIFIER_IMPLEMENTED_OPERATIONAL_REPAIRS_OPEN`. أُنجز فاحص قرائي مستقل وعقد بيانات مقترح وخطة قبول تربط المراجعتين السابقتين. لم تُنفذ إصلاحات التشغيل أو هجرة البيانات. المرجع: [Root Source of Truth](../../ROOT-SOURCE-OF-TRUTH.md).

## نتيجة التحقق الفعلي

أعاد الفاحص `EVIDENCE_UNSAFE_OR_MISMATCH` ورمز خروج `1`: طابقت **9 ملفات من أصل 11** لقطة المراجعة السابقة. اختلفت بصمتا ملف قاعدة SQLite وسجل الأدلة V2. بقيت المانيفستات الأربعة والمصادر الأربعة وسكربت V35.9 مطابقة في هذه القراءة. السبب ومصدر التغييرات غير مثبتين بهذا الفحص.

لم تُحدّث القيم المرجعية لجعل الفحص ناجحًا. نتيجة الفشل محفوظة كما صدرت؛ أي تسوية لاحقة تحتاج تفسيرًا وأدلة محددة، مع حفظ اللقطة السابقة. لا يدل الاختلاف وحده على تلف أو تلاعب، ولا يثبت توقيت تشغيل سابق.

الخطوة الأولى في خطة القبول هي تحديد مصدر التغييرات بقراءة مستقلة. لا تتضمن هذه الحزمة إيقاف أي كاتب أو خدمة أو إعادة تشغيل مرحلة تاريخية.

## حدود الفاحص

- يعتمد قائمة أسماء ثابتة للملفات الـ11، ويتحقق من تطابق مسارات baseline مع تلك القائمة. لا يستورد مصادر V35 أو يشغلها.
- يرفض JSON بمفاتيح مكررة أو أرقام غير منتهية أو بصمات غير صالحة أو إصدارات ناقصة ومكررة.
- يفتح المجلدات والملفات بواصفات و`O_NOFOLLOW`، ويرفض الروابط الرمزية والملفات غير العادية. الحد الأعلى للملف الواحد 256 MiB ولـbaseline مقدار 2 MiB.
- يتحقق من هوية الملف وحجمه وأوقات تغييره قبل القراءة وبعدها، ثم يعيد فحص الهوية في نهاية الجولة. هذا استقرار مرصود، وليس ضمان لقطة ذرية مشتركة بين الملفات.
- يرفض وجود `-wal` أو `-shm` أو `-journal`، ولو فارغًا أو رابطًا مكسورًا، قبل الجولة وبعدها. يقرأ DB كبايتات فقط؛ لا يفتح وصلة SQLite ولا يدعي فحص سلامتها المنطقية.
- لا يكتب ملفات أو logs ولا يستخدم الشبكة أو أوامر فرعية. التشغيل الموثق يستخدم `-B` لتعطيل إنشاء bytecode.
- يُخرج بصمة baseline نفسه، لكن تلك البصمة لا تثبت أصالته. النجاح `BASELINE_HASHES_MATCH` يعني مطابقة البايتات فقط؛ تبقى فجوات القدرات التسع `OPEN_NOT_EVALUATED` و`claimClosurePerformed:false`.

رموز الخروج: `0` لمطابقة الملفات الـ11، و`1` لعدم المطابقة أو حالة غير آمنة في الأدلة، و`2` لخلل baseline أو تعذر قراءته والتحقق من عقده. لا يمنح نجاحًا لجولة جزئية.

## عقد الكيانات والمواد والإصدارات

يفصل العقد بين `entities` و`jurisdictions` و`sources` و`instruments` و`articles` و`article_versions` و`assessments` و`assets`. جهة إصدار اللائحة تُحدد في `issuer_entity_id`؛ لا يُستنتج من ذلك انطباقها على كل نشاط للكيان.

معرّفات `urn:sheikha:*` والأرقام التسلسلية الداخلية معرّفات فهرسة. أرقام التسجيل الرسمية محفوظة في حقول منفصلة تتضمن الجهة المصدرة والولاية ومصدر الإثبات وحالة التحقق. وجود رقم مكتوب لا يثبت تسجيل جهة أو جامعة أو وقف أو شركة.

لكل مادة معرّف مستقل، ولكل إصدار نص ومصدر وموضع في المصدر وتواريخ وحالة تحقق للتاريخ، مع رابط إلى الإصدار السابق عند وجوده. هذا يمنح العقد القدرة على تمثيل عدة مواد وإصدارات للكيان نفسه. لا يغير جدول V35.7 الحالي ولا يطبق SQL أو migration.

تقييم `LEGAL_APPLICABILITY` مستقل عن `SHARIAH_REVIEW` ومرتبط بإصدار محدد. الحالة `QUALIFIED_REVIEW_RECORDED` تتطلب بيانات مراجع بشري ووقتًا واستنتاجًا معللًا ودليل مراجعة؛ المراجعة الشرعية المسجلة تحتاج مراجعها أيضًا. تحقق شكل هذه الحقول لا يصادق على هوية المراجع أو أهليته، ولا يلغي قانونًا أو يصدر فتوى.

يفصل سجل الأصل بين رقمه الداخلي والمعرفات الخارجية والبصمة المقيسة ودليل الملف وقياس الجودة ووحدته وطريقته. لا ينشئ درجات `AAA` من غياب القياس.

**قواعد العلاقات بين السجلات ما زالت غير منفذة:** تفرد المعرفات عبر المجموعات، وصحة المراجع، وتسلسل الإصدارات، وترتيب التواريخ، وانطباق اللوائح والتحفظات، والتحقق المستقل من المصدر والمراجع. هذه القواعد موصوفة في `x-cross-record-rules` وتدخل في معايير القبول اللاحقة. لا يكفي اجتياز JSON Schema لإثباتها.

## التحقق الذي أُنجز

نجحت الاختبارات المعزولة الستة عشر للفاحص، ومنها تغير البايتات، وفقد ملف، والروابط الرمزية للملف والمجلد، وملفات SQLite الجانبية، والمسار الخارج عن القائمة، وbaseline غير الصالح، والمسارات غير القابلة للترميز أو المحتوية على NUL، وتغير ملف بعد قراءته.

اجتاز العقد فحص Draft-07 واختبارًا مصطنعًا يمثل كيانًا واحدًا ولائحتين وأربع مواد وثمانية إصدارات في الذاكرة. اجتازت اختبارات العقد التسعة حالات الرفض واشتراط أدلة المراجعة وفصل نوعي التقييم. لا يثبت هذا حفظًا في قاعدة دائمة أو اكتمال قواعد العلاقات المذكورة أعلاه. لم تُثبت أو تُرقّ مكتبات؛ استُخدمت مكتبة `jsonschema` الموجودة محليًا للتحقق من العقد فقط.


لمراجعة السلوك ببيانات مصطنعة:

```bash

python3 -I -B docs/canonical/registry/reviews/2026-10-17-v35-completion/test_catalog_contract.py
```

لا يحتاج الفاحص ولا اختباراته إلى مكتبات خارج Python القياسي. اختبار العقد يحتاج مكتبة `jsonschema` المثبتة في بيئة المراجعة. خيارات `--baseline` و`--ecosystem-root` و`--master-script` مخصصة لتحديد لقطة وجذور قراءة صريحة؛ لا تمنح تنفيذًا أو كتابة إلى تلك الجذور.

لفحص سلامة هذه الحزمة فقط، من داخل مجلدها: `sha256sum --check SHA256SUMS`.
