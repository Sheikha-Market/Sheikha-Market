# شيخة: أسرار الخدمات دون جلسة مستخدم

## القرار والحالة

طلب المستخدم تشغيلًا دون جلسة مستخدم، لذلك لم تُنقل مفاتيح الموصلات إلى مخزن أسرار سطح المكتب. لا يتم نسخ المفاتيح بين بيئتي GPT وCodex أو إعادة استخدام الموافقات بينهما.

| البند | الحالة المرصودة |
| --- | --- |
| systemd | النسخة المحلية 249 |
| استمرار مدير خدمات المستخدم | `Linger=yes` موجود مسبقًا، دون تعديله |
| `systemd-creds` | غير موجود؛ لم تُحدّث حزم النظام |
| تمرير سر اصطناعي عبر `LoadCredential` | مختبر فعليًا بخدمة مؤقتة |
| مراقب الحوكمة للقراءة فقط | مفعّل كل 15 دقيقة؛ نجح أول تنفيذ |
| نقل أو تدوير مفاتيح حقيقية | لم ينفذ |
| ربط إنتاجي لموصل بمصدر أسرار خدمات | لم ينفذ |
| تسجيل خروج فعلي أو إعادة تشغيل الجهاز | لم يختبر |
| اتصال ChatGPT السحابي | غير متحقق |

وفق [توثيق systemd 249](https://www.freedesktop.org/software/systemd/man/249/systemd.exec.html#Credentials)، يمرر `LoadCredential` بيانات إلى مجلد خاص بالخدمة، ويعرّف مساره عبر `CREDENTIALS_DIRECTORY`. هذا ليس تشفيرًا تلقائيًا لملف المصدر على القرص. لا تستخدم `SetCredential` أو `Environment` لوضع قيمة مفتاح داخل تعريف الخدمة.

## القارئ المحلي

`tools/environment/sheikha_service_credentials.py` يوفر `read_credential()`:

- يقبل المعرّفين `hostinger_api_token` و`sheikha_probe` فقط.
- يقرأ من `CREDENTIALS_DIRECTORY`، بلا رجوع إلى متغير مفتاح موروث أو ملف Codex أو مخزن سطح المكتب.
- يرفض المسارات النسبية، والروابط الرمزية النهائية، والملفات الخاصة والروابط الصلبة، والمجلدات والملفات المتاحة للمجموعة أو الآخرين.
- يشترط مالكًا هو مستخدم الخدمة الحالي أو root، ويحد القراءة بـ 8 KiB ويتحقق من عدم تغير الملف أثناء القراءة.
- لا يطبع القيمة ولا يشغّل موصلًا. أخطاؤه رموز ثابتة دون مسارات أو محتوى حساس.

هذا قارئ ضمن العملية، وليس عزلًا عن مستخدم نظام التشغيل نفسه أو تطبيق يملك تعديل الشيفرة. لا يحمي سرًا يعيد المستهلك تسجيله أو نشره، ولا يثبت هوية الموصل. ربطه بأي عامل إنتاج يتطلب مراجعة مسار المستهلك أيضًا.

## الاختبار الآمن

```bash
python3 -B tools/environment/sheikha-headless-credential-check.py --systemd
python3 -B -m unittest discover -s tests -p test_sheikha_service_credentials.py -v
```

الاختبار الأول ينشئ ملفًا خاصًا يحوي قيمة اصطناعية معلنة فقط، ويمرره إلى خدمة مؤقتة ذات اسم فريد. يحذف متغيرات سطح المكتب من بيئة الخدمة، ويمنع عائلات عناوين الشبكة سوى AF_UNIX، ويقارن القيمة دون إظهارها. يجمع الخدمة المنتهية وينظف الملف المؤقت. في المهلة يطلب إيقاف وحدة الاختبار المحددة فقط. لا يختبر مفاتيح مزود حقيقية أو يثبت خدمة إنتاج دائمة.

اختبار `--self-test` مخصص للاستدعاء داخل البيئة التي تتلقى السر الاصطناعي؛ غياب الدليل أو عدم تطابق القيمة يفشل، ولا يتحول إلى قراءة مفتاح الإنتاج.

`tools/environment/sheikha-secret-store-check.py` فاحص مستقل لحالة مخزن سطح المكتب، وليس مسار التشغيل المعتمد. يستعلم فقط عن وجود خدمة D-Bus وحالة القفل، دون سرد العناصر أو فتحها أو إنشاء مخزن. حالة `READY_FOR_MIGRATION_REVIEW` لا تعني دعم التشغيل بلا جلسة مستخدم.

## الربط الإنتاجي المتبقي

ينبغي أن يملك كل نطاق تشغيل مصدره المستقل دون نسخ تلقائي من بيئة أخرى. في systemd 249 يمكن أن يكون المصدر ملفًا خاصًا لا يقرأه إلا حساب مدير الخدمة، مع مجلد `0700` وملف `0600` أو `0400`، خارج Git والمرفقات والسجلات. يحمي ذلك الوصول المحلي ولا يشفر المصدر على القرص؛ لا يُوصف بأنه خزنة مشفرة.

مثال ربط لمصدر محلي لم يتم إنشاؤه أو تفعيله:

```ini
[Service]
LoadCredential=hostinger_api_token:%h/.local/share/sheikha/service-credentials/runtime-a/hostinger_api_token
UnsetEnvironment=HOSTINGER_API_TOKEN DBUS_SESSION_BUS_ADDRESS DISPLAY WAYLAND_DISPLAY
```

لا يحتوي المثال على `ExecStart` عمدًا؛ لا يوجد موصل أو عامل إنتاج معتمد ضمن هذا الاختبار. قبل نقل المفاتيح يلزم تحديد الخدمة المستهلكة وحسابها ومصدر السر، ثم التحقق من تحميلها بلا عرض القيمة وإزالة الربط المضمن بعد نجاح الاختبار فقط. إذا كان المزود لا يقبل إلا متغير بيئة، تُراجع آلية تمريره داخل عملية المستهلك وآثار تسربه إلى العمليات الفرعية؛ لا يوضع المفتاح في وحدة systemd.

مراقب الحوكمة المفعّل لا يحتاج هذا الربط ولا ينفّذ طلبات مزودين. إعداد الخدمات للاستمرار لا يعني تفعيل توليد مدفوع أو نشر أو تشغيل أجهزة. تعطل مصدر السر يجب أن يوقف العمل المتأثر، دون استخدام سر بيئة أخرى أو العودة الصامتة إلى إعداد قديم.
