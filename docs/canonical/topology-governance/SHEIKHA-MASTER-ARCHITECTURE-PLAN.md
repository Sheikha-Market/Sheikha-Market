## الحالة والنطاق

بتاريخ 2026-10-22: تنفيذ محلي للمخطط المطلوب، وليس سجل ملكية أو نشرًا حيًا. المصدر الوحيد لتعريف هذه الخطة هو `config/sheikha-master-architecture-topology-v1.json`، بحالة `DESIRED_LOCAL_ARCHITECTURE`. هذا المرجع يشرح الخطة ولا يستبدل سياسة المسارات V2 أو سجل المجالات المنطقية والمحركات V3.

تسري [حوكمة المخططات](SHEIKHA-TOPOLOGY-GOVERNANCE.md) و[حوكمة المساعدين](../environment/SHEIKHA-ASSISTANT-GOVERNANCE.md). وصف خدمة مالية أو كلمة «سيادي» في تسمية يحددان مقصد المستخدم، ولا يثبتان صفة رسمية أو ترخيصًا أو تفويضًا ماليًا. قيم الكتاب والسنة مرجعية للمشروع وليست شهادة امتثال شرعي آلية.

## المعمارية المحلية

```text
config/sheikha-master-architecture-topology-v1.json
    -> core/site-registry/sheikha-master-architecture-topology-v1.cjs
        -> tools/site/sheikha-master-architecture-check.cjs
        -> routes/site-registry/sheikha-master-architecture-topology-routes-v1.cjs
            -> existing V3 router at /api/site-registry/v3/architecture
```

المدقق يرفض الحقول غير المتوقعة، والتكرار، والمراجع المفقودة، والتحويل إلى نطاق خارج السجل، وسلاسل التحويل وحلقاته. وجهات التحويل HTTPS ثابتة بلا بيانات اعتماد أو منفذ أو query أو fragment. سياسة التحويل المخططة تخص `GET` و`HEAD` فقط، وتسقط المسار الوارد ومعاملاته لصالح الوجهة المحددة؛ لا تنقل طلبات الكتابة أو رموز الدخول. تنفيذ تحويل HTTP، بخلاف سجل DNS، يحتاج طبقة خدمة منفصلة بعد المراجعة.

تستخدم وحدة الحالة سجلي التكامل المحلي والمسارات الحاليين للقراءة فقط. تسجيل مستودع لا يثبت الوصول إليه، وإعلان مسار لا يثبت مصادقته أو صلاحيته الحية. بصمة `topologySha256` محسوبة من `JSON.stringify` للكائن المحلل، وليست بصمة بايتات الملف أو توقيعًا موثوقًا. تغيير الترتيب قد يغير البصمة.

## واجهات القراءة

| المسار النسبي إلى `/api/site-registry/v3/architecture` | الوظيفة |
| --- | --- |
| `GET /topology` | الخطة المحققة مع `mode: PLAN_ONLY` |
| `GET /status` | الإحصاءات والفجوات وحدود الأدلة |
| `GET /resolve?hostname=sheikha.me` | وجهة مخططة مع `applied: false`، دون HTTP redirect |

الاستجابات `Cache-Control: no-store`. مدخل hostname غير صالح أو query إضافي: `400`؛ نطاق صحيح الصياغة غير مسجل: `404`؛ تعذر القراءة أو بطلان الإعداد: `503` برسالة منقحة. يقبل المحلل أحرف hostname الكبيرة بتحويلها إلى صغيرة، ولا يقبل URL كاملًا أو منفذًا أو مسافة أو قائمة قيم. لا يعتمد على `Host` أو `X-Forwarded-Host` لتحديد الوجهة المطلوبة؛ تبقى سياسة المضيف السابقة أمامه دون تعديل.

لا توجد واجهات كتابة أو تفعيل هنا. القيم `productionReady` و`financialOperationsAuthorized` و`performsExternalActions` و`redirectsInstalledByThisModule` تبقى `false`، حتى عند اكتمال التصريحات المحلية. قد يحوّل middleware السابق `www.sheikha.top` إلى النطاق الأساسي بـ`308` في وضع الإنتاج؛ هذا سلوك سابق وليس تفعيلًا لتحويلات هذه الخطة.

## متطلبات النشر غير المحققة

كشف الفحص المحلي في 2026-10-22 ما يلي:

- `sheikha-main-portal` مسجل في `config/sheikha-repository-integrations-v1.json`؛ المستودعات الثلاثة الأخرى غير مسجلة فيه. هذا لا يثبت غيابها عن خدمة بعيدة أو عن مسارات أخرى.
- `/profile` غير معلن في سجلي المسارات المفحوصين؛ لم تُنشأ صفحة هوية أو يُتجاوز تسجيل الدخول لإزالة التحذير.
- لم تُتحقق ملكية النطاقات أو صلاحيات المستودعات أو DNS أو TLS أو أي نشر حي.

قبل النشر: تحقق الملكية والوصول، وتحديد خدمة فعلية لكل hostname، ومراجعة مصادقة وجهات الهوية، وجرد DNS وسجلات البريد دون استبدالها جماعيًا، وتوفير TLS، ثم اختبارات staging وموافقة بشرية على التغيير المحدد وخطة الرجوع. اشتراك ثلاثة نطاقات في المستودع الرئيسي لا يجعل واجهاتها مختلفة تلقائيًا؛ إعداد توجيه المضيفين ما زال مطلوبًا.

لم تُسجل عناوين مستودعات تخمينية، ولم تُعدّل سجلات DNS أو MX أو إعدادات الاستضافة أو حسابات الخدمات. لا عمليات دفع أو نشر أو تشغيل أجهزة. الخدمات القائمة وتغييرات المستخدم خارج نطاق هذه الملفات محفوظة.

خروج المدقق بصفر يعني نجاح القراءة وصحة الخطة واتساقها مع خطة الاستضافة الهجينة فقط؛ يجب قراءة `findings` و`evidence` و`execution`. يخرج برمز `1` عند تعارض الخطتين. ليست هذه أداة قبول نشر. اختبارات HTTP تستخدم خادم Express محليًا مؤقتًا، ولا تثبت تشغيل `server.js` كاملًا أو وجود خدمة عامة. الاختبارات تشمل مطابقة الطلب، والتحويلات غير الآمنة، وفشل القراءة، وعدم تغيير السجلات الحالية، والتعايش مع middleware التحويل السابق.

نتيجة التحقق المحلي في 2026-10-22: نجحت 42 حالة في المجموعات الثلاث المحددة، دون إخفاق أو تخطٍّ. نجحت فحوص الصياغة للملفات الخمسة JavaScript، وتحليل JSON، وفحص المسافات ونهايات الأسطر للملفات السبعة المتأثرة. ليست هذه نتيجة لجميع اختبارات المشروع. بصمة الخطة عند التحقق: `ea4c728838dd25e6b6fb4d50449eb38ee053bb39c5ece5cf54323ea05fb6f3e3`. بقيت الفجوات المحلية الأربع المذكورة أعلاه؛ لم تُعتبر الاختبارات دليل نشر.

## متابعة الاتساق في 2026-10-23

أعيدت مطابقة الخريطة التي أكدها المستخدم مع الملفين الحاليين؛ بقي توزيع النطاقات والمستودعات ووجهات التحويل دون تغيير، وبقيت بصمة الخطة السابقة نفسها. أضيف `checkHybridAlignment` إلى وحدة المخطط الموجودة، دون إنشاء شجرة topology أخرى أو تشغيل أي موصل خارجي.

يفحص المدقق `config/cloud/sheikha-hybrid-domain-plan-v1.json` بمحلله الحالي أولًا، ثم يقارن مجموعة النطاقات وأنواعها، وربط مستودعات الخدمات، ووجهات التحويل، ومجموعة المستودعات. اختلاف ترتيب الصفوف لا يعد تعارضًا. الحالة الجديدة `hybridArchitecture` تظهر في واجهة القراءة `/status` وفي أداة الطرفية. التعارض يعيد `alignmentValid: false` و`LOCAL_PLAN_CONFLICT_DEPLOYMENT_NOT_VERIFIED` مع رموز محددة، ولا يغيّر أي ملف تلقائيًا.

الخطة الهجينة المتسقة تستهدف الدمام `me-central2` وDNS لدى `HOSTINGER` في وضع `HYBRID`؛ تبقى هذه إعدادات مرغوبة لا أدلة تشغيل. تغيير المنطقة أو جهة DNS أو إزالة `productionHold` أو الخلط بين `sheikha.dev` و`dev.sheikha.top` يفشل التحقق. لا يُفعّل مرشح fallback ولا يتغير مستودع أي نطاق بسبب غياب تسجيله المحلي.

لا تزال الفجوات المحلية الأربع قائمة: ثلاثة مستودعات غير مسجلة محليًا ووجهة `/profile` غير معلنة. تفاصيل عوائق النشر التي رُصدت في الجولة السابقة محفوظة في [تقرير إصلاح البناء](../environment/SHEIKHA-CLEAN-BUILD-RECOVERY.md)؛ لم تُعد استعلامات السحابة أو Hostinger في متابعة الاتساق هذه.

نتيجة متابعة الاتساق: نجحت 56 حالة Jest في المجموعات الثلاث المذكورة، و10 حالات في `tests/sheikha-hybrid-domain-plan-v1.test.cjs`، بمجموع 66 دون إخفاق أو تخطٍّ. أعاد المدقق `alignmentValid: true` بلا تعارض، مع إبقاء `productionReady: false`. شملت الإضافات اختلاف المستودع والوجهة ونوع النطاق، النطاقات الناقصة والزائدة، الإعداد الهجين غير الصالح، وعدم تعديل المدخلات، ورمز خروج الطرفية عند التعارض.
