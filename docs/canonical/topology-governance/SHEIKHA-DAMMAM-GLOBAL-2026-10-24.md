# شيخة: الدمام والتوزيع الدولي

التاريخ: 2026-10-24، بتوقيت السعودية. الحالة: تجهيز محلي مختبر، وليس نشرًا حيًا.

## النطاق

تنفيذ توجيه المستخدم بأن تكون الدمام الأساس داخل السعودية، مع توسع متعدد الخوادم دوليًا. المرجع القيمي الكتاب والسنة وفق حوكمة المشروع؛ ليس هذا اعتمادًا شرعيًا أو شهادة امتثال تقني آلية. لم تُعدّل خدمة قائمة أو DNS أو IAM أو فوترة، ولم يُنقل محتوى إلى مزود خارجي.

الخطة الجديدة `config/cloud/sheikha-regional-topology-v1.json` مكملة لخريطة النطاقات الاثني عشر `config/cloud/sheikha-hybrid-domain-plan-v1.json`. لا تستبدل ربط المستودعات، ولا تفعّل مرشحات fallback. المدقق يرفض تعارض المنطقة وجهة DNS أو إزالة القيود.

## المعمارية المستهدفة

```text
Hostinger DNS (existing authority; no changes made)
  |
  +-- Saudi core: Google Cloud / Dammam / me-central2
  |     +-- Portal and private APIs: authenticated, separately reviewed ingress
  |     +-- Shared state, locks, sessions, queues: Saudi external store required
  |     +-- Registry, source artifacts, logs, secrets and backups: verify location
  |     +-- Single scheduler; idempotent workers; no per-replica duplicate jobs
  |
  +-- International public asset plane (proposed, disabled)
  |     +-- Europe: europe-west1
  |     +-- Asia: asia-southeast1
  |     +-- Americas: us-east1
  |     +-- Optional Hostinger edge: location and contract unverified
  |
  +-- Independent Saudi disaster-recovery site: not selected or provisioned
```

العقد الدولية مرشحة وليست خدمات عاملة أو مناطق اختارها المستخدم تفصيليًا. تبدأ بمرئيات وملفات عامة معتمدة للنشر فقط، ضمن منتج منفصل لا يحمل مفاتيح المنصة أو واجهات الإدارة أو بيانات الأشخاص والمعاملات. لا يجوز نسخ كامل مجلد `public` أو الحاوية الحالية تلقائيًا؛ يلزم بيان تصدير عام مراجع. السجلات ومعرّفات الزوار في الطرف الدولي تحتاج مراجعة مستقلة أيضًا.

المستخدمون في العالم يستطيعون الوصول إلى الخدمة السعودية دون أن يعني ذلك نسخ قاعدة البيانات في بلدانهم. تعطل الموقع السعودي لا يجيز تحويل الطلبات الخاصة إلى عقد أجنبية تلقائيًا. الحد المقترح للبوابة ثلاث نسخ و`minInstances=0`، لا ثلاثة خوادم قائمة ولا ضمان توافر أو سقف تكلفة. الإنفاق على الطلبات والشبكة والتخزين وموازن الحمل يُراجع منفصلًا.

Cloud Run خدمة إقليمية؛ التوزيع الدولي يتطلب خدمات إقليمية وموازن حمل مناسبًا، ويحتاج التعافي اختبار صحة وتحويل فعليًا، لا مجرد DNS. [توثيق تعدد المناطق](https://docs.cloud.google.com/run/docs/multiple-regions). للخدمات الخاصة، تُراجع حدود إنهاء TLS ومعالجة السجلات والشبكة؛ عبارة «البيانات سعودية» في الإعداد ليست إثبات إقامة كل المعالجة.

حالة العقول الحالية وملفات التشغيل المحلية ليست مخزنًا موزعًا. لا توضع ملفات الحالة أو الأقفال على GCS Fuse بوصفه بديل قاعدة بيانات مشتركة. يلزم مخزن سعودي مناسب واختبار التزامن والاستعادة قبل زيادة النسخ. لم يُنفذ تحويل مخزن الحالة في هذه المهمة.

## التشخيص المرصود

استعلامات قراءة فقط للمشروع `sheikha-marketplace`، دون قيم متغيرات البيئة أو الأسرار:

| العنصر | النتيجة |
| --- | --- |
| المراجعة الأمريكية | `sheikha-main-portal-00029-5ct`، `Ready=False` |
| منفذ الحاوية | `8080` مضبوط بالفعل |
| السبب قبل تشغيل Node | فشل تركيب `llama-models` عند `/app/models` |
| سجل التخزين | `NotFound` للحاوية `sheikha-marketplace-models` عند الإقلاع بتاريخ 2026-10-23 20:09:22 UTC |
| تحقق التخزين المباشر اللاحق | انتهت مهلة الاستعلام؛ لا يثبت عدم وجود الحاوية الآن |
| الوصول إلى الدمام | `PERMISSION_DENIED` مع `LOCATION_POLICY_VIOLATED` ورسالة طلب التواصل مع المبيعات |
| IAM المباشر للخدمة | ربط invoker بعضوين، دون `allUsers` أو `allAuthenticatedUsers` |
| آخر مراجعة جاهزة في السجل | `00014-h2n`؛ لم يُثبت نجاح فحصها الصحي الحالي |

خطأ فحص المنفذ نتيجة لاحقة لتعطل التركيب؛ لا يبرر تغيير المنفذ أو تخفيف فحص الأسرار. كذلك 403 للوصول غير المصادق لا يعالج بإصلاح Docker وحده، ولا يجيز فتح واجهات الإدارة للعامة. الربط المباشر لـ IAM ليس تحليلًا كاملًا للأذونات الموروثة أو سياسات الشبكة.

اللقطة المنقحة محفوظة في `runtime/cloud-build-recovery-verification/2026-10-24-cloud-run-regional-snapshot.json`. أُبدلت هوية عضوي IAM بمعرّفين منقحين، وحُذفت متغيرات البيئة. نتيجة `NOT_FOUND_AT_STARTUP` تاريخية من سجل التركيب، وليست ادعاء فحص تخزين حي ناجح. لا تمنح هذه اللقطة إذن نشر ولا تثبت الحالة في وقت لاحق.

وفق [شروط الوصول إلى الدمام من Google](https://docs.cloud.google.com/docs/dammam-region-access)، العملاء ذوو عنوان فوترة سعودي يحتاجون الشراء عبر CNTXT، والعملاء خارج السعودية يحتاجون فوترة بالفاتورة للوصول إلى المنطقة. لم يُفحص عنوان فوترة الحساب أو وضعه التعاقدي؛ الخطأ المرصود وحده لا يحدد سبب عدم الأهلية بدقة. لا تُغيّر سياسة المؤسسة أو عنوان الفوترة لتجاوز القيد.

## إصلاح مسار البناء

عدّلت `cloudbuild.yaml` ليستهدف `me-central2-docker.pkg.dev` ويستخدم `$BUILD_ID` بدل اعتماد وسم مبني على متغير commit قد يكون فارغًا. أزيل دفع الوسمين المكرر؛ حقل `images` يتولى رفع الناتج عند نجاح البناء. أضيف فحص أول يرفض المنطقة المخالفة والسياق المفقود أو المختلف عن البصمات. `$LOCATION` متغير Cloud Build الموثق لمنطقة البناء. [مرجع المتغيرات](https://docs.cloud.google.com/build/docs/configuring-builds/substitute-variable-values).

هذا التغيير لا يشغّل بناءً ولا ينقل مستودع Artifact Registry الأمريكي، ولا ينشئ مستودعًا سعوديًا. أي triggers تستخدم المصدر الخام بدل السياق المرحلي ستُرفض حتى يُعدّل مسارها بمراجعة. فاحص الخادم يعمل بعد وصول المصدر إلى Cloud Build، فلا يمنع وحده رفع 6.1 GiB؛ فحص السياق المحلي قبل الرفع ضروري.

أوامر محلية فقط:

```bash
node tools/runtime/sheikha-regional-preflight.cjs plan
node tools/runtime/sheikha-regional-preflight.cjs assess < runtime/cloud-build-recovery-verification/2026-10-24-cloud-run-regional-snapshot.json
python3 -B tools/production/sheikha-cloud-build-context-v1.py --stage --staging-root /tmp
```

يُرجع `assess` الرمز 1 عند وجود موانع، و2 للمدخلات غير الصالحة؛ القراءة لا تتصل بـ Google. يُرجع `plan` صفرًا عند صحة الخطة المحلية فقط. حتى اجتياز الفحوص المحدودة يبقي `eligibleForDeployment=false`. الفاحص ليس محرك تصاريح، ولا يفحص جميع شروط الإنتاج أو صحة الأسرار.

استخدم مجلد `staging_directory` الجديد الناتج من الفاحص المحلي، لا جذر المشروع. من داخله يمكن تشغيل `node tools/verification/sheikha-cloud-build-source-guard.cjs me-central2` محليًا. فحص البصمات يكشف تغير المحتوى مقارنة بالبيان؛ البيان غير موقّع ويمكن لمن يملك الكتابة تعديلهما معًا، فلا يُعد إثبات ملكية أو مصدر موثوق بذاته. ليست هناك حماية من كاتب متزامن بعد انتهاء الفحص؛ يلزم بناء نسخة معزولة دون كاتب آخر.

قبل استئناف أي بناء سحابي: تفعيل أهلية الدمام، التحقق من توفر Cloud Build وArtifact Registry وصلاحيات حساب البناء هناك، وتحديد حاويات المصدر والسجلات السعودية صراحةً، وتقدير التكلفة واعتمادها. لا تعتمد الحاوية الافتراضية الأمريكية للمصدر أو السجلات. لم تُنشأ الموارد ولم يُعتمد سقف إنفاق جديد.

## تسلسل النشر بعد رفع الموانع

1. التحقق من الوصول إلى الدمام عبر حساب المشروع والفوترة المعتمدين، دون تعطيل سياسة المؤسسة.
2. إنشاء/اعتماد الموارد السعودية ومواقع الأسرار والبيانات والنسخ الاحتياطية بمراجعة مستقلة؛ لا نقل أسرار بين البيئات.
3. تحديد الحاجة الفعلية للنماذج. إذا لم يحتج تشغيل البوابة إليها، تُنشأ المراجعة السعودية دون mount للنماذج بعد الاختبار. إن لزمت، يُتحقق من الحاوية السعودية ومحتواها وقراءة حساب تشغيل الخدمة ثم يُستخدم mount للقراءة فقط. لا تُمسح كل mounts ولا تُنشأ حاوية فارغة لإخفاء الخطأ.
4. بناء السياق المعزول المختبر محليًا، ثم رفعه ضمن ميزانية معتمدة، وتثبيت نشر الحاوية بالـ digest الناتج لا بوسم قابل للتغيير.
5. إطلاق canary سعودي مصادق عليه واختبار الصحة والمصادقة والبيانات والاستعادة. الحفاظ على الخدمة الأمريكية دون حذف، وعدم جعلها fallback للبيانات الخاصة.
6. فصل مهام الجدولة ومخازن الحالة قبل زيادة النسخ، ثم اعتماد تغيير DNS لدى Hostinger وخطة رجوع تراعي حدود السعودية.
7. نشر منتج الملفات العامة فقط في العقد الدولية المعتمدة واختبار موازن الحمل، منع التسريب، فشل المواقع والرجوع. التعافي السعودي من كارثة إقليمية يتطلب موقعًا سعوديًا مستقلًا؛ تكرار النسخ في المنطقة نفسها ليس بديلًا له.

## متابعة الاستماع وشرط الإنفاق

أكد المستخدم عدم وجود حساب CNTXT، واشترط بلوغ التعادل وتحقيق أرباح للميزانية. هذا شرط تجاري وليس سقف إنفاق رقميًا معتمدًا ولا ضمانًا للربحية؛ تبقى `zeroNewSpend=true` و`productionHold=true` حتى تتوفر بيانات الإيراد والتكلفة وسقف واضح واعتماد الموارد. لم تُنشأ فوترة ولم يُقدّم التزام مالي.

طلب المستخدم لاحقًا إصلاح الاستماع في `server.js`. كانت قيمة PORT قد عُدلت بالفعل من كتابة أخرى إلى `parseInt(process.env.PORT, 10) || 8080`؛ حُفظت. ثُبّت `HOST='0.0.0.0'` وأضيف سجل عنوان الاستماع الفعلي، مع إبقاء كائن `server` والمسارات وWebSocket وSIGTERM/SIGINT. لم تُضف أرقام 223 وزنًا أو 8,080,000 SHK إلى رسالة الإقلاع لأنها ليست قياسًا يجريه بدء الخادم. الربط بكل واجهات IPv4 يشمل التشغيل المحلي أيضًا؛ لم يُشغّل خادم على منافذ المضيف.

أثناء الاختبار ظهرت كتابة متزامنة استبدلت السطر بتركيب `const server = const PORT...` غير الصالح. صُحح هذا السطر وحده، دون إيقاف العملية الأخرى أو الكتابة فوق باقي الملف، ثم طابقت بصمته نسخة الحاوية المختبرة. لا تمنع هذه المطابقة كتابة لاحقة من جلسة أخرى.

المرفق `cd8008de-8b15-4704-a87d-0f3d3839073d` ذو البصمة `bb7f77b313589d61c07e6e5b3c13a82c97115d3e64e50da28cc052badb9b1dc2` يعرض بناء `352515cc-abb0-4e8b-8abc-06b81f473f10` فاشلًا، ثم نشر مرجع `sheikha-registry/sheikha-main-portal:b03af0d43` غير موجود. لا يُستنتج من السجل المختصر سبب فشل خطوة Docker، ولا يُعالج غياب الناتج بتغيير المنفذ أو IAM. الوصفة الحالية تستخدم `sheikha-apps` في الدمام؛ لم يُعَد تنفيذ أوامر النشر الأمريكية من المرفق.

التحقق الأحدث: 34 حالة Node ناجحة تشمل خمس حالات تحكم الخادم، مع 21 حالة Python السابقة غير المتأثرة. بُنيت حاوية محلية من السياق `/tmp/SHEIKHA_CLOUD_CONTEXT_V1_1vb0nhv7` باستخدام الطبقات المخزنة، بلا شبكة أو تنزيل. اجتازت 79 فحصًا داخل الحاوية: 78 فحص HTTP وفحص مقبس IPv4 الفعلي `0.0.0.0:8080` عبر `/proc/net/tcp`، وأغلق الخادم برمز صفر دون وحدات مفقودة. وضع الاختبار `SHEIKHA_ENABLE_ALL_ENGINES=false`؛ لا يدعي اختبار كل المحركات أو المزودين.

البيان الأحدث: `runtime/cloud-build-recovery-verification/2026-10-24-listener-local.json`. بيان المرحلة الإقليمية والسياق السابقان يبقيان سجلًا تاريخيًا ولا يمثلان آخر بايتات `server.js`. فحص فرق Git العام يرصد مسافات زائدة سابقة في الملف الكبير؛ لم تُنظّف تعديلات المستخدم، وفرق سطور هذه المهمة خالٍ من مشاكل المسافات.
