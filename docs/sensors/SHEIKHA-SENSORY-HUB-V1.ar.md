
## عقد الإدخال

```json
{
  "schemaVersion": 1,
  "tenantId": "sheikha-local-lab",
  "observations": [
    {
      "sourceId": "ENV-TEMP-01",
      "sequence": 1,
      "observedAt": "2026-10-19T00:00:00.000Z",
      "value": 25,
      "unit": "Cel",
      "quality": "VALID",
      "calibration": "UNKNOWN",
      "uncertainty": null
    }
  ]
}
```

المثال توضيحي وسيُصنف قديمًا بمرور الوقت. زر «عينة JSON» ينتج عينة اصطناعية مؤرخة وقت طلبها؛ تغيير التاريخ لا يحول العينة إلى قراءة حقيقية.

- JSON بترميز UTF-8 صحيح، بحد 512 KiB، ودفعة من 1 إلى 500 قراءة. الحقول المحددة إلزامية، وأي حقول إضافية مرفوضة.
- `sourceId` من قائمة المصادر المسجلة فقط. `tenantId` علامة نطاق محلي، وليس هوية موثقة أو حاجز مصادقة شبكيًا.
- `observedAt` بصيغة UTC المبينة، مع أجزاء الألف من الثانية؛ التواريخ غير الصالحة والمستقبلية مرفوضة.
- `sequence` عدد صحيح آمن غير سالب، يزداد لكل مصدر. التكرار أو تراجع الزمن مرفوض داخل الدفعة وعبر الدفعات في جلسة النواة نفسها.
- `value` رقم محدود، لا سلسلة نصية. الوحدة سلسلة نصية صريحة، لا مصفوفة قابلة للتحويل النصي.
- الحرارة تقبل `Cel` و`K` و`[degF]`؛ الضغط `Pa` و`kPa` و`bar`؛ القدرة `W` و`kW`؛ الرطوبة `%RH`؛ الإشعاع `W/m2`.
- `quality`: إحدى `VALID` أو `SUSPECT` أو `INVALID`. `calibration`: إحدى `CURRENT` أو `EXPIRED` أو `UNKNOWN`. كلاهما تصريح وارد من الملف، لا تحقق مستقل.
- `uncertainty`: مقدار مطلق غير سالب بوحدة الإدخال، أو `null` عندما يكون مجهولًا. لا يفترض مستوى ثقة إحصائيًا. يتحول بمقياس الوحدة دون إزاحتها.
- تحتفظ النواة بآخر 120 قراءة لكل مصدر و100 حدث قبول. تحتفظ الواجهة كذلك بآخر 100 حدث رفض، وتضمها إلى التقرير المصدر.

## التفسير والحماية

الحالات: `MISSING` و`INVALID` و`STALE` و`UNCERTAIN` و`UNCALIBRATED` ثم `ABOVE` أو`BELOW` أو`WITHIN`. يحتفظ `issues` بجميع المشكلات حتى عندما تعرض الشارة واحدة منها. عند وجود مشكلة تكون `comparison=null`، ولا يُستنتج أن القراءة سليمة.

غياب القراءة ليس صفرًا. تقاطع مجال عدم اليقين مع حد مرجعي يستدعي التحقق. النطاقات المرجعية أمثلة هندسية فقط، وليست حدود سلامة أو تشخيصًا طبيًا. الحدود العددية القصوى في المحقق قيود برمجية، وليست معايرة جهاز أو ضمانًا فيزيائيًا شاملًا.

التفسير نص حتمي من القياس وحالته، وليس استدعاء نموذج لغوي أو استنتاجًا سببيًا. المرئيات تبين السجل المحتفظ به وتترك فجوة عند القراءة ذات الجودة `INVALID`.

الوضعان الوحيدان هما `SYNTHETIC` و`IMPORTED_UNVERIFIED`. استيراد ملف حقيقي محتمل لا يمنحه صفة «جهاز موثق». تظل أعلام الاتصال والتحكم والاعتماد الإنتاجي والتحقق المستقل من المعايرة معطلة.

الاستيراد يتطلب مراجعة ثم تأكيدًا؛ الإلغاء، بما فيه Escape بعد تأكيد سابق، لا يغير القراءات. الملف غير الصالح لا يستبدل الحالة الحالية. استيراد ملف جديد يستبدل جلسة القراءة ولا يراكم التسلسلات عبر الملفات؛ منع التكرار ليس سجلًا دائمًا بين الجلسات.

لا تتصل الواجهة بالشبكة، ولا تستخدم تخزين المتصفح. سياسة CSP تمنع الاتصالات الخارجية. البيانات المستوردة تعالج في الذاكرة، ويُحفظ تقرير فقط عند طلب التصدير. سجل الواجهة ليس سجلًا جنائيًا غير قابل للتعديل أو نظام احتفاظ دائمًا.

تُحدّث أعمار القراءات وحالاتها كل خمس ثوان أثناء ظهور الصفحة؛ لا تصل قياسات جديدة تلقائيًا. ملفات البناء المحلية ذات أذونات مقيدة، وتتحقق الأداة من الروابط الرمزية وحجم الملفات وتغيرها أثناء القراءة؛ هذا لا يمثل ضمانًا ضد مهاجم يستطيع تعديل مجلدات العمل بالتزامن.

## التشغيل المحلي

الواجهة المباشرة: [مرصد مستشعرات شيخة](../../runtime/sensory-hub/index.html). تعمل كملف مستقل في المتصفح، دون خادم أو حساب أو فاتورة مزود.

```bash
node tools/sensors/sheikha-sensory-hub-v1.cjs build
node tools/sensors/sheikha-sensory-hub-v1.cjs sample
node tools/sensors/sheikha-sensory-hub-v1.cjs evaluate --input /absolute/path/readings.json
node tests/sheikha-sensory-hub-v1.test.cjs
node tests/sheikha-sensory-console-browser-v1.test.cjs
```

`evaluate` يطبع التقرير ولا ينشره أو يكتبه في خدمة خارجية. اختبار المتصفح يحتاج Playwright وChrome؛ موضع Playwright الافتراضي في بيئة العمل `/tmp/sheikha-architecture-tools/node_modules/playwright`، ويمكن تغييره بمتغير `PLAYWRIGHT_MODULE`.

`runtime/sensory-hub/latest.json` يحدد لقطة البناء الحالية. تضم اللقطة `build.json` وبصمات HTML والعينة والنتيجة الأساسية والترخيص. العينة والنتيجة الأساسية اصطناعيتان. البصريات المعمارية المعروضة أصل محلي سابق، وليست بثًا من منشأة فعلية.

## التحقق

تغطي 22 حالة اختبار للنواة: التحويلات، الحدود والأنواع، المعايرة وعدم اليقين، التقادم، التكرار، الترتيب، العزل المنطقي للمؤسسة، القبول الذري، نسخ الحالة، رفض الأوامر والروابط الرمزية وUTF-8 التالف.

يغطي اختبارا المتصفح العربية والإنجليزية عند عروض 320 و390 و820 و1440، وظهور الأصل البصري، وعدم تجاوز العناصر أو تسميات المخطط، والبحث والترشيح والتفاصيل، والمراجعة والإلغاء والرفض والتصدير وإعادة العينة. تقريري التنفيذ:

- `runtime/sensory-hub/browser-verification.json`: فحص العرض وبصمة HTML.
- `runtime/sensory-hub/workflow-verification.json`: فحص مسار العمل وبصمة HTML.

يجب أن تطابق بصمتا التقريرين `latest.json` قبل الاستناد إليهما. هذه فحوص لهذه الوحدة فقط، لا اختبارات شاملة للمنصة أو اعتمادًا للأجهزة.

## ما يلزم للربط الفعلي

أضيف لاحقًا [تكامل SDK وMCP المحلي](SHEIKHA-SENSORY-SDK-MCP-V1.ar.md) لإعادة استخدام هذه النواة في تفسير دفعات يقدمها المستدعي. هذا المدخل لا ينشئ اتصالًا بالأجهزة ولا يغير حدود الواجهة المحلية.

1. تحديد أول جهاز أو ملف قياسات متاح، ومالكه، والبروتوكول والوحدات وتواتر القراءة والمعايرة.
2. إضافة موصل قراءة فقط خاص بالمصدر. لا يوجد الآن تنفيذ MQTT أو OPC UA أو ربط أقمار صناعية أو تسجيل حساسات بشرية.
3. توثيق هوية المصدر والاتصال، وتخصيص الصلاحيات، وتحديد سياسة الاحتفاظ والخصوصية قبل البيانات الشخصية أو الحساسة.
4. اختبار الانقطاع والتأخير وإعادة الاتصال وتفاوت الساعة والوحدات، ومقارنة القياس بأداة مرجعية مناسبة.
5. اعتماد محدود المصدر والنطاق قبل جدولة المراقبة. لا مؤقت جديد، ولا تحكم بمصنع، ولا تعديل ذاتي للشفرة أو تدريب أو نشر تلقائي في هذه النسخة.

الصوت أو اللمس أو التجسيم الحسي مسارات لاحقة تحتاج تصميمًا واختبارات وصول وموافقة مستقلة. لا يمثل النص والرسم البياني تنفيذًا لها.
