# بيئة شيخة الأصلية للنشر — تأسيس تجريبي

الهدف: استبدال Node.js وDocker وPM2 وLinux في بيئة تشغيل شيخة النهائية. الحالة الحالية ليست بديلًا إنتاجيًا مكتملًا.

| الطبقة | بديل شيخة | الإثبات الحالي |
|---|---|---|
| نظام التشغيل | نواة شيخة وUEFI | يُتحقق بالإقلاع في QEMU |
| تنفيذ اللغة | منفذ أصلي لأوامر إنتاج محدودة من .shk | GCC freestanding، بلا imports إلى نظام مضيف |
| إدارة التطبيق | Native Supervisor | حالات deploy/start/stop/restart وحد تنفيذ محدود؛ تعاوني لا استباقي |
| حزم التطبيقات | حزمة تطوير ثابتة مضمّنة في صورة الإقلاع | تحويل برنامج الوحدات إلى تعليمات وعقود تعمل في RAM |
| عزل التطبيقات | بوابة قبول وحدود ميزانية | عزل صفحات وصلاحيات مستخدم لم يثبت |
| الشبكة والتخزين | مخطط تطوير مستقل | TCP/IP وTLS وHTTP ونظام ملفات دائم غير مكتملة |

المصدر العربي: sheikha-language/foundations/activated-session-production-v1.shk. الأدوات المضيفة تستخدم Node.js وLinux لبناء الصورة فقط؛ الضيف الأصلي لا يستخدمهما في التشغيل. لا يوجد مترجم ذاتي مستضاف مثبت بعد. المنفذ الأصلي يدعم ثلاث تعليمات محلية محدودة، وليس كل دلالات لغة شيخة.

النشر التجريبي هنا: دمج حزمة موثقة في صورة جديدة ثم إقلاعها محليًا في آلة افتراضية بلا شبكة. لا يتم استبدال نظام VPS أو تحميل Firmware أو الكتابة إلى USB أو قرص فعلي. لا يُعد حفظ عقود في RAM تشغيلًا كاملًا للمنصة أو LLM أو Studio.

بوابة الإنتاج مغلقة حتى إثبات الشبكة والتخزين والعزل وتوقيع الحزم والاستعادة وتكافؤ خدمات المنصة. كل طبقة تحتاج مسؤول تطوير ومراجع أمان ومعتمد إصدار؛ تعيين الأشخاص UNKNOWN.

حالة التنفيذ: DEVELOPMENT_VM_RUNTIME_VERIFIED.

الإثبات: runtime/sheikha-native-environment/v1/builds/48cc4a2b39b796091091f6307f8229f1b70d0968f1765871ab017e0812bd07ae/verification.json. إقلاع QEMU ناجح بعد ExitBootServices، وخروج متوقع 33، وتنفيذ 37 تعليمة لإنتاج عقود 18 مكوّنًا في RAM، و10 فحوص مدير التطبيق الأصلي، و4 اختبارات حزمة و12 اختبار إدارة. الملف ELF بلا imports غير محلولة، وبصمات EFI والصورة والحزمة متحققة.

واجهة الإدارة للقراءة: /api/sheikha/foundation/managed/v1/native-environment/status. مدير التطبيق محدود ببرنامج ثابت واحد وميزانية 128 خطوة؛ لا يدير خدمات المنصة الكاملة.

مراحل استكمال البديل: (1) فضاءات عناوين وصلاحيات مستخدم ومقاطعات وجدولة استباقية؛ (2) تخزين دائم وVFS فعلي وبرامج تشغيل؛ (3) شبكة وTCP/IP وTLS وHTTP؛ (4) تحميل حزم ديناميكي وتوقيع واستعادة؛ (5) ترحيل الخدمات والتحقق من تكافؤ سلوكها؛ (6) نشر تجريبي منفصل قبل أي اعتماد إنتاجي. أي مكتبات خارجية تُوثق تراخيصها وحقوقها، ولا يُدّعى امتلاكها لمجرد دمجها.
