# ربط SDP بمنصة شيخة السابقة

تقرأ SDP الآن سجل الترخيص الداخلي ومنصة SHEIKHA_DEVELOPER_PLATFORM_V1 وعقد system-builder-platform وسجل أدواته. تعرض هذه المراجع في الحالة وتمنع بناء الحزمة الثابتة إذا اختلت البصمة أو النوع أو النطاق أو سياسة المنع.

أدوات SDP محول تطوير محلي محدود، وليست أساسًا معماريًا بديلًا. لم تتغير سجلات المنصة السابقة ولم يصدر ترخيص جديد. تطابق بصمة الترخيص الداخلي يثبت اتساق السجل فقط، لا هوية مصدره أو شهادة خارجية.

يغطي الربط الآن بناء SDP الثابت وتجميع مشاريع SDP المحلية، كما يقرأ فاحص الحزم الثابتة الربط عبر المترجم الذي يستدعيه. تحوي حزم المشاريع الجديدة ملف license-context.json بمرجع الترخيص الداخلي وبصمات السجلات، دون بيانات مالك أو منح رخصة جديدة. لا تسجيل أو تفعيل تلقائي للعائلات المخططة أو تثبيت حزم.

## مراجعة الحزم
حزمتا DEB 1.0.51 تنتميان لبناءين تاريخيين مختلفين وتطابقان البصمات في تقاريرهما. كلتا الوثيقتين تصف الفحص البنيوي دون اعتماد تثبيت أصلي. سجل V6 يحدد خط أساس مختلفًا بإصدار 1.0.51+sheikha.v6.1 وهدف ترقية 1.0.51+sheikha.v6.2، لكن الملفين المشار إليهما غير موجودين في المستودع الحالي. لا اختيار حزمة للتثبيت أو إعادة بناء قبل استرجاع الأثر وربطه بأدلته.

نقص تقرير RPM المشار إليه يظل مفتوحًا، رغم تطابق بصمة الأثر الموجود. لا تُمحى التقارير التاريخية بسبب اختلاف مرحلة التأهيل.
