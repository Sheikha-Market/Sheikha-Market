# مراجعة شيخة R5 التفاعلية

المطلوب المستخرج من المرفق الأخير: «أريد تحسينها»، في سياق
`SHEIKHA_R5_REVIEW(1).html`. التحسين هنا لواجهة المراجعة، وليس تشغيل 88 خدمة.

## النسخة المحسنة

افتح `runtime/r5-review/index.html` مباشرة، دون خادم أو نشر عام.
النصوص والمرئيات مدمجة محليًا، مع سياسة تمنع الاتصالات الخارجية وتنفيذ محتوى المرجع.
الأصل في `/home/sheikha/مستندات/شيخة الهوية/SHEIKHA_R5_REVIEW(1).html` لا يُعدل.

- كتالوج قابل للبحث والتصفية: 20 عائلة و88 وحدة مقترحة.
- 14 عقد تكامل تربط الوحدات وتعرض الأحداث وشروط العبور.
- تفاصيل الدور والمخرجات والعقود لكل وحدة.
- 34 معيار قبول مع حالة مراجعة وملاحظة لكل معيار، دون اختلاق نتيجة اختبار.
- حفظ الملاحظات في المتصفح، مفصولة بحسب بصمة المصدر، وتصدير مراجعة JSON.
- استيراد مراجعة مطابقة للمصدر، مع معاينة التعارضات ودمج اختياري وتراجع عن آخر استيراد.
- تصدير الكتالوج والمواصفة والمعايير مع بصمة المصدر وحدود التنفيذ.
- المعمارية ومواصفة RFQ / CRM والمراجع والمرئيات الأصلية داخل أقسام مستقلة.

معرّفات الوحدات مشتقة من رمز العائلة وترتيب عناصر جدول R5، وليست معرّفات
خدمات متصلة أو مستوردة من `SYSTEMS_CATALOG_R5.json` غير المرفق هنا.
تتحقق أداة البناء من الأعداد وتفرّد المعرفات ووجود طرفي كل عقد.

## حدود المراجعة

`READY_FOR_TEST` يعني جاهزًا للاختبار من وجهة نظر المراجع، ولا يعني نجاحه.
التصدير يبقي `publicationApproval: false` و`testResults: NOT_EVALUATED`.
الملاحظات المحلية ليست قاعدة بيانات مشتركة أو سجل تدقيق موثق الهوية؛ قد يمحوها
المتصفح. إذا تعذر التخزين، تظهر حالة واضحة وتبقى إمكانية التصدير.

## استيراد المراجعة

يقبل الاستيراد ملف `SHEIKHA_R5_HUMAN_REVIEW_V1` بحد أقصى 256 KiB، وبصمة
مصدر تطابق المستند الحالي. يفحص جميع المعايير والحالات والملاحظات قبل أي تغيير،
ويرفض البنية غير الصالحة والمعرّفات المجهولة وأي اعتماد نشر أو ادعاء نجاح اختبارات.
لا يتجاوز طول الملاحظة 2000 محرف، وتعرض نصًا غير منفذ حتى لو احتوت وسومًا.

تظهر الملاحظات الجديدة والتعارضات في معاينة قبل الدمج. الخيار الافتراضي لكل
تعارض هو إبقاء الملاحظة المحلية، ولا تُستبدل إلا باختيار «استخدام الواردة» ثم
تأكيد الدمج. الإلغاء أو الملف المرفوض لا يغيران الملاحظات الحالية. اختلاف تاريخ
التحديث وحده لا يُعد تعارضًا ولا يبدل المحتوى المحلي.

التراجع يعيد الحالة السابقة لآخر استيراد في الجلسة نفسها. يلغى خيار التراجع بعد
تعديل يدوي لاحق أو إعادة تحميل الصفحة حتى لا يمحو عملًا أحدث. بعد استيراد ثانٍ
يكون التراجع لذلك الاستيراد فقط. عند منع التخزين يبقى الدمج في ذاكرة الجلسة
وتظهر رسالة تطلب التصدير لحفظه. لا يوجد رفع إلى خادم أو تحقق من هوية المراجع؛
ملف المراجعة ليس توقيعًا أو إثباتًا لصحة الملاحظات.

الأقسام الوثائقية تحفظ محتوى R5 التاريخي، مع تحديث المصطلحات الظاهرة إلى
«مرئيات» و«بصريات». الأرقام ومواعيد التشغيل القديمة فيها ليست تقرير حالة حاليًا.
المنظومة اليومية الحالية موثقة في [دليل الفوندري](SHEIKHA-VISUAL-FOUNDRY.md).

وجدت حزمة مختبر RFQ / CRM أحدث في مساحة التجهيز المحلية؛ لم تُعدل أو تُشغل
اختباراتها ضمن هذه المهمة. كذلك لم تُنفذ سكربتات Gemini التي تكتب حالات
`ACTIVE` في SQLite، ولم تُعتبر بصماتها دليلًا على تشغيل الأنظمة.

## البناء والتحقق

```bash
python3 -B tools/review/build-sheikha-r5-review.py
python3 -B -m unittest discover -s tests -p test_sheikha_r5_review.py
node tests/sheikha-r5-review-state.test.cjs
PLAYWRIGHT_MODULE=/tmp/sheikha-architecture-tools/node_modules/playwright node tests/sheikha-r5-review-browser.test.cjs
```

أداة البناء تستخدم محلل HTML القياسي، لا تنفذ المستند، وتستخلص الجداول والنصوص
والمرئيات النقطية المدمجة فقط. ملف `build.json` يوثق بصمة المصدر والمخرجات؛
ملف `browser-verification.json` يوثق اختبار واجهة المراجعة فقط، وليس اختبارات
RFQ الخلفية أو قبول الأنظمة الـ88. أي تغيير في المصدر يحتاج بناءً وفحصًا جديدين.
ملف `import-verification.json` يوثق فحص الاستيراد والدمج والتراجع ورفض الملفات
غير المطابقة، ويرتبط ببصمة واجهة HTML المختبرة.
الأيقونات من Lucide المحلي، مع الرخصة ضمن المخرجات.
