# تقرير جاهزية تجربة إقلاع شيخة Kernel وBare Metal على MSI

**الإصدار:** V1  
**تاريخ التحقق:** 31 أغسطس 2026  
**نوع التجربة:** إقلاع UEFI لمرة واحدة من USB مخصص  
**الحالة:** `QEMU_BOOT_VERIFIED_PHYSICAL_BOOT_PENDING`

## 1. القرار التنفيذي

حزمة التجربة جاهزة لإعداد USB مخصص وتجربة إقلاع فيزيائية مضبوطة على جهاز
MSI. نجح البناء والتحقق البنيوي وإقلاع QEMU/OVMF، وظهرت علامة النهاية
`SHEIKHA_BARE_METAL_BOOT_OK`. لم تُكتب الصورة إلى USB، ولم يحدث إقلاع
فيزيائي، ولم يُعدل القرص الداخلي أو NVRAM أو ترتيب الإقلاع.

هذه الصورة **بذرة نواة وتجربة إقلاع** تنتهي بتوقف محكوم. ليست مثبت نظام
تشغيل، ولا تتضمن بعد نظام ملفات دائمًا أو شبكة أو تعريفات عتاد كاملة أو
Secure Boot موقعًا.

## 3. حدود السلامة الملزمة

1. استخدم USB مخصصًا قابلًا للمحو ولا يحتوي أي معلومات لازمة.
2. لا تستخدم `/dev/nvme0n1` أو `/dev/mapper/data-root` أو أي قرص داخلي.
3. لا تنفذ أمر الكتابة قبل مراجعة `lsblk` ومسار الجهاز وحجمه ونوع نقله.
4. لا تغير ترتيب الإقلاع الدائم ولا مفاتيح Secure Boot ولا Firmware.
5. استخدم قائمة الإقلاع المؤقتة في MSI عبر `F11` فقط.
6. افصل الأقراص الخارجية الأخرى لتقليل احتمال اختيار جهاز خاطئ.
7. أبق الجهاز موصولًا بالطاقة، واحفظ العمل المفتوح، وأغلق التطبيقات قبل
   إعادة التشغيل.
8. لا تعتبر ظهور الشاشة نجاح نظام تشغيل كامل؛ النجاح هنا خاص بعقد الإقلاع.

## 4. حفظ المعلومات والأدلة قبل التجربة

أنشئ مجلد جلسة مؤرخًا واحفظ فيه المخرجات القراءة فقط:

```bash
cd "$HOME/Projects/sheikha/sheikha-main-portal"
SESSION="runtime/bare-metal/v2/physical-trial/manual/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$SESSION"
lsblk -e7 -o NAME,PATH,TYPE,SIZE,RM,RO,TRAN,MODEL,MOUNTPOINTS > "$SESSION/lsblk-before.txt"
findmnt > "$SESSION/findmnt-before.txt"
sha256sum \
  bare-metal/images/v2/sheikha-sovereign-bare-metal-v2-msi-usb-gpt-v1.img \
  bare-metal/images/v2/esp/EFI/BOOT/BOOTX64.EFI \
  > "$SESSION/artifact-sha256-before.txt"
cp runtime/bare-metal/v2/physical-trial/v1/sheikha-v2-msi-usb-gpt-v1-manifest.json "$SESSION/"
```

لا تحفظ كلمات مرور أو مفاتيح خاصة أو محتوى شخصي داخل سجل التجربة.

## 5. الإجراء الصحيح لإعداد USB

1. افصل كل وسائط USB غير اللازمة.
2. صِل USB المخصص.
3. نفذ الفحص القراءة فقط:

```bash
npm run -s ops:bare-metal:physical-trial:inspect:v2
lsblk -e7 -o NAME,PATH,TYPE,SIZE,RM,RO,TRAN,MODEL,MOUNTPOINTS
```

4. يجب أن يظهر جهاز كامل مثل `/dev/sdX` بقيمة `TRAN=usb` أو `RM=1`، وألا
   يكون مركبًا. لا تستخدم مسار قسم مثل `/dev/sdX1`.
5. استبدل `/dev/sdX` فقط بعد مراجعة بشرية مستقلة. شغّل الكاتب أول مرة
   بقبول غير مطابق كي يطبع `REQUIRED_ACCEPTANCE` دون كتابة، ثم انسخ النص
   حرفيًا وأعد التشغيل بالموافقة الصريحة.
6. الكاتب يتحقق من الصورة والـmanifest والجهاز، يرفض قرص النظام، ثم يكتب
   64 MiB فقط ويعيد قراءة نفس الحجم ويقارن SHA-256. لا يعلن النجاح إذا
   اختلفت القراءة.

أمر الكتابة عالي الأثر ولا يُنفذ إلا بعد تحديد USB والموافقة الصريحة:

```bash
sudo ./scripts/bare-metal/v2/write-msi-usb-v1.sh \
  --device /dev/sdX \
  --accept 'ACCEPT SHEIKHA MSI USB V1 SHA256:<HASH> DEVICE:/dev/sdX'
```

سجل المخرجات في ملف الجلسة باستخدام `tee` عند التنفيذ الفعلي.

## 6. إجراء الإقلاع الأول الآمن

1. أوقف الجهاز إيقافًا طبيعيًا بعد حفظ العمل.
2. أبق USB موصولًا، وشغّل الجهاز واضغط `F11` دوريًا.
3. اختر إدخال UEFI الخاص بالـUSB فقط. لا تدخل إعدادات Firmware لتغيير
   الترتيب الدائم.
4. راقب شاشة تجربة شيخة. النجاح المتوقع: شاشة آمنة وشريط أخضر ثم توقف
   محكوم.
5. صوّر الشاشة دون إظهار أرقام جهاز أو معلومات سرية، وسجل وقت البداية
   والنتيجة.
6. بعد التوقف المحكوم، أطفئ الجهاز، افصل USB، ثم شغله طبيعيًا.
7. تحقق أن Pop!_OS يقلع وأن القرص والذاكرة والشبكة تعمل كالمعتاد.

## 7. إعادة الإقلاع واختبار الثبات

لا تعتمد النتيجة من محاولة واحدة. نفذ محاولتين منفصلتين:

- **Cold boot:** إيقاف كامل، انتظار 15 ثانية، ثم الإقلاع من USB عبر F11.
- **Second cold boot:** إعادة الإجراء بعد عودة ناجحة للنظام الأصلي.

قبول K1 يتطلب نجاح المحاولتين، تطابق البصمة، ظهور علامة النجاح نفسها، صفر
كتابة على القرص الداخلي، وعودة النظام الأصلي بعد فصل USB.

## 8. الطوارئ والتعافي

### إذا لم يظهر USB في F11

- لا تغير ترتيب الإقلاع الدائم.
- أطفئ الجهاز، أعد توصيل USB بمنفذ آخر، ثم أعد الفحص والبصمة من النظام.
- إذا استمر الغياب، اعتبر النتيجة `USB_ENUMERATION_FAILED` وتوقف.

### إذا ظهرت شاشة سوداء أو توقف غير متوقع

- انتظر 60 ثانية للتأكد أنه ليس التوقف المحكوم.
- دوّن آخر علامة ظاهرة وصوّر الشاشة.
- أطفئ الجهاز بزر الطاقة وفق إجراء MSI المعتاد، ثم افصل USB.
- شغّل الجهاز بلا USB. لأن ترتيب الإقلاع لم يتغير ولم تُكتب الأقراص
  الداخلية، يجب أن يعود Firmware إلى نظام التشغيل الأصلي.
- لا تكرر المحاولة قبل مراجعة الدليل وسجل QEMU.

### إذا لم يقلع النظام الأصلي بعد فصل USB

1. افصل الطاقة والـUSB، ثم أعد تشغيل الجهاز مرة واحدة.
2. افتح F11 واختر إدخال Pop!_OS أو القرص الداخلي يدويًا.
3. لا تمسح NVRAM ولا تعيد تثبيت النظام ولا تعدل الأقسام.
4. إذا بقي الفشل، توقف واحتفظ بالحالة كما هي لمراجعة فنية؛ لا تنفذ إصلاحًا
   تلقائيًا قد يغير البيانات.

### إذا فشل تحقق القراءة بعد كتابة USB

- لا تقلع من الوسيط.
- افصل USB ووسمه `FAILED_READBACK`.
- احتفظ بمخرجات `EXPECTED_SHA256` و`READBACK_SHA256`.
- استخدم وسيطًا آخر بعد إعادة الفحص؛ لا تتجاوز الخطأ.

## 9. سجل نتيجة كل محاولة

يسجل لكل محاولة: الوقت UTC، معرف الجهاز غير السري، نوع الاختبار، بصمة
الصورة، ظهور العلامات الخمس، صورة الشاشة، طريقة الإطفاء، نجاح عودة Pop!_OS،
وأي انحراف. النتيجة تكون واحدة من:

- `PHYSICAL_BOOT_VERIFIED_READ_ONLY`
- `BOOT_MARKER_MISSING`
- `USB_ENUMERATION_FAILED`
- `UNEXPECTED_HALT_OR_DISPLAY_FAILURE`
- `HOST_OS_RECOVERY_FAILED`

## 10. قرار الجاهزية

- جاهز الآن: بناء UEFI، صور الإقلاع، QEMU، عقد Paging، وحزمة تجربة USB.
- جاهز بعد موافقة منفصلة: كتابة USB مخصص وتجربتا cold boot على MSI.
- غير جاهز بعد: Secure Boot، التثبيت على القرص، نظام تشغيل عام، الشبكة،
  التخزين الدائم، وكل تعريفات العتاد.

لا تُغلق بوابة الإقلاع الفيزيائي قبل اكتمال تجربتي K1 وتوثيق العودة الآمنة
للنظام الأصلي.
