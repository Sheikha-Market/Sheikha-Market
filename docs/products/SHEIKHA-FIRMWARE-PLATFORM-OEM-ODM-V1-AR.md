# منصة شيخة للبرمجيات الثابتة التأسيسية

## التعريف

**Sheikha Foundation Firmware Platform (SFP)** منظومة مستقلة لبناء ودمج واختبار وتشغيل Firmware عبر دورة المنصة: الإقلاع، الإدارة خارج نظام التشغيل، الأمن، التحديث، Edge، مراكز البيانات، ومنصات AI. هدفها تمكين المصنع من الانتقال من مواصفات اللوحة والسيليكون إلى منتجات Firmware قابلة للتكرار والتدقيق والاسترداد، مع حوكمة الحقوق والمفاتيح طوال دورة حياة الجهاز.

المنتج ليس نسخة معاد تسميتها من AMIBIOS أو Aptio V، ولا يتضمن شفرتهما. الاسمان علامتان ومنتجان للغير ولا يستخدمان إلا كمرجع مقارن دقيق. أي مكوّن سيليكون أو Firmware مغلق يدخل فقط بترخيص مكتوب وسجل مصدر وSBOM.

## المنتجات القابلة للتسليم

1. **SFP BootLab:** بناء حتمي، إقلاع QEMU، أدلة آلية، وسجل قدرات UEFI.
2. **SFP UEFI Payload:** تطبيق UEFI محكوم وتسليم آمن إلى Sheikha Kernel أو نظام تشغيل معتمد.
3. **SFP Board Port Kit:** BSP للوحة وإصدار محددين، ACPI، PCIe، التخزين، USB، الرسوميات، والطاقة.
4. **SFP Secure Lifecycle:** Secure/Measured Boot، تحديث موقّع، منع الرجوع، استرداد ثنائي، واستجابة للثغرات.
5. **SFP OEM/ODM Production:** تهيئة المصنع، هوية كل جهاز، اختبارات نهاية الخط، تتبع الإصدارات، ودعم ميداني.

## عائلات المنصة

- **Sheikha Boot Foundation:** UEFI/PI وتهيئة المنصة وسياسات الإقلاع وACPI/SMBIOS والتحديث والاسترداد.
- **Sheikha Manage Foundation:** BMC وRedfish وMCTP وPLDM والحساسات والإدارة البعيدة والأساطيل.
- **Sheikha Trust Foundation:** Root of Trust وSecure/Measured Boot وTPM/SPDM وحوكمة المفاتيح ومنع الرجوع.
- **Sheikha Firmware Operations:** SBOM والثغرات والتوقيع والمصدر والتحديث والرجوع والاسترداد.
- **Sheikha Edge Foundation:** أجهزة Embedded وIoT وEdge.
- **Sheikha Datacenter Foundation:** الخوادم والرفوف والتنسيق والقياسات.
- **Sheikha AI Platform Firmware:** اكتشاف المسرعات وإدارتها وقياس بنية AI، دون منح AI سلطة الوميض أو المفاتيح.
- **Sheikha Open Firmware:** أدوات ومكونات مجتمعية لا تُفتح إلا بعد سياسة ترخيص ومراجعة أسرار.
- **Sheikha Platform Engineering:** تكامل السيليكون واللوحات وتخصيص OEM/ODM والتصنيع والتحقق.

## الإصدارات

نسخة **Community** ليست منتجًا ناقصًا عمدًا؛ وظيفتها دعم اللوحات المفتوحة وأدوات المطورين وتوسيع الاختبارات وبناء المجتمع، ولا تنشر قبل مراجعة الترخيص والأسرار والمصدر. نسخة **Enterprise/OEM** تضيف التخصيص التجاري وحزم السيليكون المرخصة والتصنيع والتوقيع الإنتاجي وإدارة الأساطيل ودورة الأمن والصيانة طويلة الأجل.

## المظلة الحاسوبية

تقع المنصة تحت **Sheikha Foundation Computing Platform** التي تربط Firmware وBare Metal وRuntime ونظام التشغيل والإدارة والأمن والرصد وEnterprise Control Plane. هذه مظلة معمارية نشطة لكن تنفيذها الكامل غير مكتمل؛ ولا يجوز تحويل وجود سجل الطبقات إلى ادعاء نظام حاسوبي مكتمل.

تستهلك الطبقات عقد `SHEIKHA_UNIFIED_GOVERNANCE_DECISION_CONTRACT_V1`. كل قرار يحمل فئة المصدر وحالة الاشتقاق والدليل والخطر والتفويض وخطة الاسترداد وسجل التدقيق. النص المرجعي والسياسة البرمجية المشتقة منفصلان، ولا يفصل AI في مسألة شرعية أو اجتهادية؛ الادعاء الديني يحتاج دليلًا، والمختلف فيه يحتاج مراجعة بشرية مؤهلة.

ينفذ القرار المرجعي عبر **Governance Control Plane V1**: PDP ثم lease ثم token موقع بـEd25519 ثم PEP مستقل لكل مجال، مع تحقق audience وcapability والموارد والكتابة والشبكة والإبطال واستهلاك nonce مرة واحدة. كلمة Authority تعني تفويضًا تقنيًا محدودًا فقط. لا تتضمن الشفرة مفتاح إنتاج خاصًا. المحرك الحالي مرجع اختباري داخل الذاكرة؛ الإنتاج الموزع يحتاج HSM/KMS وNonce Store ذريًا دائمًا وسجل تدقيق خارجيًا append-only قبل اعتباره جاهزًا.

تقف **Release Authorization & Production Gate V1** بعد التدقيق. وهي تفحص السلسلة كاملة، وبصمة الأثر وتوقيعه وSBOM ومصدر البناء ومفتاح الإنتاج والبيئة والاسترداد. عند تطبيقها على صورة MSI الحالية تقبل وجود الدليل الفيزيائي، لكنها تصدر `RELEASE_DENY` لغياب قرار وlease وtoken إنتاجية وتوقيع وSBOM ومفتاح إنتاج واسترداد معتمد. نجاح اختبار منطق البوابة لا يساوي السماح بإصدار فعلي.

تربط **Runtime Adapter Fabric V1** عشرة نطاقات بالـPDP والـtoken والـPEP والتنفيذ والتحقق والتدقيق، وتمنع الوصول المباشر للمنفذ. وضع Firmware وBMC وBare Metal الافتراضي `READ_ONLY` ووضع AI الافتراضي `ANALYSIS_ONLY`. ويصنف **Hardware/Firmware Adapter V1** عمليات الفحص والوميض وCapsule وBoot Policy وBMC والمفاتيح والاسترداد؛ ولا ينفذها بذاته. خطة الوميض الحالية مرفوضة لغياب الموافقة والاسترداد والتوقيع والنسخة المقروءة وأداة الاسترداد، ولا توجد كتابة فيزيائية مفعلة.

يقرأ **Physical Platform Trust V1** حالة الجهاز دون تغييرها ويربطها بدليل الإقلاع. القياس الحالي يثبت UEFI وTPM 2.0 ودليل الإقلاع الفيزيائي، لكنه وجد Secure Boot معطلًا، ولم يجد سجل measured boot مقروءًا أو BMC/IPMI، ولم ينفذ remote attestation مشفرة. لذلك الحالة `PARTIAL_LOCAL_PLATFORM_TRUST_EVIDENCE` وليست اعتماد ثقة إنتاجيًا.

تستقبل **Boot Evidence Collector V1** ملفات export محددة صراحة من 15 نوعًا، وترفض الروابط الرمزية والأجهزة و`/dev` و`/proc` و`/sys` والملفات الكبيرة أو غير المعتمدة، ولا تنفذ المحتوى. ويعيد **TPM Evidence Normalizer V1** حساب امتداد PCR من event log ويدعم SHA-1/256/384/512 ويصنف النتائج إلى MATCH أو MISMATCH أو UNVERIFIED. لم تُدخل حتى الآن exports حقيقية لـPCR أو TPM event log، ولذلك جاهزية المحرك لا تعني تحقق measured boot.

يقرأ **Native TPMS_ATTEST Parser V1** البنية الثنائية الأصلية للـQuote، بما فيها magic والنوع وnonce وclock وPCR selection وpcrDigest، ويفصل حقل حجم `TPM2B_ATTEST` عن bytes الموقعة. ويتحقق **Native TPMT_SIGNATURE Verifier V1** من RSASSA وRSAPSS وECDSA باستخدام هوية AK العامة، ويدعم pin حكومي داخلي وسلسلة X.509 مع حدود صريحة: السلسلة لا تثبت إقامة المفتاح داخل TPM، والـpin لا يثبت هوية الجهاز وحده. لم يُدخل Quote أو توقيع أو AK enrollment حقيقي بعد، ولذلك `nativeQuoteCryptographicallyVerified=false`.

## البنية الهندسية

يمر المنتج بسبع طبقات: حدود ترخيص السيليكون، تهيئة اللوحة، خدمات UEFI، إقلاع شيخة وحوكمته، التحديث والاسترداد، إعدادات المصنع وعلامته، ثم مختبر CI والعتاد وSBOM والاستجابة للثغرات. ويُركب لكل منتج وفق السلسلة: `Core → Architecture Adapter → Licensed Silicon Package → Named Board Package → OEM Product`. لا تنتقل الأسرار بين هذه الطبقات إلا من خلال خزنة ومراسم مفاتيح موثقة.

المعماريات المستهدفة هي x86-64 وARM64 وRISC-V، لكن إدراج المعمارية في السجل هدف معماري وليس ادعاء دعم فعلي. كل Silicon Package وBoard Package يحتاجان ترخيصًا واختبارًا ودليلًا مستقلًا.

## Evidence-Governed Firmware

الميزة الأصلية للمنصة هي أن سلسلة الدليل جزء من المنتج: المصدر، عقد البناء، هوية المترجم، SBOM، بصمة الأثر، هوية التوقيع، ربط اللوحة والسيليكون، الاختبار الفيزيائي، تفويض الإصدار، النشر، القياس والتصديق، الدليل التشغيلي، ثم دليل الاسترداد. انقطاع أي حلقة يمنع الترقية التجارية.

قانون التشغيل هو: `FAIL_CLOSED → PROTECT → DETECT → ISOLATE → RECOVER → VERIFY → RECORD_EVIDENCE`. ويمنع العقد Firmware إنتاجيًا غير موقّع، تحديثًا بلا استرداد، خلط مفاتيح التطوير والإنتاج، توسعة شبكة BMC بلا حاجة، أو سلطة AI تتجاوز سياسة الأمن.

## بوابات الإنتاج

| البوابة | النتيجة المطلوبة | الحالة الحالية |
|---|---|---|
| F0 | عقد المنتج والحقوق | متحقق |
| F1 | إقلاع محاكى وأثر بناء حتمي | متحقق |
| F2 | BSP واسترداد للوحة مسماة | جزئي: نجح إقلاع USB للقراءة فقط على MSI، ولم يُستبدل Firmware اللوحة |
| F3 | Secure Boot وTPM وتحديث موقّع ومنع الرجوع | محجوب بالدليل |
| F4 | مصفوفة Linux وWindows وACPI والتعريفات | محجوب بالدليل |
| F5 | مفاتيح المصنع وهوية الجهاز واختبار خط الإنتاج | محجوب بالدليل |
| F6 | مشروع تجريبي بعقد قبول مع OEM/ODM | محجوب لعدم وجود لوحة وعميل متعاقدين |
| F7 | إصدار عالمي ودعم واسترداد ميداني | محجوب حتى نجاح F0-F6 لكل عائلة لوحات |

## السلامة والاسترداد

القاعدة الافتراضية هي منع الكتابة على Firmware. لا يسمح بالوميض إلا لصورة مرتبطة بمعرّف اللوحة وإصدارها، بعد نسخة احتياطية قابلة للتحقق، وطريق استرداد خارجي، وتجربة انقطاع طاقة، وتوقيع إصدار، وموافقة بشرية. يجب أن يفشل الجهاز إلى صورة سليمة سابقة أو بنك استرداد، لا إلى صورة غير موثقة.

## الملكية والترخيص

- تبقى شفرة شيخة الأصلية ومحرك البناء والحوكمة ملكًا لشيخة وفق العقد النهائي.
- تبقى ملفات العميل السرية وحقوق اللوحة وفق تعريف العقد الموقّع.
- تبقى حقوق كل مكوّن خارجي وترخيصه لصاحبه، ويمنع نسخه أو نقله بغير حق.
- رقم العقد الداخلي ليس شهادة حكومية أو اعتماد UEFI Forum أو ترخيصًا من AMI.
- يحدد العقد التجاري رسوم هندسة المنصة NRE، ونطاق كل عائلة لوحات، والدعم، وحقوق التوزيع؛ ولا تصدر أسعار أو حقوق تلقائيًا بلا اعتماد قانوني.
- الاسم الحالي اسم عمل هندسي وتجاري. يلزم فحص Trademark Clearance قبل التسجيل أو الادعاء بحماية عالمية للعلامة.
- التطوير Clean-room: تُستخلص المتطلبات من المعايير والواجهات المصرح بها، وتوثق استقلالية التصميم والتنفيذ، ولا تنسخ شفرة أو واجهات خاصة أو أسرارًا تجارية للغير.

## خارطة الطريق المقاسة

تُقاس النهاية بمعايير خروج مدعومة بالأدلة لا بالتاريخ وحده. `M0` متحقق كأساس تطوير محكوم. `M1` جارٍ ويحتاج BSP وACPI واستردادًا ومختبر وميض غير هدّام للوحة مرجعية. ثم `M2` لدورة الأمن والمفاتيح، و`M3` للتصنيع والتوافق والعميل التجريبي، و`M4` للإصدار التجاري لعائلة لوحات مسماة. تسجيل ARM64 أو RISC-V هدف معماري لا يغلق بوابة التنفيذ.

## الحالة المثبتة والخطوة التالية

المثبت حاليًا هو نسيج UEFI، إقلاع QEMU، وصورة USB آمنة دخلت Sheikha Native Kernel على جهاز MSI دون تثبيت أو كتابة Firmware. ظهور الشريط الأخضر في تجربتين يثبت دخول النواة بعد `ExitBootServices` ضمن هذا الأثر والجهاز، لكنه لا يثبت اكتمال نظام تشغيل عام أو استبدال Firmware اللوحة. وهذا يكفي لحزمة تطوير وتجربة، ولا يكفي لتوريد Firmware إنتاجي لمصنّع.

الخطوة التالية هي اختيار لوحة مرجعية مفتوحة أو لوحة يقدم المصنع مخططها وملفات السيليكون المرخصة، ثم تنفيذ F2: BSP، ACPI، استرداد غير هدّام، ومختبر وميض محدود لتلك اللوحة وحدها. بعد ذلك تنفذ F3-F7 بالترتيب، ولا توصف أي عائلة أجهزة بأنها إنتاجية قبل اجتيازها منفردة.

أُنشئت حزمة اللوحة المرجعية `SFP_BOARD_MSI_PULSE_16_AI_C1VFKG_V1` وربطت بطراز MSI وإصدار BIOS والأثر المجرب. أعاد المدقق حساب بصمات سجلات التجربتين ونجح ربطها، لكنه يبقي `isCompletedBsp=false` و`physicalRecoveryDrillCompleted=false` و`productionReleasePermitted=false`. الإجراء الآمن التالي هو تنفيذ جداول ACPI/SMBIOS وجرد الأجهزة دون كتابة Firmware فيزيائي.
