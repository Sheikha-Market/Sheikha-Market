# Sheikha Production Change Admission Gate V1

## الغرض

بوابة قبول التغييرات الإنتاجية طبقة قرار قرائية تمنع قبول أي تغيير إنتاجي قبل اكتمال الأدلة الفنية، وسلامة خط الأساس، والتحقق من الحالة التشغيلية، وجاهزية الرجوع، وصحة الاختبارات، والموافقة البشرية الموثقة.

المرجع الحاكم: الكتاب والسنة، وقاعدة «لا ضرر ولا ضرار»، مع الصدق، ومنع الادعاء، وحفظ سلطة القرار للإنسان.

## الوضع

`EVIDENCE_VERIFY_CLASSIFY_REQUIRE_HUMAN_APPROVAL_ONLY`

## سلطة القرار

`HUMAN_ONLY`

أي حقول موافقة قادمة ضمن طلب خارجي لا تمنح قبولًا. ولا تعتمد البوابة إلا سجل موافقة موثقًا يمر عبر سياق موثوق منفصل، مع مطابقة نطاق الموافقة. والتغييرات عالية الأثر تتطلب موافقة بشرية إضافية خاصة بالأثر العالي.

## قرار الإغلاق الآمن

`ADMISSION_DENIED`

الحالات غير المعروفة أو الأدلة غير المكتملة أو الانحرافات الحرجة تُرفض افتراضيًا مع حفظ الأدلة وعدم تنفيذ أي تغيير.

## بوابات القبول

تشمل البوابات: سلامة خط الأساس، الضمان التشغيلي، خلو الحالة من الانحراف الحرج، اكتمال الأدلة، تعريف نطاق التغيير، نجاح الاختبارات، سلامة الإصدار الحالي، جاهزية الرجوع، سلامة المسارات والعقود، التخزين، سياسة الاحتفاظ، خطة الحزم، خطة النشر، وخطة التحقق بعد النشر.

## الحدود

هذه الطبقة:

- لا تنشر إلى الإنتاج.
- لا تعيد تشغيل الخدمات.
- لا تثبت الحزم.
- لا تنظف الملفات أو الإصدارات.
- لا تنفذ تعديلًا خارجيًا ذاتيًا.
- لا تدعي علم المستقبل أو الغيب.
- تصدر قرارًا توثيقيًا للاستخدام اليدوي ضمن نطاق الموافقة فقط.

## التكامل

تعتمد البوابة على:

`SHEIKHA_PRODUCTION_RISK_TO_SAFE_GOVERNANCE_V1`

وتمرر حالة الانحراف إلى طبقة تحويل الخطر إلى مسار آمن. ولا يصبح المرشح مؤهلًا للموافقة البشرية إلا عندما تعيد طبقة الخطر حالة إنتاجية آمنة وغير محجوبة.

## التشغيل المحلي

```bash
npm run ops:production-change-admission:v1
```


## فصل سلامة الإصدار الحالي عن قبول التغيير

حالة `CURRENT_PRODUCTION_SAFE` تعني أن الإصدار الحالي المتحقق يمكنه الاستمرار. وقد يبقى `promotionBlocked=true` لأن أي ترقية جديدة ما زالت تحتاج بوابات القبول والموافقة البشرية. لذلك تفصل هذه البوابة بين سلامة الإصدار العامل وبين السماح بتغيير جديد، ولا تستخدم حجب الترقية دليلًا على أن الإصدار الحالي غير آمن.
