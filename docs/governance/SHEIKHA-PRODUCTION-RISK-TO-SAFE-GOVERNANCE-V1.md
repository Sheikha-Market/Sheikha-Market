# Sheikha Production Risk-to-Safe Governance V1

## الغرض

هذه الطبقة تمنع انتقال أي حالة تشغيلية خطرة إلى مسار إنتاج جديد. عند اكتشاف خطر، لا تنفذ الطبقة تغييرًا خارجيًا، بل توقف الترقية الخطرة، وتحفظ الأدلة، وتبني خطة إصلاح آمنة، وتطلب التحقق والموافقة البشرية قبل اعتماد أي مرشح إنتاجي جديد.

المرجع الحاكم: الكتاب والسنة، وقاعدة لا ضرر ولا ضرار، والصدق والأمانة والتحقق قبل التنفيذ.

## قاعدة القرار

- `NO_OPERATIONAL_DRIFT`: استمرار الإصدار الحالي المتحقق مع بقاء أي ترقية جديدة محجوبة حتى موافقة مستقلة.
- `HEALTHY_RUNTIME_CHURN`: استمرار الإصدار الحالي مع التسجيل والمراقبة.
- `DEPLOYMENT_DRIFT`: حجز آمن ومنع أي ترقية جديدة حتى استعادة تطابق الإصدار والـManifest.
- `SERVICE_DRIFT`: حجز آمن، حفظ الأدلة، وإعداد خطة إصلاح أو رجوع متحققة.
- `STORAGE_RISK`: منع توسعة الإصدارات، وعدم السماح بالتنظيف دون نسخة مستقلة ونطاق صريح.
- `RETENTION_DRIFT`: منع التنظيف وتقاعد الإصدارات حتى استعادة سياسة الاحتفاظ.
- `MULTIPLE_CRITICAL_DRIFT_CONDITIONS`: حجز آمن شامل وترتيب الاستعادة تحت سلطة بشرية.
- أي تصنيف غير معروف: حجز آمن افتراضي.

## خط الإنتاج الآمن

1. الكشف.
2. تجميد الترقية الخطرة.
3. حفظ الأدلة.
4. الاحتواء.
5. إعداد خطة الإصلاح.
6. التحقق من الإصلاح.
7. طلب الموافقة البشرية.
8. ترقية المرشح الآمن المتحقق فقط.
9. الاحتفاظ بإصدار الرجوع.
10. المراقبة.

## الحدود الفنية

- لا تنفيذ خارجي.
- لا نشر إنتاجي.
- لا إعادة تشغيل.
- لا تثبيت حزم.
- لا تنظيف.
- الاحتفاظ بوضع `DENY_BY_DEFAULT`.
- القرار عالي الأثر للبشر.
- لا ادعاء معرفة الغيب أو التنبؤ بالمستقبل.
