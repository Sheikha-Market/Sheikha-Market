# شيخة — حوكمة النواة الموحدة للوكلاء — الإصدار الأول

الاسم المعماري: `SHEIKHA Infinite Agent Kernel`.

التاريخ: 2026-10-22. حالة النموذج الوصفي المحلي: `IMPLEMENTED / VERIFIED_LOCAL_TESTS`. حالة التكامل الإنتاجي والقدرات الخارجية: `DECLARED / REVIEW_REQUIRED`. هذه وثيقة تصميم وحوكمة؛ لا تنشئ عملية تشغيل أو موارد، ولا تمنح تفويضًا بالنشر أو تشغيل وكلاء مستقلين.

## المرجعية والنطاق

تتبع الوثيقة [سجل المصدر الرسمي](../registry/ROOT-SOURCE-OF-TRUTH.md)، و[الميثاق التأسيسي](SHEIKHA-FOUNDATIONAL-CHARTER-V1.md)، و[حوكمة المساعدين](../canonical/environment/SHEIKHA-ASSISTANT-GOVERNANCE.md). توحد عقد الوكيل وتوثق نموذجه الوصفي المحلي؛ لا تستبدل نواة التطبيق أو الإقلاع أو مصادر الحوكمة الموجودة. عند تعارض التصورات مع التفويض الفعلي أو حدود المضيف تُمنع العملية المتأثرة حتى تتضح الحدود.

مرجعية القيم: القرآن الكريم والسنة النبوية الصحيحة، والصدق والعدل والأمانة وحفظ الحقوق ومنع الربا والغرر والغش والضرر. تُترجم القيم إلى سياسات بشرية قابلة للمراجعة؛ الوثيقة ليست فتوى أو شهادة امتثال آلية، ولا تجعل الله سبحانه وتعالى كيانًا تقنيًا أو عقدة برمجية.

## القانون الموحد: بوت يجمع واجهات المنظومة

«بوت = آلة = مصنع = تعلم = هيكل = بنية فوقية وتحتية = منظومة = OS = حوسبة = كيرنل = مانيفست = توأم رقمي» تعني توحيد وصف هذه الأدوار وربطها داخل عقد واحد. لا تعني أن كائنًا برمجيًا صار جهازًا ماديًا أو نظام تشغيل مستقلًا أو نموذجًا مدربًا بمجرد تسميته.

| واجهة الوكيل | المسؤولية المقترحة | الدليل المطلوب لإثبات القدرة |
| --- | --- | --- |
| الآلة والحوسبة | طلب CPU والذاكرة والتخزين عبر محول مرخص | مورد محدد، حصة، قياس واختبار محول |
| المصنع والإنتاج | تحويل مدخلات معروفة إلى مخرجات قابلة للفحص | مهمة محدودة، اعتماد مدخلات، معايير قبول وسجل نتيجة |
| التعلم وAI | استدعاء نموذج أو استرجاع معرفة أو اقتراح تحسين | مزود ونموذج محددان، اختبار جودة وبيانات مأذون بها؛ الاستدعاء وحده لا يثبت تدريبًا |
| الهيكل والتنظيم | مهام وملكية وتفويض وإشراف على الأبناء | سجل هوية ومسؤول بشري وصلاحيات فعلية |
| البنية التحتية | محولات للنواة والعتاد والحاويات والتخزين | أدلة تشغيل لكل بيئة؛ لا وصول مباشر للعتاد من الوكيل |
| البنية الفوقية | إدارة ومحاسبة وأصول وسير عمل | تكامل مختبر ومفوض مع النظام المختص |
| OS والكيرنل | الاستفادة من خدمات التشغيل الموجودة | عقد تكامل واختبارات؛ الوكيل ليس بديلًا تلقائيًا لنواة النظام |
| المانيفست والتوأم الرقمي | وصف الأصول والقدرات والحالة وعلاقتها بمورد مادي أو رقمي | معرف الأصل، المصدر، توقيت القياس، حداثته وجودته؛ غياب الرابط يعني توأمًا وصفيًا فقط |

كل وكيل يحمل العقد الكامل لهذه الواجهات، وإصدار السياسة ومراجع المحولات؛ في النموذج الحالي تُوصف القدرات بـ`PLANNED` أو `LOCAL_SIMULATION` مع `executionSupported: false`. يجب أن يرفض أي محول مستقبلي تنفيذ قدرة غير متاحة. اكتمال العقد لا يلزم تحميل كل المحركات أو نسخ كل البيانات أو منح كل الصلاحيات لكل وكيل.

## متطلبات عقد التشغيل الإنتاجي المقترح

يجب أن يحدد المانيفست: `agentId` و`parentId` والمالك البشري والغرض، وإصدار النواة والسياسة وبصمتهما، والقدرات المطلوبة والممنوحة، ومراجع الأدوات والمصادر، وحالة التوأم وأدلتها، والميزانية والحصص، ووقت انتهاء التفويض، ومعايير الإنجاز والإيقاف والرجوع، ومرجع سجل التدقيق.

الصلاحيات الممنوحة هي تقاطع تفويض المستخدم وحدود المضيف وسياسة المهمة وقائمة الأدوات. مراجع الأسرار لا تحتوي قيمها؛ لا تُنسخ مفاتيح أو جلسات أو موافقات بين الوكلاء. لا يثبت حقل مثل `approved: true` أو اسم الوكيل وجود موافقة فعلية.

## التسلسل: 100 مدير ثم توسع محكوم

طبقات الإدارة التالية منفصلة عن أسماء مستويات الحوكمة `L0/L1/L2` الواردة لاحقًا:

| طبقة الإدارة | التصور العددي | الحالة |
| --- | --- | --- |
| منسق رئيسي | 1 | دور مقترح تحت مسؤولية بشرية |
| مديرون | حتى 100 | سقف تصميمي، لا طلب تشغيل |
| فرق | حتى 10,000 عند 100 تابع لكل مدير | مثال حسابي مشروط بالحصص |
| مهام أو وحدات فرعية | حتى 1,000,000 عند تكرار معامل 100 | مثال حسابي، لا سعة مثبتة |

«لانهائي» اسم للرؤية القابلة للامتداد عبر إصدارات؛ كل تشغيل محدود. تُفصل أعداد التعريفات المسجلة عن العمليات النشطة والطلبات المتزامنة. لا تُنشأ مليون عملية لتجسيد مليون تعريف؛ يمر العمل عبر طوابير وعمال محدودين عند اعتماد تنفيذ مناسب.

قبل أي إنشاء يجب ضبط حدود صريحة: إجمالي الوكلاء النشطين، والتزامن، والعمق، وعدد الأبناء، وعدد المهام والمحاولات، ومدة التشغيل، وطلبات الشبكة والنماذج، والرموز، والتكلفة، وCPU والذاكرة والتخزين. الحد غير المحدد لا يعني السماح. تُحجز حصة الابن من ميزانية المهمة المشتركة لمنع مضاعفتها مع كل جيل.

تشغيل ابن خارج المحاكاة يحتاج تفويضًا صريحًا قابلًا للتحقق وميزانية متاحة وهوية فريدة وتسجيلًا قبل التشغيل. يرث الابن السياسة بحدود مساوية أو أشد، ولا يوسع صلاحيات الأب، ولا يستدعي نفسه دوريًا بلا حد. يجب أن يوقف إلغاء المهمة أو انتهاء التفويض قبول أعمال جديدة ويتسلسل إلى الأبناء، مع إنهاء آمن للأعمال الجارية. يُمنع التكرار غير المقصود بمعرف مهمة وآلية منع الازدواج. هذه شروط للتنفيذ الإنتاجي اللاحق؛ تسجيل كائن محلي في النموذج لا يشغّل عاملًا أو موردًا خارجيًا.

## مستويات القرار — Fail-Closed

| المستوى | القاعدة | التطبيق |
| --- | --- | --- |
| `L0` المرجعية | القرآن والسنة مرجعية ثابتة للمشروع؛ لا ربا ولا غرر ولا ضرر | لا يعدل الوكيل المرجعية أو يستقل بالفتوى. صياغة القواعد التنفيذية وتفسيرها يحتاجان مراجعة بشرية مؤهلة وإصدارًا موثقًا |
| `L1` الأثر الحساس | البنية والنظام والقانون والعقود والنشر والصلاحيات والأجهزة بموافقة محددة | يشمل IAM وDNS والجدار الناري والمنافذ الخارجية والأسرار والمدفوعات وأوزان النماذج وتشغيل الموارد السحابية أو الأجهزة وإعادة تشغيل خدمات الإنتاج. الإذن مقيد بالهدف والبيئة والفعل والمدة ولا ينتقل بين البيئات |
| `L2` الإصلاح المحلي الآمن | عمل محلي قابل للرجوع ضمن طلب المستخدم وملكية واضحة | فحص الملفات والتبعيات، نسخ مكونات محلية ناقصة إلى سياق بناء معزول، وفحص صحة محلي محدود؛ دون ترقية للإنتاج أو توسيع صلاحيات |

عند غياب دليل أو تفويض أو حصة أو سجل تدقيق صالح تُرفض العملية المتأثرة مع سبب واضح. لا يصنف الوكيل عملًا حساسًا على أنه `L2` لتجاوز `L1`، ولا يمنح هذا المستند صلاحيات جديدة. التفويض الصريح الموجود للنطاق نفسه يُراعى؛ لا تُطلب الموافقة مجددًا لمجرد تغيير اسم الوكيل.

تنظيف منفذ أو حاوية يكون فقط لمورد محلي معروف الملكية ومحدد ضمن المهمة، بعد التحقق من أثره؛ حذف جميع حاويات المستخدم ليس إصلاحًا محليًا آمنًا. إنشاء stub جائز لتجربة معزولة فقط عندما يعيد «غير متاح» أو رفضًا صريحًا؛ لا يحل محل تبعية إنتاجية إلزامية ولا يعرض صحة زائفة أو يتجاوز بوابة أمنية.

## صلة التصميم بالمكونات الحالية

فحص الملفات بتاريخ الوثيقة أظهر المراجع التالية دون تشغيلها أو إثبات جاهزيتها الإنتاجية:

| المكون الموجود | صلته بالتصميم وحدود الدليل |
| --- | --- |
| `bare-metal/kernel/entry/sheikha_kernel.c` | مرجع طبقة الإقلاع؛ مجرد وجود المصدر لا يثبت إقلاع جهاز فعلي. تُراعى حدود `bare-metal/governance/README.md` |
| `runtime/kernel/sheikha-runtime-kernel.js` | نواة تطبيق Node؛ ضبط أعلام `ai` و`neural` إلى `true` داخل المصدر لا يثبت اتصال نموذج أو تعلمًا أو شبكة عصبية حية |
| `runtime/sheikha-os-enterprise-federation/` | اتحاد وصفي وفحص أدلة؛ مصدره يعلن `productionReady: false` واحتياج الأدلة |
| `core/enterprise/sheikha-enterprise-control-tower-v1.js` | جمع مؤشرات العملية والمضيف وGit؛ لا يثبت وحده تشغيل المحاسبة أو الأصول أو المصانع |

أضيف [النموذج المحلي للنواة](../../runtime/sheikha-infinite-agent/v1/sheikha-infinite-agent-kernel.js) مع [اختباراته](../../tests/sheikha-infinite-agent-kernel.test.cjs) في هذه المهمة. يصدّر `SheikhaInfiniteAgentKernel` و`SheikhaBot` والاسم المستعار `SheikhaInfiniteAgent`؛ جميعها كائنات وصفية داخل ذاكرة العملية. لا يستدعي النموذج ملفات أو شبكة أو shell أو مؤقتات أو محولات أو نماذج AI، ولا ينشئ عملية خلفية أو موردًا عند الاستيراد.

الأعداد المنقولة مثل `1680 FABRIC` و`567 RAG` و`5 وكلاء` تحتاج جردًا مؤرخًا يميز المسجل والمهيأ والمختبر والنشط؛ لم تتحقق هذه الوثيقة منها، ولا يحولها وجود النموذج إلى شبكة متصلة.

## واجهة النموذج المحلي وحدوده المتحققة

| الواجهة | السلوك المحلي |
| --- | --- |
| `registerBot(descriptor)` | تسجيل أصل وصفي بهوية فريدة بعد فحص المدخلات وحدود السجل |
| `getBot(id)` و`getChildren(id)` | قراءة كائن أو قائمة أبناء مجمدة؛ السجل الداخلي خاص بالنواة |
| `spawnChild(parentId, descriptor)` | إنشاء كائن ابن بطلب صريح، بعد فحص العمق وعدد الأبناء والحصة المركزية |
| `iterateChildren(parentId, {count, template})` | مؤشر محدود وكسول؛ لا تسجيل قبل `next()`، ويتوقف عند نهاية العدد أو `return()` أو فشل حد من الحدود |
| `evaluateOperation(botId, operation)` | رفض تعديل `L0`، ورفض `L1` بطلب تفويض خارجي دون دعم تنفيذ، ورفض الأعمال المجهولة؛ يمنع تمرير مستوى مزيف لتخفيض التصنيف |
| `planLocalRepair(botId, plan)` | خطة وصفية من قائمة سماح محددة فقط؛ `executed: false` و`executionSupported: false` |
| `statistics()` | عدادات التسجيل والحصة المتبقية؛ ليست قياسًا لنشاط شبكة أو عمال فعليين |

لكل كائن 14 واجهة وصفية: `machine` و`factory` و`aiLearning` و`structure` و`superstructure` و`substructure` و`system` و`os` و`compute` و`kernel` و`bareMetal` و`interfaces` و`manifest` و`digitalTwin`. التوأم يدعم مرجعًا ماديًا ورقميًا لكل من `partyA` و`partyB`، ويظل `verified: false`. المانيفست مرجع وصفي محدود، وليس تصريح تشغيل أو ملف اعتماد.

يشترك الأب والابن في المخطط والسياسة المجمدين. لا تُنسخ تلقائيًا مراجع محولات الأب أو بيانات توأمه أو مانيفسته أو صلاحياته؛ قالب الابن المقدم صراحة يُفحص ويُثبت قبل استخدام المؤشر. لا يوجد تنفيذ للمحولات حتى لو احتوى الوصف على مرجع محول.

| الحد | الافتراضي | السقف المقبول في النموذج |
| --- | --- | --- |
| `maxAgents` | 1,000 | 100,000 |
| `maxDepth` | 8 | 64 |
| `maxChildren` | 100 | 10,000 |
| `totalBudget` | 1,000 | 100,000 |

`totalBudget` عداد مركزي لوحدات تسجيل الكائنات، وحدة واحدة لكل تسجيل ناجح، بما فيها الأصول. ليس ميزانية مالية أو رموز نموذج أو حصة CPU/ذاكرة. يُستهلك عند التسجيل الفعلي، ولا تُخصص حصة مستقلة لكل جيل أو مؤشر. تتشارك كل الأصول والأبناء داخل نسخة النواة الحدود نفسها. ترفض الحدود الكسور والقيم السالبة و`NaN` و`Infinity`؛ الصفر مسموح للعمق والأبناء فقط. لا يثبت سقف المدخلات قدرة المضيف على بلوغه بأمان.

نطاق هذا الإصدار لا يشمل تفويضًا إنتاجيًا أو تحقق هوية خارجيًا، أو انتهاء تفويض وإلغاءً متسلسلًا، أو صف مهام وعمالًا، أو حصص موارد فعلية، أو تدريبًا واتصال نماذج، أو تنفيذ إصلاح، أو تخزينًا دائمًا وسجل تدقيق. تبقى هذه متطلبات للتكامل اللاحق؛ غيابها لا يتحول إلى سماح بتنفيذ خارجي.

## بوابة التنفيذ اللاحق والقياس

قبل اعتماد runtime جديد: راجع واجهات المكونات القائمة لتجنب الازدواج، وحدد مسؤولًا وحدود تكلفة وموارد، واختبر العقد ورفض الصلاحيات والميزانيات والإلغاء والعزل، ثم نفذ تجربة محلية محدودة. تتطلب ترقية الأثر إلى `L1` تفويضًا بالنطاق المعين وخطة رجوع وأدلة القبول.

يجب أن يميز تقرير الحالة بين `DECLARED` و`IMPLEMENTED` و`VERIFIED`، ويعرض نطاق التحقق وتاريخه وبيئته. يسجل كل قرار: هوية المهمة والوكيل، والفعل والهدف، وبصمة السياسة، ومرجع التفويض، والقرار والسبب، والموارد المحجوزة والمستهلكة، والنتيجة ومرجع الدليل، دون أسرار.

كتابة هذه الوثيقة لا تفعّل شبكة أو تكاثرًا أو تدريبًا، ولا تثبت اتصال Cloud Run أو VPS أو Cloud Build. تبقى الأدلة التشغيلية مستقلة عن الوصف المعماري؛ نجاح بناء صورة وحده لا يثبت نجاح النشر أو صحة التطبيق.
