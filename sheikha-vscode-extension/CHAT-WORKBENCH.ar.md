# مركز عمل شات شيخة

الإصدار المحلي: 1.0.139. هذا دليل وظائف منفذة وحدود تشغيلها، وليس اعتمادًا تجاريًا للمنظومة كاملة.

## مصدر التقرير وموصل VS Code

«اكتب تقرير» يتبع آخر جواب مسجل في الشات، ولا يستبدله فتح فهرس بيانات أو مكتبة في اللوحة الجانبية. قبل وجود جواب في الجلسة، يستخدم آخر نتيجة محلية متاحة مع التصريح بمصدرها. التقرير مشتق ولا يصبح مصدرًا لنفسه.
زر «اختيار مصدر التقرير» يتيح اختيار نتيجة أخرى صراحة. يظهر اسم المصدر الحالي في اللوحة؛ وصول جواب جديد إلى المحادثة يعيد الاختيار للمصدر الأحدث. مسح المحادثة يمسح الاختيار والمصادر المؤقتة.

«فهرس أوامر VS Code» يقرأ الأوامر العامة المسجلة فعليًا من مضيف الإضافة ويعرض JSON كاملًا محدودًا بـ30000 أمر. لا يشمل واجهات داخلية غير منشورة، ولا يثبت أن كل إضافة مرخصة أو كل خلفية تعمل. رقم 39 يخص أوامر شيخة وليس إجمالي أدوات VS Code.
«استخدام أدوات VS Code» يفتح اختيارًا أصليًا للأدوات المعتمدة: المستكشف، البحث، Git، الإضافات، لوحة التصحيح، التشخيصات والمخرجات ولوحة الأوامر. فتح لوحة التصحيح ليس تشغيلًا للمصحح، وفتح Git ليس push.
تنسيق الملف وتنظيم استيراداته يتطلبان موافقة أصلية، ومساحة موثوقة، وثبات الملف النشط وإصداره حتى التنفيذ. قد يستدعيان مزود تنسيق أو لغة مثبتًا؛ لا ندعي تدقيق سلوكه الخارجي. لا حفظ تلقائي من الموصل.
المهام والطرفية والتصحيح الفعلي وأوامر الأطراف الأخرى تبقى `NATIVE_PALETTE_ONLY`: تختارها بنفسك داخل لوحة أوامر VS Code؛ لا يشغلها الشات أو النموذج بالنيابة عنك. الموصل لا يقبل command ID أو وسائط تنفيذ من Webview.
إيصال الأمر يثبت عودة استدعاء VS Code فقط، لا تحقق نتيجة الأداة أو جاهزية المنتج.

## الهيكل والمعمارية

```text
مالك المنظومة + مراجعة الحوكمة والصلاحيات
  |
  +-- الذكاء الصناعي: بوابة النماذج -> Foundry -> تقييم وسجل أوزان
  +-- الحاسب: Runtime -> الموارد -> الرصد والتعافي
  +-- الشات: الطلب -> السياق المختار -> أدوات -> رد ومصدر
  +-- التطوير: متطلبات -> Git -> اختبارات -> مراجعة إصدار
  +-- البرمجة: لغة شيخة -> SDK/CLI/MCP -> عقود واختبارات
  |
طلب محدد -> تفويض -> تنفيذ محدود -> دليل -> مراجعة -> تسليم
```

هذا مخطط مسؤوليات وتكامل. تسجيل الأوامر لا يثبت اتصال Foundry أو جودة نموذج أو تشغيل كل الخلفيات.
لكل إدارة في الدليل المضمّن: مسؤول، مكونات، مدخلات، مخرجات، ضابط تنفيذ ومؤشرات أداء مقترحة.
مرجعية المشروع القيمية الكتاب والسنة؛ التفويض تقني ولا يمثل سلطة شرعية أو فتوى آلية.

## الاستخدام

- «الهيكل والمعمارية» ينتج مستندًا فعليًا في قائمة المخرجات.
- «تشغيل المراجعة المحلية» يفحص تسجيل أدوات المجالات الخمسة، موارد النظام وتشخيصات VS Code.
- يمكن كتابة «هيكل شيخة» أو «راجع أدوات شيخة» مباشرة في الشات لتنفيذ المسار المحلي دون استدعاء نموذج.
- «تكامل شيخة» أو «مستجدات شيخة» أو زر «فحص التكامل والمستجدات» يفحص بصمات مصادر 18 مكوّنًا في مساحة العمل المحلية الموثوقة. عند فتح عدة مجلدات يطلب اختيار واحد في نافذة VS Code الأصلية.
- التقدم يتغير مع أحداث التنفيذ. فحوص الإدارات أدوات محلية؛ دورة المهام المنظمة تضيف وكلاء نموذج اختياريين كما هو موضح أدناه.
- المخرجات: فتح في المحرر، نسخ إلى الحافظة، تصدير اختياري، أو وضع في المسودة دون إرسال تلقائي.
- زر المسح يزيل ذاكرة الجلسة عند المزود، المخرجات وسجل اللوحة والمسودة؛ لا يحذف الملفات التي صدّرتها سابقًا ولا الحافظة أو سجلات خدمات خارجية.

## التقارير والأزرار المصححة

«اكتب تقرير» وDOC يتبعان المصدر المختار صراحة، وإلا آخر جواب في المحادثة، وإلا آخر نتيجة محلية عند عدم وجود جواب. يعرض التقرير وقت المصدر وبصمة نصه، ولا يفترض أصفارًا عند غياب القياسات أو يجمع تغييرات Git والتحذيرات كمؤشر جودة. تكرار التقرير لا يضع التقرير داخل نفسه؛ المسح يمسح مصدره. لصق مخرج سابق كاملًا دون تعليمة يطلب تحديد المطلوب بدل تشغيل كلمات داخل المستند.

SUM المجرد يطلب السؤال والقيم والوحدات. PKG يقرأ `runtime/distribution/v2/sheikha-universal-delivery-v2-report.json` ويفحص أحجام الحزم وبصماتها الآن، مع فصل تاريخ التقرير المحفوظ. ليس خدمة شحن، ولا يشغل الحزم أو يثبت توقيعها أو جاهزيتها التجارية. حد القراءة: 32 سجلًا، 64 MiB للحزمة، 128 MiB للحزم مجتمعة، و5 MiB للتقرير. تُرفض المسارات الخارجة والروابط والملفات غير العادية.

## جسر البيانات والحساب

يتصل عند طلب المستخدم فقط بـ`http://127.0.0.1:8142` بمسارات ثابتة، وحد استجابة 1 MiB، ومهلة خمس ثوانٍ لكل طلب، دون تحويلات أو مضيف بديل. الفشل ظاهر، ولا يستخدم نموذجًا بديلًا أو يعرض نجاحًا قديمًا.

- «حالة البيانات والمستجدات»: لقطة وأعداد، دون محتويات السجلات الخاصة في التقرير التجميعي.
- «أدوات البيانات والحساب»: اختيار أصلي في VS Code، ثم مدخلات JSON إن لزمت. القيم المعروضة أمثلة قابلة للتعديل، وليست قياسات للمشروع.
- «فتح مساحة البيانات»: اختيار `/data` أو `/news` أو `/chat` في التطبيق المستقل الموجود. أزرار الحفظ داخل التطبيق تحكمها موافقاته الخاصة، وليست مفوضة من الجسر.

الأدوات الـ16: STATUS، NEWS_INBOX، DATA_CATALOG، DATA_METRICS، DATA_SEARCH، DOMAIN_PLAN، EFFECT، INDUSTRIAL_BALANCE، PROOF_REVIEW، DATA_PREVIEW، NEWS_PREVIEW، ARCHITECTURE، FILES، FILES_INDEX، GITHUB_SNAPSHOT، MEMORY_READ.

المعاينات لا تحفظ أو تعتمد، والحساب لا يثبت السببية، ولقطة GitHub ليست فحص CI حيًا. رصد الإصدارات الخارجي OFFICIAL_RELEASES غير متاح في الجسر، وكذلك البحث العام وGitHub الخاص والمكتبة البعيدة وتنفيذ الشيفرة والوكلاء وحفظ ذاكرة المحادثة التي تحتاج إعدادًا مستقلًا.

الـ39 أمرًا في VS Code منفصلة عن أدوات الخدمة الـ16؛ ليست 55 خدمة إنتاجية. الخدمة حتمية وليست LLM. المصادقة محلية لمستخدم نظام التشغيل، وليست عزل عملاء متعددين. لا حفظ تلقائي أو إرسال مخرجات للنموذج أو تدريب عليها. بيانات الخدمة استجابة محلية وليست شهادة مستقلة للجاهزية.

## التكامل ورصد التغيرات

```text
مساحة عمل موثوقة -> مسارات مضمّنة محددة -> قراءة مقيدة وبصمات SHA-256
  -> أول لقطة كخط أساس -> مقارنة اللقطات -> مستجد يحتاج مراجعة
  -> تقرير خاص -> فتح / نسخ / تصدير باختيار المستخدم
```

يرتبط الفهرس بمسارات Git وVisual وNode وDocker وStudio وModel Hub وFoundry واللغة وSDK وCLI وMCP والتجارة المستخدمة في مفتش المستودعات السابق. أضيفت مصادر Runtime وLLM/التدريب وCloud والثقة وFirmware/UEFI/Secure Boot والجنات والأمن. يوجد اختبار تطابق للمسارات المشتركة.

الحالة «المصدر موجود» ليست «الخدمة تعمل»: لا require أو تنفيذ لملف في مساحة العمل، ولا اتصال بالخدمات، ولا قراءة أوزان أو `.env` أو تشغيل أوامر. القراءة غير ذرية، محدودة بـ5 MiB لكل ملف، وتستبعد الروابط الرمزية والصلبة والملفات غير العادية. لا تقرأ الملفات غير المحفوظة في المحرر.

أول فحص لا ينتج تنبيه تغيير، والفحص المكرر بالمحتوى نفسه لا يكرر التنبيه. تغير البصمة أو فقدان الدليل أو عودته يُسجل للمراجعة، دون نسبة السبب إلى شخص أو إثبات الأثر. يحتفظ السجل بآخر 20 مستجدًا في الجلسة فقط. تغيير مساحة العمل يعيد خط الأساس؛ المسح يزيله مع التقارير.

الرصد يدوي عند الطلب فقط، لا خدمة أخبار ساعية أو بحث خارجي. ادعاءات CI والإصدارات في المستندات المرفقة ليست أدلة حية ولا تُعيد تشغيل مراحل تاريخية أو تفوض Merge/Release.

أضيفت إلى الدليل عقود مراجعة لثمانية مجالات: الأسباب، الآثار، البراهين، التراث، التعلم والتذكير، بر الوالدين، المستجدات والسلاسل المؤسسية. حالتها `DESIGN_REVIEW_REQUIRED` وليست محركات تجارية مُنفذة.

تقارير الأوامر المحلية مستبعدة من سجل المحادثة الذي يُمرَّر لاحقًا لبوابة النموذج. النسخ أو التصدير صريح؛ النقل إلى المسودة لا يرسلها. إرسال المسودة لاحقًا اختيار مستقل للمستخدم يخضع لمسار الشات ومزوده.

## التشغيل الآمن

النص الذي ينتجه النموذج لا يشغّل إجراءات اللوحة تلقائيًا. الرسائل تقبل قائمة إجراءات ثابتة، لا أوامر shell أو مسارات أو مضيفين يرسلهم Webview.
تُرفض دورات العمل المتداخلة، ويظل إيقاف الدورة وفتح تفاصيلها متاحين أثناء العمل. المخرجات محدودة بـ12 مخرجًا و65536 وحدة نصية JavaScript لكل مخرج، والأحداث العامة بـ24، والمصادر بـ16.
يُنشأ التصدير بصلاحية 600 في ملف Markdown أو JSON جديد يختاره المستخدم؛ لا استبدال لملف موجود ولا اتباع لرابط رمزي نهائي.
لا حفظ دائم تلقائي، لا تحميل نموذج، لا تعديل TPM أو Firmware، لا نشر أو دفع مالي.
التعديل والتثبيت والتدريب والنشر والمزامنة الخارجية تبقى ضمن مسارات تفويضها السابقة، ولا تفتحها هذه الواجهة.

## محرك الفحص والوكلاء والموصلات

المسار: هدف صريح، مساحة عمل موثوقة، اختيار أدوات فقط أو أدوات ونموذج، خطة JSON، فحص الموصلات، تنفيذ محدود، تحقق النتيجة، ثم تقرير إغلاق النطاق.
ابدأ من «ابدأ مهمة منظمة» أو أمري «وكيل محكوم» و«مهمة وكيل». اختيار النموذج وموافقته نافذتان أصليتان من VS Code؛ لا يقبل Webview عنوان مزود أو نص أمر تنفيذي.

حد الدورة ست مهام وعاملان متزامنان، مع طلب نموذج واحد فقط في اللحظة. حد المهمة 90 ثانية، وطلب النموذج 75 ثانية و512 رمز إخراج وسياق 4096.
الحالات: QUEUED ثم INSPECTING/WORKING، ثم COMPLETED أو REVIEW_REQUIRED أو FAILED أو TIMED_OUT أو CANCELLED.
Started working وUpdated وWorked ناتجة من أحداث المحرك؛ المؤقت يقيس الزمن فقط ولا يختلق تقدمًا أو نجاحًا. سجل الدورة محدود بـ128 حدثًا، وعرض المحادثة بآخر ثلاث دورات.
تفاصيل المهمة تفتح JSON في المحرر: المنفذ، الهدف، الأوقات، النتيجة المقبولة وبصمتها، أو سبب الفشل الآمن. بصمة النتيجة ليست تصديقًا مستقلًا.
«إيقاف المهام» يمنع جدولة المتبقي ويقطع انتظار النقل ويرفض الردود المتأخرة. قد تستمر قراءة بدأت أو حساب لدى الخدمة؛ لا تراجع تلقائيًا ولا وعد بإيقاف GPU لحظيًا.

الموصل لا يستخدم إلا `/api/tags` و`/api/show` و`/api/chat` على `127.0.0.1:11434`، ويرفض التحويلات والنماذج السحابية وتغير البصمة المختارة. هذه قيود اتصال الإضافة وليست شهادة عزل شبكة لخدمة Ollama نفسها.
المدخل للنموذج هو الهدف المدخل صراحة وتعليمات ثابتة، دون ملفات أو نتائج الأدوات أو المحادثة السابقة. يُطلب JSON بنقاط محدودة، ويُرفض الرد غير المطابق أو المبتور أو المحتوي على طلب تنفيذ أدوات. لا يُعرض حقل التفكير.
كل مسودة تبقى REVIEW_REQUIRED؛ سلامة JSON لا تضمن صحة الفكرة أو تحسن الجودة. فشل قالب محلي لا يطلق إعادة محاولة أو تحويلًا لنموذج آخر تلقائيًا.
مرجع الطلب: [Ollama Chat API](https://docs.ollama.com/api/chat).

## القياس والإدارة التشغيلية

مسؤول كل مجال يحدد خط أساس وهدفًا وزمن مراجعة ومراجعًا مستقلًا للمؤشرات قبل تسويقها كوعود خدمة.
أمثلة المؤشرات: تكلفة المهمة الناجحة للذكاء، توافر الخدمة للحاسب، زمن أول استجابة للشات، انحدارات الإصدار للتطوير، وتوافق العقود للبرمجة.
المقاييس المقاسة الآن في المراجعة المحلية هي تسجيل الأوامر، موارد الجهاز وأعداد التشخيصات فقط؛ البقية أهداف قياس لا أرقام نجاح مختلقة.

## الاختبار والتثبيت

### الرصد والفرص في 1.0.140

قسم «الرصد والفرص» يجمع بيانات عامة من ثمانية مصادر ثابتة بعد موافقة أصلية، ويحفظها في `~/.local/share/sheikha-opportunity-watch/v1` بصلاحيات 700/600. لا تُرسل المحادثة أو الملفات ولا تُنزّل أوزان. «رصد كل ساعة» يعمل داخل جلسة الإضافة فقط؛ «إيقاف الرصد» يقطع الطلب الجاري ويمنع حفظ نتيجته المتأخرة. مسح المحادثة يوقف المؤقت ولا يحذف أرشيف الفرص.

«تقرير الإدارة» خاص، و«نشرة المستخدمين» لا تضم إلا عنوانًا وملخصًا اعتمدتهما في نافذة أصلية. تغيّر المصدر يبطل النسخة المعتمدة، و«سحب من النشرة» يلغيها. النشرة مسودة محلية غير مرسلة؛ البريد وWebhook ولوحة العملاء تحتاج هوية ومستلمين وموصلًا مستقلًا. القنوات الجاهزة موضحة في «قنوات التقارير».

«اهتماماتي» تضبط المجالات والجديد/الجميع. «تقييم الفائدة» يسجل رأيك المحلي ويحسب معدل الفائدة؛ ليس تدريبًا للنموذج. «تقييم فرصة» يطلب قيم الملاءمة والمنفعة والقابلية والمخاطر من 0 إلى 5 وسببها واختبار القبول. حساب العائد اختياري من افتراضاتك، وليس ربحًا مضمونًا. «تأهيل الأوزان» مسار مراجعة للترخيص والبيانات والموارد لا يملك صلاحية تنفيذ التدريب.

«استيراد مرشحات» يقبل JSON فيه `records` بعناصر `title, summary, category, sourceUrl, publishedAt`؛ المجالات `TECHNOLOGY, COMMERCIAL, CHARITABLE, SCIENTIFIC, NONCOMMERCIAL`، والتاريخ UTC كامل أو null عند غيابه. يدعم كذلك ملف صندوق الأخبار `SHEIKHA_NEWS_INBOX_V1`. يعرض معاينة ويطلب حفظًا خاصًا؛ لا يعتمد أو ينشر تلقائيًا. الرصد الآلي الحالي تقني/علمي؛ مصادر المناقصات والمنح والقطاعات الأخرى تحتاج تأهيلًا مستقلًا.

حد السجل 500 مادة/4 MiB، وعرض المادة 30 يومًا؛ انتهاء العرض ليس حذفًا للأرشيف. لا تعديل بيانات قديمة أو كسر قفل متبقٍ تلقائيًا. حماية البصمة فحص تلف وليست توقيعًا أو تشفيرًا أو تفويضًا متعدد العملاء.

اختبارات الوحدة تعمل من جذر المشروع:

```bash
node node_modules/jest/bin/jest.js --config jest.config.js --runInBand sheikha-vscode-extension/tests
```

فحص المتصفح المحلي يستخدم Playwright موجودًا مسبقًا وChrome، دون تنزيل أي حزمة:

```bash
SHEIKHA_PLAYWRIGHT_MODULE=/path/to/installed/playwright node sheikha-vscode-extension/scripts/verify-chat-workbench.js
```

محاكي VS Code في اختبار المتصفح لا يثبت تحميل الإضافة داخل نافذة المستخدم الحية. بعد تثبيت الحزمة المحلية، يلزم إعادة تحميل نافذة VS Code لالتقاط الإصدار الجديد؛ لا يتم ذلك قسرًا أثناء العمل.
